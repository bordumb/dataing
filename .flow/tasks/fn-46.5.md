# fn-46.5 Add workspace-scoped query filtering throughout system

## Description

This is the most critical and highest-risk task in the multi-workspace epic. Every repository
method that reads or writes resource data must be updated to filter by `workspace_id`. Missing this
on ANY query is a cross-workspace data leak. The approach is to create a workspace context that
propagates through the request lifecycle, and audit every repository method to ensure filtering.

Depends on: fn-46.3 (workspace CRUD routes for context) and fn-46.4 (workspace_id columns exist).

### Implementation

1. Create a workspace context module
   `python-packages/dataing-ee/src/dataing_ee/core/workspace/context.py`:
   ```python
   """Workspace context for request-scoped workspace filtering."""
   from contextvars import ContextVar
   from uuid import UUID

   _current_workspace_id: ContextVar[UUID | None] = ContextVar(
       "current_workspace_id", default=None
   )

   def get_current_workspace_id() -> UUID | None:
       """Get the current workspace ID from context."""
       return _current_workspace_id.get()

   def set_current_workspace_id(workspace_id: UUID | None) -> None:
       """Set the current workspace ID in context."""
       _current_workspace_id.set(workspace_id)
   ```

2. Create workspace middleware in
   `python-packages/dataing-ee/src/dataing_ee/entrypoints/api/middleware/workspace.py`:
   ```python
   class WorkspaceMiddleware:
       """Extract workspace_id from request and set in context.

       Workspace is determined by:
       1. X-Workspace-ID header (explicit)
       2. workspace_id query parameter
       3. JWT claim (if workspace is encoded in token)
       4. Default workspace for the tenant (fallback)
       """
   ```

3. Update repository methods to filter by workspace_id. This is an exhaustive audit of every
   repository. Key repositories to update:

   **CE repositories** (`python-packages/dataing/src/dataing/adapters/`):
   - `datasource/` - All datasource queries add `AND workspace_id = $N` or
     `AND (workspace_id = $N OR workspace_id IS NULL)` during transition.
   - `investigation/` - Investigation queries filter by workspace.
   - `db/` - Any direct SQL queries on resource tables.

   **EE repositories** (`python-packages/dataing-ee/src/dataing_ee/adapters/`):
   - All EE adapters that query resource tables.

   Pattern for each repository method:
   ```python
   # Before:
   async def list_datasources(self, tenant_id: UUID) -> list[...]:
       rows = await self._conn.fetch(
           "SELECT * FROM data_sources WHERE tenant_id = $1", tenant_id
       )

   # After:
   async def list_datasources(
       self, tenant_id: UUID, workspace_id: UUID | None = None
   ) -> list[...]:
       if workspace_id:
           rows = await self._conn.fetch(
               "SELECT * FROM data_sources WHERE tenant_id = $1 AND workspace_id = $2",
               tenant_id, workspace_id,
           )
       else:
           rows = await self._conn.fetch(
               "SELECT * FROM data_sources WHERE tenant_id = $1", tenant_id
           )
   ```

4. Update API route handlers to pass workspace context to repository methods:
   ```python
   @router.get("/datasources")
   async def list_datasources(
       workspace_id: UUID | None = Header(None, alias="X-Workspace-ID"),
       ...
   ):
       return await repo.list_datasources(tenant_id, workspace_id=workspace_id)
   ```

5. Create an audit script `scripts/audit_workspace_filtering.py` that greps all repository
   methods for queries on workspace-scoped tables and flags any that do not include
   `workspace_id` in the WHERE clause.

6. Write/update queries add workspace_id on INSERT:
   ```python
   # Before:
   await self._conn.execute(
       "INSERT INTO data_sources (tenant_id, name, ...) VALUES ($1, $2, ...)",
       tenant_id, name, ...
   )
   # After:
   await self._conn.execute(
       "INSERT INTO data_sources (tenant_id, workspace_id, name, ...) VALUES ($1, $2, $3, ...)",
       tenant_id, workspace_id, name, ...
   )
   ```

7. Add comprehensive tests in
   `python-packages/dataing-ee/tests/integration/workspace/test_isolation.py`:
   - Create two workspaces in the same tenant.
   - Create resources in workspace A.
   - Query with workspace B context -> must return empty.
   - Query with workspace A context -> must return the resources.
   - Test for EACH resource type: datasources, investigations, issues, etc.
