# fn-42.3 Add troubleshooting section for common issues

## Description

Add a comprehensive troubleshooting section to the quickstart guide covering the most common issues users will encounter during first-time setup. Based on the architecture (Docker Compose + Temporal + PostgreSQL + LLM API), the likely failure modes are: missing API key, Docker resource limits, Temporal startup timing, port conflicts, and database connectivity.

**Depends on**: fn-42.2 (investigation walkthrough)

### Implementation

1. Add a "Troubleshooting" section at the bottom of `docs/docs/quickstart.md` with the following subsections:

2. **"ANTHROPIC_API_KEY not set"**:
   - Symptom: Investigation created but immediately fails
   - Fix: Set the key in `.env` and restart: `docker compose restart api worker`
   - Link to get a key: https://console.anthropic.com

3. **"Cannot connect to Docker daemon"**:
   - Symptom: `docker compose up` fails immediately
   - Fix: Ensure Docker Desktop is running, or start the daemon (`sudo systemctl start docker` on Linux)

4. **"Port already in use" (8000, 3000, 5432, 7233)**:
   - Symptom: Service fails to start with "address already in use"
   - Fix: Find and stop the conflicting process, or change ports in `.env`:
     ```bash
     # Find what's using port 8000
     lsof -i :8000
     ```

5. **"Temporal server not ready" / worker connection failures**:
   - Symptom: Worker logs show "failed to connect to temporal"
   - Cause: Temporal takes 30-60 seconds to initialize its database schemas on first run
   - Fix: Wait and retry, or check `docker compose logs temporal`

6. **"Out of memory" / Docker crashing**:
   - Symptom: Containers killed, Docker Desktop becomes unresponsive
   - Cause: Temporal + PostgreSQL + all services can exceed default Docker memory (2GB on macOS Docker Desktop)
   - Fix: Increase Docker Desktop memory to at least 6GB: Preferences > Resources > Memory

7. **"Database migration failed"**:
   - Symptom: API fails to start, logs show SQL errors
   - Fix: Check `docker compose logs api`, ensure postgres is healthy, try `docker compose down -v && docker compose up -d` for clean start

8. **"Investigation stuck in 'running' state"**:
   - Symptom: Investigation never completes
   - Fix: Check worker logs `docker compose logs worker`, verify Temporal UI at http://localhost:8233 for workflow status

9. **Platform-specific notes**:
   - macOS: Docker Desktop memory defaults, Rosetta for Intel images on Apple Silicon
   - Linux: Docker Compose v2 required (`docker compose` not `docker-compose`)
   - Windows: WSL2 backend required for Docker Desktop

10. Add a "Getting Help" section:
    - GitHub Issues link
    - Architecture docs link for deeper understanding
