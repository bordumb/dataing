# fn-46.1 Create migration for workspaces and workspace_members tables

## Description

Create the foundational database migration that adds the `workspaces` and `workspace_members`
tables. These tables establish the workspace concept within a tenant: a workspace is a sub-tenant
grouping that owns datasources, investigations, and other resources. Members have per-workspace
roles. This migration does NOT yet add `workspace_id` to existing tables -- that is fn-46.4.

No dependencies -- this is the starting point for the entire multi-workspace epic.

### Implementation

1. Create `python-packages/dataing/migrations/032_workspaces.sql` (or next available number):
   ```sql
   -- Workspaces: sub-tenant grouping for resource isolation
   CREATE TABLE workspaces (
       id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
       tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
       name TEXT NOT NULL,
       slug TEXT NOT NULL,
       description TEXT,
       settings JSONB DEFAULT '{}',
       is_default BOOLEAN NOT NULL DEFAULT false,
       created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
       updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
       UNIQUE (tenant_id, slug)
   );

   -- Index for tenant lookups (most common query pattern)
   CREATE INDEX idx_workspaces_tenant_id ON workspaces(tenant_id);

   -- Workspace members with per-workspace roles
   CREATE TABLE workspace_members (
       workspace_id UUID NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
       user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
       role TEXT NOT NULL DEFAULT 'member' CHECK (role IN ('owner', 'admin', 'member')),
       created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
       updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
       PRIMARY KEY (workspace_id, user_id)
   );

   -- Index for user lookups (which workspaces does this user belong to?)
   CREATE INDEX idx_workspace_members_user_id ON workspace_members(user_id);
   ```

2. Key design decisions:
   - `slug` is unique per tenant (not globally) via the composite unique constraint.
   - `is_default` boolean marks the auto-created "Default" workspace (exactly one per tenant).
   - `role` uses a CHECK constraint with the same role values as `OrgRole` (owner/admin/member).
   - CASCADE on DELETE: deleting a workspace removes memberships; deleting a tenant removes
     workspaces.
   - `settings` JSONB for workspace-level configuration (notification preferences, etc.).

3. Verify the migration file number does not conflict. Check the latest migration in
   `python-packages/dataing/migrations/` and use the next sequential number.

4. Test the migration runs cleanly:
   ```bash
   # Against a fresh database
   just dev-backend  # starts DB + applies migrations
   ```
