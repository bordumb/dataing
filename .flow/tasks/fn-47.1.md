# fn-47.1 Create migration for scheduled_investigations table

## Description

Create the SQL migration that defines the `scheduled_investigations` table. This table stores cron-based investigation schedules so users can configure recurring health checks on critical tables. It is the foundation for all downstream schedule features (model, API, workflow).

### Implementation

1. Create migration file `python-packages/dataing/migrations/032_scheduled_investigations.sql`.
2. Define the table using the schema from the epic spec:

```sql
-- Scheduled Investigation Jobs
-- Epic fn-47: Scheduled Investigation Jobs

CREATE TABLE scheduled_investigations (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    workspace_id UUID,
    asset_id UUID NOT NULL,
    goal TEXT NOT NULL,
    cron_expression TEXT NOT NULL,
    timezone TEXT NOT NULL DEFAULT 'UTC',
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    notify_always BOOLEAN NOT NULL DEFAULT FALSE,
    notification_channels JSONB DEFAULT '[]',
    max_concurrent INT NOT NULL DEFAULT 1,
    last_run_at TIMESTAMPTZ,
    next_run_at TIMESTAMPTZ,
    last_run_status TEXT,
    created_by UUID REFERENCES users(id) ON DELETE SET NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_si_tenant ON scheduled_investigations(tenant_id);
CREATE INDEX idx_si_tenant_active ON scheduled_investigations(tenant_id, is_active);
CREATE INDEX idx_si_next_run ON scheduled_investigations(next_run_at)
    WHERE is_active = TRUE;
CREATE INDEX idx_si_asset ON scheduled_investigations(tenant_id, asset_id);
```

3. Validate the SQL locally against a running Postgres instance with the demo stack.
