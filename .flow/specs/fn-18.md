# fn-18: Golden Path Demo

## Goal
Create a polished 2-minute notebook demo that showcases the full investigation loop using SDK magics, making the value proposition immediately obvious to CTOs.

## The Canonical Story
**Scenario**: Null spike in `customer_id` over 7 days

**Root cause** (deterministic, pre-seeded in fixtures):
1. Schema change: `customer_id` column type changed from NOT NULL to nullable
2. Pipeline task failure: ETL job failed validation but partial data loaded
3. Partial backfill: Recovery job ran but only backfilled 60% of affected rows

**Why this story works**:
- It's realistic (happens in production systems)
- It has clear evidence trail (schema snapshot → failed task → partial counts)
- The report tells a story a VP can understand without the notebook

## Problem
The current demo (`demo/demo_notebook.ipynb`) uses raw `requests` calls instead of the SDK magics. This misses the UX that makes Dataing feel like "an investigation operating system."

## Solution
Build a notebook demo that flows:
1. `%dataing connect` - Connect to the API
2. `%dataing attach orders.customer_id` - Bind context to asset (resolves datasource)
3. `%dataing lineage` - Show data lineage for bound asset
4. `%dataing ask "Why are nulls spiking in customer_id?"` - Start investigation
5. Timeline streams events + evidence in real-time
6. One-click export: markdown "Incident Report" artifact

**Note on `attach`**: This binds context to an asset, not "choosing a database." The datasource is resolved from the asset. This reinforces that IDs are internal implementation details.

## Success Criteria

### Implementation Outputs
- [ ] Demo runs end-to-end in under 2 minutes
- [ ] Uses SDK magics exclusively (no raw requests)
- [ ] Evidence timeline renders inline in notebook
- [ ] Export produces clean markdown report
- [ ] Works with `just demo` out of the box

### User Outcome Metrics (VP-level)
- [ ] A new user can understand what happened + what to do next by reading the exported report **without the notebook**
- [ ] The report includes: datasource name, time window, linked assets, top 3 evidence items with verdicts
- [ ] The loop works for the canonical "null spike" scenario with deterministic, reproducible results
- [ ] The exported report answers: "What broke? Why? What should I do?"
