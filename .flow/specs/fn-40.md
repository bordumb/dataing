## Gap Analysis Risks

- **Package naming conflicts**: Verify `dataing-cli`, `dataing-sdk`, `dataing-notebook` are available on PyPI before committing to these names.
- **Monorepo versioning**: 5 separate pyproject.toml files with independent version numbers. Cross-package version compatibility must be ensured. Consider whether semantic-release should bump all packages together.
- **Build system mismatch**: Packages use hatch for building but `uv` for development. Clarify: does hatch replace `uv`'s build backend, or is hatch only for publishing? Note: `uv publish` now supports PyPI natively.
- **Backend package not published**: Only client packages (CLI, SDK, notebook) go to PyPI. The backend is self-hosted via Docker. Workers get backend code through Docker image builds from source, not PyPI install.
- **PyPI security**: Use OIDC-based trusted publishing (no long-lived API tokens). Enforce 2FA on PyPI account. Consider SBOM generation.
- **Minimum dependency conflicts**: CLI (Rich, Typer), SDK (httpx), notebook (ipywidgets, ipycytoscape) have potentially overlapping transitive dependencies. Test in clean virtualenvs.
