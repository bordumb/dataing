# Epic fn-13: Helm Charts for Self-Hosted Deployment

## Overview

Create production-ready Helm charts for self-hosted Kubernetes deployments of Dataing CE. Enable companies to deploy the full stack (API, Worker, observability) with a single `helm install`.

## Goals

1. **Single-command deployment**: `helm install dataing ./charts/dataing`
2. **Production-ready defaults**: Sensible resource limits, health checks, security contexts
3. **Configurable observability**: Optional OTEL Collector + Jaeger/Grafana
4. **Documentation**: Clear self-hosting guide

## Non-Goals

- EE-specific charts (SSO, SCIM) - separate epic
- Managed cloud offerings
- Terraform/Pulumi alternatives

## Architecture

```
charts/
├── dataing/                    # Main umbrella chart
│   ├── Chart.yaml
│   ├── values.yaml
│   ├── templates/
│   │   ├── _helpers.tpl
│   │   ├── api-deployment.yaml
│   │   ├── api-service.yaml
│   │   ├── worker-deployment.yaml
│   │   ├── configmap.yaml
│   │   ├── secret.yaml
│   │   └── ingress.yaml
│   └── charts/                 # Subcharts (dependencies)
│       ├── postgresql/
│       ├── redis/
│       └── observability/      # Optional OTEL + Jaeger
└── dataing-ee/                 # EE extension chart (future)
```

## Values Schema (key options)

```yaml
# values.yaml
global:
  imageTag: "latest"

api:
  replicas: 2
  resources:
    requests: { cpu: 100m, memory: 256Mi }
    limits: { cpu: 500m, memory: 512Mi }

worker:
  replicas: 2
  resources:
    requests: { cpu: 200m, memory: 512Mi }
    limits: { cpu: 1000m, memory: 1Gi }

postgresql:
  enabled: true  # Set false to use external DB
  auth:
    database: dataing

redis:
  enabled: true  # Set false to use external Redis

observability:
  enabled: false  # Optional OTEL + Jaeger
  jaeger:
    enabled: true
  otelCollector:
    enabled: true

ingress:
  enabled: false
  className: nginx
  hosts:
    - host: dataing.example.com
```

## Tasks

### fn-13.1: Chart Scaffolding
- Create chart directory structure
- Define Chart.yaml with dependencies
- Create base values.yaml schema
- Add _helpers.tpl with common labels/selectors

### fn-13.2: Core Deployments
- API deployment with health checks, probes
- Worker deployment with resource limits
- ConfigMap for shared configuration
- Secret template for sensitive values

### fn-13.3: Database & Redis
- PostgreSQL subchart configuration
- Redis subchart configuration
- External database connection options
- Migration job for schema setup

### fn-13.4: Observability Subchart
- OTEL Collector deployment
- Jaeger deployment (optional)
- ServiceMonitor for Prometheus (optional)
- Grafana dashboards (optional)

### fn-13.5: Networking & Ingress
- Service definitions (ClusterIP/LoadBalancer)
- Ingress template with TLS support
- NetworkPolicy templates
- PodDisruptionBudget

### fn-13.6: Documentation & Testing
- Self-hosting guide in docs/
- Example values for common scenarios
- Helm test templates
- CI pipeline for chart linting

## Success Criteria

- [ ] `helm install dataing ./charts/dataing` deploys working stack
- [ ] Health checks pass within 2 minutes
- [ ] Traces visible in Jaeger when observability enabled
- [ ] Documentation covers common deployment scenarios
- [ ] Chart passes `helm lint` and `helm test`

## Dependencies

- fn-12 (Observability) - completed

## Risks

- Chart complexity vs. user experience trade-off
- Version compatibility across Kubernetes versions
- Secret management patterns vary by organization
