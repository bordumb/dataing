# fn-48.6 Add hysteresis: sustained breach requirement before trigger

## Description

Implement configurable hysteresis so that a threshold must be breached for a sustained number of consecutive evaluations before triggering an investigation. This prevents spurious triggers from transient metric fluctuations (e.g., a single null_rate spike that resolves on the next evaluation cycle). The `hysteresis_count` field on the threshold configures how many consecutive breaches are required.

Depends on: fn-48.4 (evaluation engine must exist with state machine).

### Implementation

1. Enhance `ThresholdEvaluationEngine.evaluate()` in `python-packages/dataing/src/dataing/core/threshold/engine.py` to incorporate hysteresis:

```python
def evaluate(self, threshold: Threshold, measured_value: Decimal) -> EvaluationResult:
    """Evaluate threshold with hysteresis support."""
    op_fn = OPERATORS[threshold.operator]
    is_breach = op_fn(measured_value, threshold.value)
    prev_state = ThresholdState(threshold.state)

    if is_breach:
        new_consecutive = threshold.consecutive_breaches + 1
        new_state = ThresholdState.BREACHED
    else:
        if prev_state == ThresholdState.BREACHED:
            new_state = ThresholdState.RECOVERING
            new_consecutive = threshold.consecutive_breaches  # preserve count during recovery
        elif prev_state == ThresholdState.RECOVERING:
            new_state = ThresholdState.NORMAL
            new_consecutive = 0  # reset on full recovery
        else:
            new_state = ThresholdState.NORMAL
            new_consecutive = 0

    # Only trigger if sustained breach meets hysteresis threshold
    should_trigger = (
        is_breach
        and new_consecutive >= threshold.hysteresis_count
        and new_consecutive == threshold.hysteresis_count  # trigger exactly once
        and self._cooldown_elapsed(threshold)
    )

    return EvaluationResult(
        threshold_id=str(threshold.id),
        measured_value=measured_value,
        is_breach=is_breach,
        previous_state=prev_state,
        new_state=new_state,
        should_trigger=should_trigger,
        consecutive_breaches=new_consecutive,
    )
```

2. Key hysteresis behaviors:
   - `hysteresis_count=1` (default): trigger on first breach (backward compatible)
   - `hysteresis_count=3`: require 3 consecutive breaches before triggering
   - Consecutive count resets to 0 only when state returns to `normal` (after passing through `recovering`)
   - During `recovering` state, the count is preserved so a re-breach immediately continues the count
   - Trigger fires exactly once when `consecutive_breaches` reaches `hysteresis_count` (not repeatedly on every subsequent breach)

3. Add `GET /thresholds/{id}/evaluations` enhancement to show hysteresis context:
   - Include `consecutive_breaches` at time of evaluation
   - Include whether the evaluation triggered an investigation

4. Update the `ThresholdResponse` API model to include `hysteresis_count` and `consecutive_breaches` so the UI can display breach progression.
