# fn-42.5 Test quickstart flow end-to-end on clean environment

## Description

Validate the entire quickstart guide end-to-end by following the documented steps on a clean environment (no pre-existing Dataing installation, no cached Docker images). This ensures a first-time user can go from zero to first investigation in under 5 minutes. Test both the Docker Compose path and the pip install path.

**Depends on**: fn-42.3 (troubleshooting section), fn-42.4 (demo fixtures package)

### Implementation

1. **Test Docker Compose path on a clean machine** (or Docker-cleaned environment):
   - Remove all Dataing Docker images and volumes: `docker system prune -af`
   - Follow the quickstart guide step-by-step as written (copy-paste commands only)
   - Time each step:
     - Clone + setup: expected < 30s
     - `docker compose up -d`: expected < 120s (cold pull)
     - Wait for healthy: expected < 60s after containers start
     - Trigger investigation: expected < 5s
     - Investigation completes: expected < 120s (depends on LLM latency)
   - Total time should be under 5 minutes (excluding image pull time)
   - Verify every `curl` command in the docs produces the documented output structure
   - Verify the frontend loads at http://localhost:3000 and shows the investigation

2. **Test pip install path**:
   - Create a fresh Python 3.11 virtual environment
   - Follow the pip install steps exactly as documented
   - Download and extract demo fixtures tarball
   - Load fixtures into DuckDB
   - Verify the demo datasource connects
   - (Note: full investigation requires running infrastructure; document this limitation)

3. **Test on multiple platforms**:
   - macOS (Apple Silicon preferred, as it is most common developer machine)
   - Linux (Ubuntu 22.04 or equivalent)
   - Windows (WSL2) if possible

4. **Validate documentation accuracy**:
   - Every command in the quickstart must work as written
   - Every expected output must match actual output (structure, not exact values)
   - No broken links in MkDocs output
   - Code blocks render correctly with syntax highlighting
   - Tabs switch correctly between Docker and pip paths

5. **Create a CI validation script** `docs/test-quickstart.sh`:
   ```bash
   #!/bin/bash
   set -e
   echo "=== Quickstart E2E Test ==="

   # Start the stack
   cp .env.example .env
   echo "ANTHROPIC_API_KEY=${ANTHROPIC_API_KEY}" >> .env
   docker compose up -d

   # Wait for health
   echo "Waiting for API..."
   timeout 120 bash -c 'until curl -sf http://localhost:8000/health; do sleep 5; done'

   # Trigger investigation
   RESPONSE=$(curl -s -X POST http://localhost:8000/api/v1/investigations \
     -H "Content-Type: application/json" \
     -H "X-API-Key: dd_demo_12345" \
     -d '{"alert":{"table":"orders","column":"user_id","metric":"null_rate","anomaly_type":"spike","description":"NULL rate spike"}}')

   INV_ID=$(echo "$RESPONSE" | python3 -c "import sys,json; print(json.load(sys.stdin)['investigation_id'])")
   echo "Investigation: $INV_ID"

   # Poll for completion
   for i in $(seq 1 30); do
     STATUS=$(curl -s "http://localhost:8000/api/v1/investigations/$INV_ID" \
       -H "X-API-Key: dd_demo_12345" | python3 -c "import sys,json; print(json.load(sys.stdin).get('status','unknown'))")
     echo "Status: $STATUS ($i/30)"
     [ "$STATUS" = "completed" ] && break
     sleep 10
   done

   [ "$STATUS" = "completed" ] && echo "PASS" || echo "FAIL: Investigation did not complete"

   # Cleanup
   docker compose down -v
   ```
