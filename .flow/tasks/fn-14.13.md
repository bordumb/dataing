## Done summary
- `spawn_investigation` (routes/issues.py) now builds a real `AnomalyAlert`: `dataset_ids=[request or issue dataset]`, description-type `metric_spec` (expression = focus prompt, display name = issue title), `anomaly_type="custom"`, 0.0 metric values (no measured metric, as in the CE/EE integration auto-investigations), `anomaly_date` = issue creation date (UTC), severity from the issue or "medium". `issue_id` and `focus_prompt` stay as top-level extra keys next to `datasource_id`.
- `list_investigations` (routes/investigations.py) extracts the primary dataset in SQL: `COALESCE(alert->'dataset_ids'->>0, 'unknown')`, mirroring `AnomalyAlert.dataset_id`; it no longer fetches the whole alert.
- No response shapes changed, so openapi.json and the orval client are untouched.
