# fn-69.14 [M2] Automation credential: API, settings UI and audit

## Description
### Goal
An automation credential for each datasource, set up by an admin, with real audit records (design §5.2).

### Implementation
- **Routes** (admin only, following `routes/credentials.py:31-224`):
  - `PUT /datasources/{id}/automation-credentials`
  - `GET` (returns a masked value)
  - `DELETE`
  - `POST …/test`

  Payloads use fn-69.31's schema for each adapter. Encrypt with fn-69.2's helper.
- **Real CE audit.**
  - `adapters/audit/__init__.py` is a no-op stub today.
  - Implement a CE `AuditRepository.record` that writes to `audit_logs` (`migrations/010_audit_logs.sql`), and use it for set, test (including failed tests) and delete.
  - Never record secret material. EE may extend this.
- **CE hook:** `on_automation_credential_changed(tenant_id, datasource_id)`, through `ChecksHooks` (fn-69.21).
- **UI:** Settings → Datasource → Automation, with a form for each schema and a "use a read-only account" warning.
## Acceptance
- [ ] Non-admins get 403, and secrets are never returned.
- [ ] An integration test shows `audit_logs` rows for set, test (success and failure) and delete, with no secret material in them.
- [ ] Changes fire the hook, and `api`-triggered runs get 409 without the credential.
