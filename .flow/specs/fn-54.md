# dataing mock - Local Mock Data Environments

## Overview

Spin up a local data environment that mirrors production schema with realistic sample data for development and testing.

## User Value

Dev/prod parity without copying production data. Engineers can develop locally with confidence.

## Competitor Gap

Existing tools (dbt seed, Datafold) provide static fixtures. We provide production-like data with anomaly patterns included.

## Approach

1. Clone table schemas from production datasource
2. Sample production data with stratified sampling to preserve distributions
3. Inject anomaly patterns from recent incidents
4. Write to local database format (DuckDB, SQLite, Parquet, PostgreSQL)

## Scope

- MockSpec configuration model
- Schema cloner with type mapping between databases
- Stratified sampler preserving column distributions
- Anomaly pattern injection from history
- Output writers for DuckDB, SQLite, Parquet, PostgreSQL
- CLI command with config file support
- dataing-mock.yml configuration format

## Quick Commands

```bash
# Run mock command tests
uv run pytest python-packages/dataing/tests/unit/cli/test_mock.py -v

# Run sampler tests
uv run pytest python-packages/dataing/tests/unit/mock/test_sampler.py -v

# Type check
uv run mypy python-packages/dataing/src/dataing/entrypoints/cli/mock.py
```

## Acceptance

- [ ] `dataing mock <table>` mocks single table with defaults
- [ ] `dataing mock --all` mocks all tables in default datasource
- [ ] `--rows=N` sets default row count
- [ ] `--format=duckdb|sqlite|parquet|postgres` selects output
- [ ] Schema cloned with correct type mapping
- [ ] Stratified sampling preserves distributions
- [ ] Anomaly patterns injected and flagged in metadata
- [ ] `dataing-mock.yml` config file supported
- [ ] `dataing mock init` generates template config
