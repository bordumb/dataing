# fn-15.11 Migrate flow.py consumer to new Engine/Runner API

## Description

Migrate `dataing/src/dataing/core/investigation/flow.py` to use the new Engine/Runner architecture.

**Current code to migrate:**

1. **`run_with_checkpointing()`** (lines 241-343):
   - Currently calls `workflow.tick()` in a loop
   - Has custom checkpoint callbacks
   - Needs to use Runner with event-based checkpointing

2. **`_run_branches_sequentially()`** (lines 346-459):
   - Custom sequential branch execution
   - Can be removed - Runner handles branches

3. **`InvestigationSignalHandler`** (lines 137-162):
   - Extends `BranchingSignalHandler`
   - AWAIT_USER handling moves to Engine/Runner

4. **`InvestigationMergeStrategy`** (lines 95-134):
   - Keep this - it's domain-specific
   - Just needs to match new `MergeStrategy` protocol

**Migration approach:**

```python
async def run_with_checkpointing(
    workflow: Workflow[InvestigationContext],
    context: InvestigationContext,
    checkpoint_callback: Callable[[InvestigationContext], Awaitable[None]] | None = None,
    ...
) -> InvestigationContext:
    # Create engine with investigation-specific merge
    engine = Engine(
        step_order=workflow.step_order,
        merge_strategy=InvestigationMergeStrategy()
    )

    # Create runner
    runner = Runner(engine=engine, steps=workflow.steps)

    # Run and get outcome
    outcome = await runner.run(run_id=..., context=context, start_step=...)

    # Checkpoint after each event if callback provided
    if checkpoint_callback:
        for event in outcome.events:
            # Call checkpoint after significant events
            if isinstance(event, StepCompleted):
                await checkpoint_callback(outcome.context)

    return outcome.context
```
