# fn-49.2 Implement Snapshot Capture in Temporal Workflow

## Description
Modify the investigation Temporal workflow to capture and persist snapshots at key checkpoints.

**Why:** Snapshots must be captured during live investigation while state is hot. Retrospective capture is impossible—the data may have changed.

**Key Design Notes:**
- Use Temporal activity for async upload (retryable)
- Snapshot capture should take <2s for typical investigation
- Consider streaming upload for large snapshots
- Storage abstraction: `SnapshotStore` protocol with S3/GCS/Local implementations

**API Changes:**
- Add `snapshot_config` to investigation request (enable/disable, storage backend)
- Add `GET /api/v1/investigations/{id}/snapshots` to list available snapshots

**Risks:**
- S3 upload latency delays investigation → Fire-and-forget with activity
- Storage costs → Aggressive TTL, compression, tenant quotas

**Location:** `python-packages/dataing/src/dataing/temporal/workflows/investigation.py`
## Acceptance
- [ ] Snapshot captured at: investigation start, after each hypothesis tested, on completion/failure
- [ ] Snapshots stored to configurable backend (local file, S3, GCS)
- [ ] Storage path: `{tenant_id}/snapshots/{investigation_id}/{checkpoint_name}.snapshot`
- [ ] Capture is async and non-blocking (investigation continues if capture fails)
- [ ] Capture failure logged but doesn't fail investigation
- [ ] Snapshot TTL configurable (default: 7 days)
- [ ] Cleanup job removes expired snapshots
- [ ] Unit tests pass
## Done summary
Implemented snapshot capture in Temporal workflow:

1. Created `SnapshotStore` protocol with `LocalSnapshotStore` and `S3SnapshotStore` implementations in `core/snapshot_store.py`
2. Created `capture_snapshot` Temporal activity with `CaptureSnapshotInput` and `CaptureSnapshotResult` dataclasses
3. Integrated snapshot capture into `InvestigationWorkflow` at key checkpoints:
   - START: After context gathered
   - HYPOTHESIS_GENERATED: After hypotheses generated
   - COMPLETE: At investigation completion
4. Added `enable_snapshots` flag to `InvestigationInput` (defaults to True)
5. Added `snapshot_paths` to `InvestigationResult` to track captured snapshots
6. Snapshot capture is fire-and-forget: failures logged but don't block investigation

All 44 tests pass (18 snapshot, 13 snapshot_store, 13 capture_snapshot activity).
