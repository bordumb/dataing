# CLI Streaming Timeline Display

## Overview

Enhance the `dataing run start` command to provide a rich, real-time streaming timeline display of investigation progress. Users will see hypotheses, queries, evidence, and synthesis rendered progressively with timestamps and visual formatting.

**Why**: This is the demo moment. A developer types one command and watches an AI investigate their data issue in real-time. This is the primary differentiation for Dataing.

## Scope

**In scope**:
- Enhance existing `dataing run start <dataset> --goal "<question>"` command
- Progressive SSE event rendering with timestamps and elapsed time
- Rich terminal formatting: hypothesis (blue), query (yellow/syntax-highlighted), evidence (green/red), synthesis (cyan)
- `--json` flag for NDJSON output (one compact JSON object per line)
- `--no-stream` flag to wait and output final result only
- Proper exit codes (0=success, 1=error, 130=interrupt)
- Non-TTY detection for piped output
- Heartbeat indicator for long-running investigations

**Out of scope**:
- New API endpoints (using existing `/api/v1/runs/{id}/events`)
- Auto-reconnection on network failure (defer to future enhancement)
- Sound/bell notifications
- `--timeout` flag (defer)

### Event Type Mapping

| SSE Event | Display Treatment |
|-----------|-------------------|
| `run_started` | Timeline header with goal |
| `hypothesis_testing` | Blue panel with numbered hypothesis |
| `run_progress` | Subtle progress indicator |
| `run_evidence` | Green (supports) or Red (refutes) panel with SQL syntax highlighting |
| `run_completed` | Cyan synthesis panel with root cause, confidence, recommendations |
| `run_failed` | Red error panel |
| `run_heartbeat` | Update elapsed time indicator (no new panel) |

### Design Decisions

1. **Flag naming**: Keep existing `--no-watch` AND add `--no-stream` as alias for consistency with spec
2. **NDJSON format**: Remove `indent=2` from JSON output, use `separators=(',', ':')` for compact output
3. **Non-TTY handling**: Detect `sys.stdout.isatty()`, fall back to plain text output (no Rich Live)
4. **Hypothesis numbering**: Track hypothesis index during stream, display as "Hypothesis #1", "#2", etc.
5. **Elapsed time**: Show `[00:05]` prefix on each event relative to start time

## Risks and Mitigations

| Risk | Mitigation |
|------|------------|
| Long investigations timeout | Show heartbeat indicator with elapsed time |
| Terminal width issues | Use Rich's built-in word wrap, test narrow terminals |
| Non-TTY output corruption | Detect isatty(), disable Rich Live for piped output |
| Event type changes | Document expected event types, add defensive handling |

## Acceptance Criteria

- [ ] `dataing run start <dataset> --goal "<question>"` initiates investigation and streams
- [ ] Events render progressively with `[MM:SS]` elapsed timestamps
- [ ] Hypotheses show as numbered blue panels
- [ ] SQL queries show with syntax highlighting (yellow border)
- [ ] Evidence shows green (supports) or red (refutes) with confidence
- [ ] Final synthesis shows cyan panel with root cause, confidence, recommendations
- [ ] `--json` outputs compact NDJSON (one object per line, no indent)
- [ ] `--no-stream` (and `--no-watch`) waits silently and outputs final result
- [ ] Exit code 0 on success, 1 on error, 130 on Ctrl+C
- [ ] Non-TTY output falls back to plain text (no ANSI escape codes)
- [ ] Heartbeat events update elapsed time without adding new panels
- [ ] All existing CLI tests pass
- [ ] New tests cover streaming, JSON, and no-stream modes
