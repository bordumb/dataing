# fn-16.3 Handle branch failures gracefully with error dict return

## Description

Branch failures should not crash the parent workflow. Failed branches return a structured, namespaced error payload that can be detected by the merge step.

## Implementation

Wrap branch execution in try/except and return structured error:
```python
async def _run_branch(...) -> dict[str, Any]:
    try:
        # ... branch execution ...
        return context_delta
    except Exception as e:
        return {
            "maistro": {
                "branch_error": {
                    "branch_name": branch_name,
                    "step_id": current_step_id,  # or None if failed before first step
                    "reason": "EXCEPTION",
                    "exception_class": type(e).__name__,
                    "message": str(e),
                }
            }
        }
```

**Error reasons** (from main spec):
- `EXCEPTION` - thrown exception during step execution
- `SIGNAL_FAIL` - step returned `Signal.FAIL`
- `AWAIT_USER` - step returned `Signal.AWAIT_USER` (not allowed in branches)
- `NESTED_BRANCH` - step returned `Signal.BRANCH` (not allowed)
- `MAX_ITERATIONS` - branch exceeded iteration limit
- `STEP_NOT_FOUND` - next step not in registry
- `NO_STEPS_REGISTERED` - empty step_order when child_start_step is None

## Acceptance

- [ ] Exceptions during branch execution are caught
- [ ] Failed branches return `{"maistro": {"branch_error": {...}}}` structured payload
- [ ] Error payload includes: branch_name, step_id, reason, exception_class, message
- [ ] Parent workflow continues after branch failure
- [ ] Merge step can detect errors via `"maistro" in payload and "branch_error" in payload["maistro"]`
- [ ] No stack traces leak to user-facing output
