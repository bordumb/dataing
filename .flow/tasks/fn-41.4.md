# fn-41.4 Add health checks and persistent volumes for PostgreSQL and Redis

## Description

Add robust health checks to every service in `docker-compose.yml` and configure named volumes for data persistence. Without health checks, services start before dependencies are ready, causing connection failures. Without persistent volumes, data is lost on every `docker compose down`.

**Depends on**: fn-41.3 (docker-compose.yml)

### Implementation

1. Add health checks to all services in `docker-compose.yml`:
   - **postgres**: `pg_isready -U dataing -d dataing` with interval 5s, timeout 5s, retries 5
   - **temporal**: `tctl --address temporal:7233 cluster health` or `grpc_health_probe` on port 7233, with interval 10s, timeout 5s, retries 10, start_period 30s (Temporal takes time to initialize schemas)
   - **redis**: `redis-cli ping` with interval 5s, timeout 3s, retries 5
   - **api**: `curl -f http://localhost:8000/health` with interval 10s, timeout 5s, retries 5, start_period 15s
   - **worker**: Custom script that checks Temporal connectivity, interval 15s, timeout 10s, retries 5, start_period 30s
   - **frontend**: `curl -f http://localhost:3000/` with interval 10s, timeout 5s, retries 3
   - **temporal-ui**: `curl -f http://localhost:8080/` with interval 10s, timeout 5s, retries 3
2. Add named volumes for data persistence:
   ```yaml
   volumes:
     dataing-pgdata:       # PostgreSQL data
     dataing-redis:        # Redis data (AOF persistence)
     dataing-temporal:     # Temporal internal state (if using file-based config)
   ```
3. Mount volumes in the services:
   - postgres: `dataing-pgdata:/var/lib/postgresql/data`
   - redis: `dataing-redis:/data` (and add `--appendonly yes` to the redis command for AOF persistence)
4. Update `depends_on` across all services to use `condition: service_healthy` for postgres, redis, and temporal.
5. Create `infra/healthcheck-worker.sh` -- a small script that verifies the Temporal worker can connect:
   ```bash
   #!/bin/bash
   python -c "
   import asyncio
   from temporalio.client import Client
   asyncio.run(Client.connect('temporal:7233'))
   " 2>/dev/null && exit 0 || exit 1
   ```

### Key Files
- **MODIFY**: `docker-compose.yml` (add health checks and volumes)
- **CREATE**: `infra/healthcheck-worker.sh`

### Verification
```bash
# Start stack and watch health convergence
docker compose up -d && watch docker compose ps

# Verify all services reach "healthy" status
docker compose ps --format json | python3 -c "
import sys, json
services = json.loads(sys.stdin.read())
for s in services:
    status = s.get('Health', 'N/A')
    print(f\"{s['Service']}: {status}\")
    assert status == 'healthy' or status == 'N/A', f'{s[\"Service\"]} unhealthy'
"

# Verify data persists across restart
docker compose down && docker compose up -d
docker compose exec postgres psql -U dataing -d dataing -c "SELECT 1;"

# Verify clean removal with -v
docker compose down -v
docker volume ls | grep dataing  # Should show nothing
```

## Acceptance
- [ ] Every service in docker-compose.yml has a health check defined
- [ ] All health checks pass within 60 seconds of `docker compose up`
- [ ] Named volumes exist for PostgreSQL and Redis
- [ ] `docker compose down` preserves data (volumes remain)
- [ ] `docker compose down -v` removes all volumes cleanly
- [ ] `depends_on` uses `condition: service_healthy` for postgres, redis, and temporal
- [ ] Redis uses AOF persistence (`--appendonly yes`)
- [ ] Worker health check verifies Temporal connectivity
