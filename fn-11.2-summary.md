# Task fn-11.2: Refactor AppDatabase to use robust serialization

Replaced fragile `json.dumps()` calls with `to_json_string()` from `dataing.core.json_utils` in key persistence and encryption paths.

**Files Refactored:**
- `dataing/src/dataing/adapters/db/app_db.py`: All manual JSON serialization in DB queries.
- `dataing/src/dataing/adapters/db/investigation_repository.py`: Investigation snapshots and alerts.
- `dataing/src/dataing/adapters/investigation_feedback/adapter.py`: Feedback event payloads.
- `dataing/src/dataing/adapters/notifications/webhook.py`: Webhook payloads.
- `dataing/src/dataing/adapters/training/repository.py`: RL training signals.
- `dataing/src/dataing/entrypoints/worker.py`: Worker result payloads and cancellation status.
- `dataing/src/dataing/entrypoints/api/deps.py`: Dependency injection and demo seeding encryption.
- `dataing/src/dataing/entrypoints/api/routes/datasources.py`: Data source configuration encryption.
- `dataing/src/dataing/models/data_source.py`: Encryption helper.

This ensures complex types like `UUID`, `datetime`, and `date` are correctly serialized before being stored in JSONB columns or encrypted strings.
