# fn-15.9 Modify result.py to Add await_token Field

## Description

Modify `maestro/src/maestro/result.py` to add the `await_token` field to `StepResult`.

**Key design decision:** Steps report facts, Engine decides routing.
- `await_token` is the pause point identifier (provided by Step)
- `resume_step` is computed by Engine (NOT provided by Step)

**Changes to `StepResult`:**

```python
@dataclass(frozen=True)
class StepResult(Generic[ContextT, OutputT]):
    context: ContextT
    signal: Signal
    output: OutputT | None = None
    error: str | None = None
    next_step: str | None = None
    branch_request: BranchRequest | None = None
    await_token: str | None = None  # NEW - pause point identifier
    context_update: dict[str, Any] | None = None  # NEW - delta for events

    def __post_init__(self) -> None:
        if self.signal == Signal.BRANCH and self.branch_request is None:
            raise ValueError("BRANCH signal requires branch_request")
        if self.signal == Signal.AWAIT_USER and not self.await_token:
            raise ValueError("AWAIT_USER signal requires await_token")
```

**What NOT to add:**
- `resume_step` - Engine computes this, not Steps
- Steps should report "I need input with this token", not "and then go to step X"

**Usage example:**

```python
# Step returns (correct):
return StepResult(
    context=updated_context,
    signal=Signal.AWAIT_USER,
    await_token="confirm_hypothesis_42",
    context_update={"status": "awaiting_confirmation"}
)

# Engine computes resume_step internally:
resume_step = self._default_next(current_step)
```
