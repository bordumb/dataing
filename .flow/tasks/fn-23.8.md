# fn-23.8 409 Resolver Modal

## Description
## Task: 409 Resolver Modal

Transform 409 ambiguous datasource errors into a guided selection experience.

### Goal
When an operation fails with 409 (ambiguous datasource), show a modal with datasource choices instead of an error.

### Implementation

1. **Detect 409 response**:
   - In widget's API call handlers, catch 409 status
   - Parse response body: `{error, message, available: [{id, name, platform, host}]}`

2. **Show resolver modal**:
   - Use `@jupyterlab/apputils` `showDialog()` with custom body
   - Display datasource options as clickable items with name + platform
   - "Cancel" closes modal without action

3. **On selection**:
   - Retry original operation with explicit `datasource_id`
   - Update attached datasource in state

4. **Location**: `frontend/jupyterlab-dataing/src/resolverModal.ts` (new file)

### Files to Modify
- `frontend/jupyterlab-dataing/src/resolverModal.ts` - New modal component
- `frontend/jupyterlab-dataing/src/widget.ts` - Integrate 409 handling
- `frontend/jupyterlab-dataing/src/index.ts` - Wire up modal

### UX Considerations
- Clear header: "Multiple datasources found"
- Show human-readable names, not just IDs
- Include platform icon/badge for visual distinction
- "Remember this choice" checkbox (optional, stores as default)

### Reuse
- Backend 409 format from `deps.py:574-587`
- `showDialog()` from `@jupyterlab/apputils` - see `statusbar.ts:104` for example
