# fn-23.6 Magic Integration with GUI Config

## Description

Make `%dataing connect` read saved GUI config and add "Copy reproducible snippet" feature.

### Goal
Magics become thin wrappers that use the same configuration as the GUI. Enable collaboration via shareable snippets.

### "Copy Reproducible Snippet" Feature

**High-leverage UX**: Sidebar "Copy snippet" button generates magic commands matching current GUI state.

```
# Copy to clipboard:
%dataing connect --url http://localhost:8000
# API key: using DATAING_API_KEY environment variable
%dataing attach orders --datasource-id ds_prod
```

This enables:
- Sharing notebook setup with colleagues
- Documenting environment for reproducibility
- Power users who prefer magics but want GUI discoverability

### Implementation

1. **Magic reads GUI config**:
   - `%dataing connect` (no args) uses saved URL + credential from server extension
   - `%dataing connect --url X --api-key Y` overrides for this session only
   - `%dataing connect --interactive` opens in-notebook widget (stretch goal)

2. **Print reproducible snippet after connect**:
   ```python
   # Connected to http://localhost:8000
   # Auth: using saved credentials (OS Keychain)
   # Equivalent:
   #   %dataing connect --url http://localhost:8000
   ```
   - Don't print API key, just note credential mode
   - Include comment about how auth is resolved

3. **Sidebar "Copy snippet" endpoint**:
   - `GET /dataing/snippet?kernel_id=X` returns current state as magic commands
   - Response: `{snippet: "...", description: "..."}`

4. **State sync via command endpoints**:
   - Magic uses `/dataing/command/connect` (from fn-23.9)
   - Sidebar reflects magic-initiated connections immediately

### Backward Compatibility
- Existing `%dataing connect --api-key X` syntax continues to work
