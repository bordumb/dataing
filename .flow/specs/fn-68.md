# fn-68 CI hygiene: run integration tests, fix frontend pre-commit hooks, stop uv.lock drift

## Overview

Three CI and tooling gaps let problems through silently:

- `@pytest.mark.integration` tests never ran in Backend CI, because the root pytest addopts deselect them. The older DB tests also turned every exception into `pytest.skip`, so schema drift (e.g. `datasets.fully_qualified_name`) skipped instead of failing.
- The tsc, eslint and prettier pre-commit hooks targeted `frontend/src`, but the app lives in `frontend/app`, so they never ran.
- `uv.lock` drifted from the pyproject versions, so any plain `uv run` (including the mypy hook) rewrote it.

## Scope

- Backend CI `integration` job on pgvector/pgvector:pg16, the `migrated_db` fixture, and the older DB integration tests moved onto it
- Frontend pre-commit hooks pointed at `frontend/app`
- A refreshed uv.lock, plus fixes at the root cause: release re-locks, Dependabot uses the `uv` ecosystem, CI runs `uv sync --locked`, and the hook runs `uv run --frozen`

Out of scope, filed as follow-ups: EE integration tests, and migration 008 re-creating the `teams` table.

## Approach

- `migrated_db` builds a throwaway database from every migration with psql. If psql or the server is missing, it fails instead of skipping, because integration tests only run under `-m integration`.
- Shared `tenant_id` and `dataset_id` fixtures insert rows that match the migrated schema.
- CI enforces a current lock (`--locked`). The lock stays current at the two places pyproject versions change: the release version bump and Dependabot.

## Quick commands

- `DATABASE_URL=postgresql://dataing:dataing@127.0.0.1:55432/dataing_demo uv run pytest python-packages/dataing/tests/integration -m integration --no-cov`, against a throwaway pgvector:pg16 container on port 55432
- `uv lock --check`
- `prek run tsc --files frontend/app/src/App.tsx`
