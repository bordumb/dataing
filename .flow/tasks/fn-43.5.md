# fn-43.5 Configure branch protection, Dependabot, and conventional commits

## Description

Configure repository-level settings for branch protection, automated dependency updates, CODEOWNERS, and conventional commit enforcement. These settings protect `main` from accidental breakage, keep dependencies current, and ensure consistent commit history. This task depends on fn-43.1 through fn-43.4 so that CI checks and templates are in place before protection rules reference them.

**Depends on**: fn-43.1, fn-43.2, fn-43.3, fn-43.4

### Implementation

1. **CODEOWNERS** -- Create `.github/CODEOWNERS` mapping ownership:
   - `*` -- default owner(s) (core maintainers)
   - `python-packages/dataing-ee/` -- EE maintainers
   - `frontend/` -- frontend maintainers
   - `.github/` -- repo admins
   - `docs/` -- docs maintainers

2. **Dependabot** -- Create `.github/dependabot.yml`:
   - Python (pip) ecosystem: weekly schedule, target branch `main`, limit 5 open PRs, labels `dependencies`.
   - JavaScript (npm) ecosystem: weekly schedule, directory `/frontend`, limit 5 open PRs, labels `dependencies`.
   - GitHub Actions ecosystem: weekly schedule, limit 5 open PRs.

3. **Conventional Commits CI** -- Create `.github/workflows/conventional-commits.yml`:
   - Trigger on `pull_request` events (opened, edited, synchronize).
   - Use a conventional commit linter action (e.g. `amannn/action-semantic-pull-request`) to validate the PR title follows conventional commits format.
   - Required status check name: `Conventional Commits`.

4. **DCO Check CI** -- Create `.github/workflows/dco.yml`:
   - Trigger on `pull_request`.
   - Use a DCO check action (e.g. `dcoapp/app` or a GitHub Action equivalent) to verify all commits include `Signed-off-by`.
   - Required status check name: `DCO`.

5. **Branch Protection** -- Document the following settings to be applied via GitHub UI or API (these cannot be committed as files):
   - Protect `main` branch.
   - Require pull request reviews (at least 1 approval).
   - Require status checks to pass: CI tests, lint, typecheck, Conventional Commits, DCO.
   - Require branches to be up to date before merging.
   - Require signed commits (optional but recommended).
   - Do not allow force pushes.
   - Do not allow deletions.
   - Include administrators in restrictions.
   - Document these settings in a `docs/adr/branch-protection.md` or a comment in the PR.
