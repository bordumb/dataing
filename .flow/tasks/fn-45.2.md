# fn-45.2 Implement SAML login redirect (SP-initiated flow)

## Description

Wire the SAML provider into the SSO discovery endpoint so that when a user's email domain maps to a
SAML-configured organization, the `/auth/sso/discover` route returns a SAML AuthnRequest redirect
URL instead of falling back to password auth. This is the SP-initiated flow entry point. Currently
the route explicitly rejects SAML with `"Unsupported"` -- this task replaces that guard.

Depends on: fn-45.1 (SAMLProvider must exist).

### Implementation

1. Update `python-packages/dataing-ee/src/dataing_ee/entrypoints/api/routes/sso.py`:
   - Import `SAMLConfig`, `SAMLProvider` from `dataing_ee.adapters.sso`.
   - In `discover_sso_method`, replace the guard at line ~158 that rejects non-OIDC types.
   - Add a `SSOProviderType.SAML` branch:
     ```python
     elif sso_config.provider_type == SSOProviderType.SAML:
         if not sso_config.saml_idp_entity_id or not sso_config.saml_certificate:
             logger.error(f"Incomplete SAML config for org: {domain_claim.org_id}")
             return SSODiscoverResponse(method="password", ...)

         sso_state = await state_repo.create_state(
             org_id=domain_claim.org_id,
             redirect_uri=_get_redirect_uri(),
         )

         saml_config = SAMLConfig(
             idp_metadata_url=sso_config.saml_idp_metadata_url,
             idp_entity_id=sso_config.saml_idp_entity_id,
             idp_certificate=sso_config.saml_certificate,
             sp_entity_id=_get_sp_entity_id(),
             sp_acs_url=_get_acs_url(),
         )
         provider = SAMLProvider(saml_config)
         saml_request, idp_sso_url = provider.build_authn_request(
             state=sso_state.state_id,
         )
         # Build redirect URL with SAMLRequest + RelayState params
         auth_url = f"{idp_sso_url}?SAMLRequest={saml_request}&RelayState={sso_state.state_id}"

         return SSODiscoverResponse(
             method="saml",
             auth_url=auth_url,
             state=sso_state.state_id,
             display_name=sso_config.display_name,
         )
     ```

2. Add helper functions in the same file:
   - `_get_sp_entity_id() -> str`: reads from `SP_ENTITY_ID` env var or constructs from `BACKEND_URL`.
   - `_get_acs_url() -> str`: reads from `SAML_ACS_URL` env var or defaults to
     `{BACKEND_URL}/api/v1/auth/sso/saml/acs`.

3. Update `SSODiscoverResponse.method` docstring to include `"saml"` as a valid value.

4. Add tests in `python-packages/dataing-ee/tests/unit/routes/test_sso_discover_saml.py`:
   - Mock `SSORepository` to return a SAML config, verify `method="saml"` and `auth_url` contains
     `SAMLRequest` parameter.
   - Verify incomplete SAML config falls back to `method="password"`.
