## Done summary
Brief editor, investigation card and outcome card in the issue thread.

- Investigate… (thread composer and the sidebar Investigations card) calls brief-drafts, waits for the draft on the thread stream and opens the brief editor (`features/issues/brief/`): symptom, findings and exclusions linked to their source messages (expandable quote), leads, scope tables, UTC time window, notes, depth and datasource pickers. Start sends `POST /issues/{id}/investigation-runs` with the brief, profile, datasource, the issue's dataset and `source_thread_id`. A failed draft falls back to a blank brief; "Write it myself" skips waiting. The old Run Investigation dialog and summary card are gone.
- `investigation` messages render as live cards (`thread/InvestigationCard.tsx`): phase, progress and hypotheses from `/investigations/{id}/status`, polled every 3 s while running; finished runs show the outcome's hypotheses.
- Outcome messages (`payload.phase == "outcome"`) render `thread/OutcomeCard.tsx`: root cause, confidence, per-hypothesis end state, evidence, recommendations, the review verdict; Confirm, Reject (reason required), Continue investigating (brief + conclusion as a finding, or as an exclusion when rejected, + empty lead, `parent_run_id`), Add as check (codify dialog).
- Moving to Resolved pre-fills the note with the latest confirmed run's root cause.
- Hand-written API wrappers in `lib/api/investigation-runs.ts`; `IssueHubProvider` shares the issue and the editor across thread and sidebar.
