# fn-69.5 [M1] Read-only validation at execution and the condition evaluator

## Description
### Goal
1. Validate every check query right before it runs.
2. Evaluate conditions and baselines (design §3.5, §16, §17).

### Validation
- **Extend** `safety/validator.py:55` to `validate_query(sql, dialect, *, require_select=True, require_limit=True)`. The SQL-hardening fix in flight changes this function too, so rebase on it.
- **Walk the whole tree against an allowlist.** Reject:
  - `exp.Command`
  - `SELECT … INTO`
  - DML or DDL anywhere, including inside CTEs
  - more than one statement
  - denied functions (`pg_sleep`, `dblink`, …)
- **Dialect:** use the datasource's real dialect.
- **Scalar-aggregate rule** (the only case where the LIMIT requirement is waived):
  1. The **outer SELECT scope must contain at least one non-window aggregate function**. Aggregates inside nested SELECTs don't count, so `SELECT 1 FROM t` is rejected.
  2. Each top-level projection is built only from:
     - aggregates of the outer scope;
     - literals;
     - approved scalar operations: `COALESCE`, `NULLIF`, `CAST`, arithmetic, comparisons and date differences.
  3. No column reference may sit outside an aggregate's scope.
  4. The top level may not have GROUP BY, HAVING, window functions or set-returning functions.
  5. Subqueries in FROM, such as the grouped subquery for duplicate counts, are allowed; their own scopes are still checked for DML.

### Evaluator
`dataing/checks/evaluator.py` provides `evaluate(value, check, history) -> Outcome(pass|warn|fail|error, message, flags)`:
- `change_pct` is signed.
- The baseline uses only `pass` results with the same `compiled_sql_hash`, from runs whose `seq` is lower than the current run's.
- Warm-up needs N eligible results.
- Zero baseline: 0 → 0 is 0%; 0 → n is a pass flagged `baseline_zero`.
- NaN and Inf give `error`.
- `None` gives `warn` flagged `no_rows`, except `freshness_minutes`, which gives `fail`.
## Acceptance
- [ ] Every compiler output (fn-69.4) on every dialect passes the validator without a LIMIT.
- [ ] Rejected:
  - `SELECT 1 FROM t`
  - `SELECT count(*), id FROM t`
  - a top-level GROUP BY
  - an outer query that has an aggregate only in a nested SELECT
  - `WITH d AS (DELETE …) SELECT`
  - `SELECT … INTO`
  - two statements
  - `pg_sleep`
- [ ] Table-driven evaluator tests cover comparisons, ranges, signed change, warm-up, zero and negative baselines, NaN/Inf and empty windows.
- [ ] The baseline ignores fail, warn, error and preview results, and the current and later runs. It resets when the hash changes, but not when only the threshold changes.
