# fn-55.3 Thread tenant_id through Temporal activities

## Description

Add `tenant_id` to Temporal activity inputs so memory operations can be tenant-scoped. Currently `InvestigationInput.tenant_id` exists but doesn't flow to activities.

### Implementation

1. **Activity input dataclasses** - Add `tenant_id: str` to:
   - `GenerateHypothesesInput` (temporal/activities/generate_hypotheses.py)
   - `EvaluateHypothesisInput` (temporal/activities/evaluate_hypothesis.py)
   - `SynthesizeInput` (temporal/activities/synthesize.py)
   - Other activity inputs as needed

2. **Workflow** - Update `InvestigationWorkflow` to pass `self._tenant_id` when constructing activity inputs (investigation.py lines 263+)

3. **TemporalAgentAdapter** - Update methods to accept `tenant_id: str` parameter and convert to `UUID` for memory operations

4. **AgentClient methods** - Add optional `tenant_id: UUID | None` parameter to `generate_hypotheses`, `synthesize_findings`, etc.

### Type Conversion
- Workflow stores `tenant_id: str`
- Memory protocol requires `UUID`
- Convert at activity/adapter boundary: `UUID(tenant_id)`
