# fn-69.27 [M3] PR previews via Check Runs

## Description
### Goal
Validate check files, and run gated dry-runs, on pull requests, without touching production state (design §6.6, §17).

### Implementation
- **Triggers:**
  - `pull_request` opened, synchronize or reopened, when it targets the tracked branch and touches the folder or an imported library.
  - `check_run` or `check_suite` with action `rerequested`.
- **Workflow:** one per PR. It resolves the **current PR head via the API** before running and again before publishing; a stale head's work is discarded.
- **Preview input:**
  - An **immutable `ResolvedSuite` snapshot** of the files at that head SHA, including the SHAs of its imports.
  - It runs through the runner ports (fn-69.8) with preview implementations.
  - Results are stored in **`check_preview_runs` / `check_preview_results`** (source, PR, head SHA, file path; `suite_id` may be null).
  - This supports brand-new suites. Previews **never** touch production versions, baselines, incidents or schedules.
- **Check Run:** "dataing checks" on the head SHA.
  - Annotations use 1-based lines, at most 50 per request (PATCH in batches), with titles of 255 characters or fewer.
- **Dry-run only when all of these hold:**
  - `head.repo` isn't null and `head.repo.id == base.repo.id`;
  - the author has write, maintain or admin permission;
  - the datasource has an automation credential.
- **Output:** never includes metric values or raw error text, only the error class.
- **Conclusions** (checked in order, failure first):
  1. **`failure`:** an invalid spec, or **any permanent execution error**, including unknown or unclassified errors: QuerySyntax, TableNotFound, ColumnNotFound, AccessDenied, InsufficientPermissions, AuthenticationFailed.
  2. **`neutral`:** execution wasn't possible (gated off, no credential, transient errors after retries, limiter unavailable), with the reason stated; or checks that would fail today.
  3. **`success`:** only when every changed check validated **and** executed.
## Acceptance
- [ ] A PR that adds the first suite, and a PR that changes SQL: production versions, baselines, incidents and schedules are unchanged.
- [ ] Every runner error class maps to the specified conclusion, and a test with mixed results confirms failure takes priority over neutral.
- [ ] PRs from forks and from non-writers → `neutral` with "validated only". Out-of-order PR events never publish for an old head.
- [ ] 120 errors are sent in 3 PATCH calls, and the output contains no values or raw messages.
