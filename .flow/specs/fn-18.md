# fn-18: Golden Path Demo

## Goal
Create a polished 2-minute notebook demo that showcases the full investigation loop using SDK magics, making the value proposition immediately obvious to CTOs.

## Problem
The current demo (`demo/demo_notebook.ipynb`) uses raw `requests` calls instead of the SDK magics. This misses the UX that makes Dataing feel like "an investigation operating system."

## Solution
Build a notebook demo that flows:
1. `%dataing connect` - Connect to the API
2. `%dataing attach postgres://...` - Bind to a datasource
3. `%dataing lineage` - Show data lineage
4. `%dataing ask "Why are nulls spiking?"` - Start investigation
5. Timeline streams events + evidence in real-time
6. One-click export: markdown "Incident Report" artifact

## Success Criteria
- [ ] Demo runs end-to-end in under 2 minutes
- [ ] Uses SDK magics exclusively (no raw requests)
- [ ] Evidence timeline renders inline in notebook
- [ ] Export produces clean markdown report
- [ ] Works with `just demo` out of the box

## Dependencies
- fn-17 SDK/Notebook packages installed (DONE)
- Working Temporal workflows for investigation

## Files to Modify
- `demo/demo_notebook.ipynb` - Main demo notebook
- `python-packages/dataing-notebook/src/dataing_notebook/magic.py` - Add missing magics
- `python-packages/dataing-notebook/src/dataing_notebook/renderers.py` - Timeline rendering

## Non-Goals
- Persistence (covered by fn-19)
- Evidence schema normalization (covered by fn-20)
