# fn-69.3 [M1] Checks migration, repositories and removal of test tracking

## Description
### Goal
Add the checks schema (design §4, §17), automation credentials (§5.2), audit changes and datasource keys, plus repositories. Delete the dead Codify test-tracking code.

### Implementation
- **One migration.** Take the next free number, because 035 is claimed elsewhere. Make it idempotent (`IF NOT EXISTS`, guarded `ALTER`s). It contains:
  - **`check_sources`, `check_suites` and `check_suite_versions`.**
    - A partial **unique index on `check_suites(tenant_id, datasource_id, native_path) WHERE is_active`**, which enforces one active suite per dataset across the tenant (§16), in addition to UNIQUE(source_id, file_path).
  - **`check_runs`:**
    - `seq`: bigint, monotonic per suite, assigned at insert. Used for ordering and for baselines.
    - `suite_version_id`, pinned at creation.
    - `as_of` (timestamptz), pinned at creation.
    - `trigger`: schedule, manual, api.
    - `status`: queued, running, completed, failed, cancelled, timed_out, skipped.
    - `temporal_workflow_id`, which is deterministic: `check-run-<id>`.
    - `principal_kind`, `triggered_by`, and the timestamps.
  - **`check_results`:** UNIQUE(run_id, check_key).
    - Values: `outcome`, `metric_value`, `baseline_value`, `change_pct`, and `flags` (JSONB) for warming_up, baseline_zero, no_rows and so on.
    - What ran: `condition` (JSONB), the **`executed_sql` text**, `dialect` and `compiled_sql_hash`.
    - Errors: `error_class` and `error_message`.
    - Also `attempt` and `duration_ms`.
    - INDEX(suite_id, check_key, created_at DESC).
  - **`datasource_automation_credentials`**, mirroring `user_datasource_credentials` (`024_user_credentials.sql`). Its payload follows fn-69.31's schemas.
  - **`query_audit_log` changes:** `user_id` becomes nullable; add `principal_kind` and `actor`; add CHECK (principal_kind <> 'user' OR user_id IS NOT NULL).
  - **`data_sources.key`:** backfilled with distinct keys when names repeat. Add UNIQUE(tenant_id, key) and NOT NULL once backfilled.
  - DROP `generated_tests` and `test_runs`.
- **Datasource keys for new datasources.** Assign a key on create: slugify the name, and add a numeric suffix on collision, retrying on unique violations (`app_db.py:237` insert path).
  - The key never changes when the display name changes.
  - Expose it in the model and API.
  - Add a `PATCH` to edit it, validated as a slug and unique per tenant.
- **Repository:** `adapters/db/checks_repository.py`, following `adapters/db/code_changes.py`.
  - Write JSONB with `core/json_utils.to_json_string` and read it with `json.loads`.
  - Translate unique violations into typed conflicts, which `apply` and sync report as per-file errors.
- **Remove test tracking:**
  - `services/test_tracking.py`
  - the `/tests/*` routes (`routes/investigations.py:772-910`) and their models
  - the tracking call in the codify route (`:733-750`)
  - `tests/unit/services/test_test_tracking.py`
  - unused frontend types in `frontend/app/src/lib/api/investigations.ts`

### Pitfalls
The migration runner is lenient today. Test this file on a fresh database with `ON_ERROR_STOP`.
## Acceptance
- [ ] The migration applies on a fresh database and re-applies without errors.
- [ ] Two datasources named "Warehouse" get distinct keys, both on backfill and when created concurrently afterwards. Renaming a datasource keeps its key, and `PATCH` validates the new key.
- [ ] Two concurrent inserts of an active suite for the same dataset from different sources: one succeeds, and the other gets a typed conflict.
- [ ] The audit CHECK rejects `principal_kind='user'` when `user_id` is NULL.
- [ ] A repository round-trip test shows a historical run (executed SQL, `as_of`, flags, baseline) stays inspectable after a new suite version and catalog changes.
- [ ] No references to `generated_tests`, `test_runs` or `TestTrackingService` remain, and the codify route tests pass.
