## Description
## Bridge Temporal Workflow Evidence to Hash Chain and Add root_hash

### What
Connect the Temporal investigation workflow to the evidence hash chain system. After parallel hypothesis evaluation completes, build the hash chain and persist evidence. Add `root_hash` column to the investigations table.

### Why
The Temporal workflow is the primary production code path, but it currently produces evidence as `dict[str, Any]` with no hash chain awareness. The rich evidence schema (`core/evidence.py`) and the `sdk_evidence` table exist but are disconnected from the Temporal pipeline. Without bridging these, the hash chain only works for SDK runs (a secondary code path).

### Approach

1. **Add DB migration** for `root_hash`:
   - New migration file `031_investigation_root_hash.sql`
   - `ALTER TABLE investigations ADD COLUMN root_hash VARCHAR(64)`
   - Also add to SQLAlchemy model in `models/investigation.py`

2. **Add evidence chain finalization activity**:
   - New Temporal activity `finalize_evidence_chain` in `temporal/activities/`
   - Input: `investigation_id`, `evidence_items: list[dict]`, `hypotheses: list[dict]`
   - Steps:
     a. Normalize all evidence items to JSON-safe dicts (UUIDs to strings, datetimes to ISO 8601 UTC)
     b. Sort deterministically: by `hypothesis_id` (alphabetical), then by evidence type within each hypothesis (query_result before interpretation)
     c. Include hypothesis and synthesis items in the chain
     d. Assign `seq` numbers (1-indexed)
     e. Build hash chain using `create_evidence_chain()` from task fn-33.1
     f. Persist all items via `EvidenceRepository.store_evidence()`
     g. Set `root_hash` on investigation record (content_hash of final item)
   - Output: `root_hash: str`

3. **Integrate into InvestigationWorkflow**:
   - After `_evaluate_hypotheses_parallel()` returns and synthesis is complete (`temporal/workflows/investigation.py:308-318`)
   - Call `finalize_evidence_chain` activity with collected evidence + hypotheses + synthesis
   - Store returned `root_hash` in `InvestigationResult`

4. **Add `root_hash` to InvestigationResult dataclass**:
   - `temporal/workflows/investigation.py:26-65` — add `root_hash: str | None = None`

5. **Update investigation completion**:
   - Store `root_hash` when recording investigation outcome
   - Add to `InvestigationStateResponse` API schema

6. **Handle edge cases**:
   - Cancelled investigation: `root_hash = None` (chain not finalized)
   - Failed child workflows: only chain evidence from successful evaluations (no seq gaps)
   - Empty evidence: `root_hash = None`
   - Hash chain disabled (`EVIDENCE_HASH_CHAIN=false`): skip finalization activity entirely
