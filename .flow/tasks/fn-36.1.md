# fn-36.1 Create migration for git_repositories and code_changes tables

## Description

Create the SQL migration that adds the `git_repositories` and `code_changes` tables to the application database. These tables are the foundation for all git integration features -- `git_repositories` stores connected repos with OAuth credentials and sync state, while `code_changes` stores parsed commit data with affected asset metadata. This follows the same migration pattern established by `030_dataset_repo_mappings.sql`.

### Implementation

1. Create a new migration file `032_git_repositories.sql` in `python-packages/dataing/migrations/`.
2. Define the `git_repositories` table:
   ```sql
   CREATE TABLE git_repositories (
       id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
       tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
       name TEXT NOT NULL,
       url TEXT NOT NULL,
       provider TEXT NOT NULL CHECK (provider IN ('github', 'gitlab', 'bitbucket')),
       access_token_encrypted TEXT,
       tracked_paths TEXT[],
       default_branch TEXT DEFAULT 'main',
       last_sync_at TIMESTAMPTZ,
       sync_status TEXT NOT NULL DEFAULT 'pending'
           CHECK (sync_status IN ('pending', 'syncing', 'synced', 'error')),
       sync_error TEXT,
       created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
       updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
   );
   ```
3. Define the `code_changes` table:
   ```sql
   CREATE TABLE code_changes (
       id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
       repo_id UUID NOT NULL REFERENCES git_repositories(id) ON DELETE CASCADE,
       commit_hash TEXT NOT NULL,
       author_name TEXT,
       author_email TEXT,
       message TEXT,
       committed_at TIMESTAMPTZ,
       affected_assets JSONB DEFAULT '[]',
       raw_diff TEXT,
       files_changed TEXT[],
       created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
   );
   ```
4. Add indexes for common query patterns:
   - `git_repositories(tenant_id)` for tenant-scoped lookups
   - `git_repositories(tenant_id, url)` unique index to prevent duplicate connections
   - `code_changes(repo_id, committed_at DESC)` for time-range queries
   - `code_changes(commit_hash)` unique per repo to prevent duplicate sync
   - GIN index on `code_changes(affected_assets)` for JSONB asset lookups
