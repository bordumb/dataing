# fn-37.2 Add code changes section to hypothesis generation prompt

## Description

Inject recent code changes into the hypothesis generation prompt so the LLM can consider code deploys as potential root causes. This modifies the `build_user()` function in `hypothesis.py` to accept an optional list of `CodeChange` objects and renders them as a "Recent Code Changes" section in the prompt. The activity and adapter layers are updated to pass code changes through from the gather_context step.

### Implementation

1. Update `build_user()` in `python-packages/dataing/src/dataing/agents/prompts/hypothesis.py` to accept an optional `code_changes` parameter:
   ```python
   def build_user(
       alert: AnomalyAlert,
       context: InvestigationContext,
       code_changes: list[CodeChange] | None = None,
   ) -> str:
   ```

2. Add a `_build_code_changes_section()` helper that formats code changes for the prompt:
   ```python
   def _build_code_changes_section(changes: list[CodeChange]) -> str:
       lines = ["## Recent Code Changes (last 14 days)"]
       for c in changes:
           date_str = c.committed_at.strftime("%Y-%m-%d %H:%M") if c.committed_at else "unknown"
           lines.append(f"- [{c.commit_hash[:8]}] {date_str} by {c.author_name}: {c.message}")
           if c.affected_assets:
               lines.append(f"  Affected: {', '.join(c.affected_assets)}")
       return "\n".join(lines)
   ```

3. Insert the code changes section into the user prompt between the schema and lineage sections, only when code_changes is non-empty.

4. Update `GenerateHypothesesInput` in `python-packages/dataing/src/dataing/temporal/activities/generate_hypotheses.py` to include `code_changes: list[dict[str, Any]] | None = None`.

5. Update `TemporalAgentAdapter.generate_hypotheses_for_temporal()` in `python-packages/dataing/src/dataing/temporal/adapters/agent_adapter.py` to accept and forward `code_changes`.

6. Wire the `CodeChangesRepository` call into the workflow between gather_context and generate_hypotheses (in the workflow orchestrator or as part of gather_context activity).

7. Add tests verifying the prompt renders code changes correctly and gracefully handles None/empty lists.
