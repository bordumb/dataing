# fn-69.9 [M1] Checks API: apply, suites, runs and Run now

## Description
### Goal
The CE API (design §5.5–5.6, §17).

### Implementation
- **File:** `entrypoints/api/routes/checks.py`, registered in `routes/__init__.py:53-95`. Ownership dependencies return the same 404 for missing IDs and for another tenant's IDs.
- **`POST /checks/apply`**, body `{source, sha, expected_revision, files: [{path, content}]}`:
  - Compare-and-swap on the source revision: a stale one gets 409.
  - An identical retry is idempotent. The same SHA with different content gets 409.
  - The response includes the new revision.
  - Invalid files keep their last-good version. Only files absent from the upload are deactivated.
  - Unique conflicts become per-file errors.
  - Activation and deactivation call `ChecksHooks` (fn-69.21).
- **`GET /checks/sources/{name}`:** returns the current `revision` and `applied_sha`, which the CLI's ancestry check uses (fn-69.10).
- **Manual run:** `POST /checks/suites/{id}/run`.
  - Requires a user identity.
  - Preflight `has_credentials(UserPrincipal)` returns 403 with `action_url` before any row is created.
  - If a run is already in progress, return it.
- **Automation run:** `POST /checks/suites/{id}/automation-runs`.
  - Requires the explicit `checks:automate` scope; `admin` doesn't imply it (`require_scope` is unchanged).
  - Uses `AutomationPrincipal` with trigger `api`.
  - Preflight returns 409 when there's no automation credential.
- **Issuing automation keys in CE.** Today, API-key creation exists only in EE settings (`dataing_ee/.../routes/settings.py:341`), and JWTs carry only read/write/admin.
  - Add **`POST /checks/automation-keys`** (admin only), which creates a tenant-bound API key with no user and exactly the scope `checks:automate`, shown once.
  - Add `GET` (list, masked) and `DELETE` (revoke).
- **Credentials deleted after enqueueing** show up as a structured error in the run's results.
- **Reads:**
  - `GET /datasets/{id}/checks`, with bounded history: the last 30 results per check, including gaps and hash-change markers.
  - `GET /checks/suites/{id}` and `GET /checks/suites/{id}/runs`, with cursor pagination.
  - `GET /checks/runs/{id}`, with the persisted `executed_sql`, dialect, `as_of` and baseline.
  - `GET /checks/schema`.
- **Client:** regenerate it with `just generate-client`.
## Acceptance
- [ ] A stale `apply` gets 409; an identical retry is idempotent; the same SHA with different content gets 409; of two concurrent applies, one wins.
- [ ] `apply` returns 1-based errors, and bad YAML never causes a 500.
- [ ] A manual run without credentials gets 403 and creates no row. An automation run without a credential gets 409.
- [ ] An admin issues an automation key and it can start automation runs; an ordinary read/write key gets 403; revoking a key stops it working.
- [ ] A double "Run now" returns the same run, and cross-tenant IDs return 404.
