# fn-46.7 Create migration path: existing data to Default workspace

## Description

Create a data migration that provisions a "Default" workspace for every existing tenant and
backfills the `workspace_id` column on all resource tables. After this migration, every resource
row has a non-null `workspace_id`, and every tenant has exactly one default workspace. Existing
users become members of their tenant's default workspace with their current role. Finally, alter
the columns to NOT NULL.

This is the bridge from the old single-tenant model to multi-workspace. It must be safe to run in
production with existing data and must be idempotent.

Depends on: fn-46.4 (workspace_id columns must exist on all tables).

### Implementation

1. Create `python-packages/dataing/migrations/034_backfill_default_workspace.sql`:
   ```sql
   -- Step 1: Create a "Default" workspace for each tenant that does not already have one.
   INSERT INTO workspaces (id, tenant_id, name, slug, is_default, created_at, updated_at)
   SELECT
       gen_random_uuid(),
       t.id,
       'Default',
       'default',
       true,
       NOW(),
       NOW()
   FROM tenants t
   WHERE NOT EXISTS (
       SELECT 1 FROM workspaces w WHERE w.tenant_id = t.id AND w.is_default = true
   );

   -- Step 2: Add all existing users as members of their tenant's default workspace.
   INSERT INTO workspace_members (workspace_id, user_id, role, created_at, updated_at)
   SELECT
       w.id,
       u.id,
       COALESCE(u.role, 'member'),
       NOW(),
       NOW()
   FROM users u
   JOIN workspaces w ON w.tenant_id = u.tenant_id AND w.is_default = true
   WHERE NOT EXISTS (
       SELECT 1 FROM workspace_members wm WHERE wm.workspace_id = w.id AND wm.user_id = u.id
   );

   -- Step 3: Backfill workspace_id on all resource tables.
   -- For each table, set workspace_id = default workspace for the resource's tenant.
   UPDATE data_sources ds
   SET workspace_id = w.id
   FROM workspaces w
   WHERE w.tenant_id = ds.tenant_id AND w.is_default = true AND ds.workspace_id IS NULL;

   UPDATE investigations inv
   SET workspace_id = w.id
   FROM workspaces w
   WHERE w.tenant_id = inv.tenant_id AND w.is_default = true AND inv.workspace_id IS NULL;

   UPDATE issues i
   SET workspace_id = w.id
   FROM workspaces w
   WHERE w.tenant_id = i.tenant_id AND w.is_default = true AND i.workspace_id IS NULL;

   UPDATE notifications n
   SET workspace_id = w.id
   FROM workspaces w
   WHERE w.tenant_id = n.tenant_id AND w.is_default = true AND n.workspace_id IS NULL;

   UPDATE webhooks wh
   SET workspace_id = w.id
   FROM workspaces w
   WHERE w.tenant_id = wh.tenant_id AND w.is_default = true AND wh.workspace_id IS NULL;

   UPDATE api_keys ak
   SET workspace_id = w.id
   FROM workspaces w
   WHERE w.tenant_id = ak.tenant_id AND w.is_default = true AND ak.workspace_id IS NULL;
   ```

   For tables without a direct `tenant_id` column, join through the parent resource to find
   the tenant and then the default workspace.

2. Create a second migration `python-packages/dataing/migrations/035_workspace_id_not_null.sql`
   that makes the columns NOT NULL after backfill:
   ```sql
   -- Only safe to run AFTER 034_backfill_default_workspace.sql
   -- Verify no NULLs remain before altering.

   DO $$
   BEGIN
       -- Verify backfill is complete
       IF EXISTS (SELECT 1 FROM data_sources WHERE workspace_id IS NULL) THEN
           RAISE EXCEPTION 'data_sources still has NULL workspace_id rows';
       END IF;
       IF EXISTS (SELECT 1 FROM investigations WHERE workspace_id IS NULL) THEN
           RAISE EXCEPTION 'investigations still has NULL workspace_id rows';
       END IF;
       -- ... repeat for all tables ...
   END $$;

   ALTER TABLE data_sources ALTER COLUMN workspace_id SET NOT NULL;
   ALTER TABLE investigations ALTER COLUMN workspace_id SET NOT NULL;
   ALTER TABLE issues ALTER COLUMN workspace_id SET NOT NULL;
   ALTER TABLE notifications ALTER COLUMN workspace_id SET NOT NULL;
   ALTER TABLE webhooks ALTER COLUMN workspace_id SET NOT NULL;
   ALTER TABLE api_keys ALTER COLUMN workspace_id SET NOT NULL;
   -- ... repeat for all tables with workspace_id ...
   ```

3. Update SQLAlchemy models to change `nullable=True` to `nullable=False`:
   ```python
   # Before (from fn-46.4):
   workspace_id: Mapped[UUID | None] = mapped_column(ForeignKey("workspaces.id"), nullable=True)
   # After:
   workspace_id: Mapped[UUID] = mapped_column(ForeignKey("workspaces.id"), nullable=False)
   ```

4. Handle edge cases:
   - Tables that reference a parent with `tenant_id` indirectly (e.g., `audit_logs` may have
     `tenant_id`, but `sdk_bundles` may only have `data_source_id` -- join through to find tenant).
   - Tables that may have been dropped (check actual schema before adding UPDATE statements).
   - Idempotent: all statements use `WHERE workspace_id IS NULL` or `WHERE NOT EXISTS`.

5. Add integration test that:
   - Creates a tenant with datasources and investigations (no workspace_id).
   - Runs the backfill migration.
   - Verifies all rows have workspace_id set.
   - Verifies a Default workspace exists for the tenant.
   - Verifies all users are members of the Default workspace.
