# fn-21: Datasource Clarity

## Goal
Establish clear precedence rules for datasource resolution and make the bound datasource visible everywhere.

## Problem
`default_datasource_id` makes UX clean, but ambiguity creeps in with:
- Multi-region deployments
- Clone databases
- dbt models vs physical tables
- Multiple datasources per tenant

The 409 ambiguity response exists but precedence rules aren't documented or consistently applied.

## Solution
1. **Document precedence order** (highest to lowest):
   1. Explicit `datasource_id` in request
   2. Asset-level `datasource_id` (from URN or attachment)
   3. Session/context `default_datasource_id`
   4. Tenant's single datasource (if only one exists)
   5. 409 Conflict if ambiguous

2. **Visible indicators everywhere**:
   - SDK `repr()` shows bound datasource
   - Notebook magics display datasource in output
   - JupyterLab sidebar shows attached datasource
   - All run events include `datasource_id`

3. **Explicit attachment UX**:
   - `%dataing attach postgres://db.schema.table` binds context
   - `client.attach("postgres://...")` in SDK
   - Clear error messages when ambiguous

## Implementation Details

### Precedence in `resolve_datasource_id()`
```python
async def resolve_datasource_id(
    request: Request,
    tenant_id: UUID,
    explicit_id: UUID | None,
    asset_id: UUID | None = None,
    session_default: UUID | None = None,
) -> UUID:
    # 1. Explicit always wins
    if explicit_id:
        return explicit_id

    # 2. Asset-level binding
    if asset_id:
        return asset_id

    # 3. Session default
    if session_default:
        return session_default

    # 4. Single datasource for tenant
    datasources = await get_tenant_datasources(tenant_id)
    if len(datasources) == 1:
        return datasources[0].id

    # 5. Ambiguous - 409
    raise HTTPException(
        status_code=409,
        detail={
            "error": "ambiguous_datasource",
            "available": [str(ds.id) for ds in datasources],
            "hint": "Specify datasource_id or use %dataing attach"
        }
    )
```
