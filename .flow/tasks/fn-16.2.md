# fn-16.2 Implement _run_branch sub-workflow execution

## Description

Replace the stub `_run_branch` with actual sub-workflow execution. The method should run steps starting at `child_start_step` until a termination signal.

## Implementation

In `Runner._run_branch`:
1. Fork context via `copy.deepcopy` (from fn-16.1)
2. Deep copy `branch_spec.data` for `input_data` (first step only)
3. Call `step.execute()` directly (NOT `_execute_step`) for full diagnostic access
4. Run until termination condition
5. Compute and return context delta (for dict) or `{"_full_context": ctx}` (for non-dict)

**Termination conditions** (return structured error from fn-16.3):
- `Signal.COMPLETE` → return context
- `Signal.FAIL` → return structured error (reason="SIGNAL_FAIL")
- `Signal.AWAIT_USER` → return structured error (reason="AWAIT_USER")

- `next_step` not in registry → return structured error (reason="STEP_NOT_FOUND")

## Done summary
Implemented full _run_branch sub-workflow execution:

1. Resolved start step: child_start_step or first step in step_order (with NO_STEPS_REGISTERED guard)
2. Deep copied branch_spec.data for input_data (first step only)
3. Calls step.execute() directly (not _execute_step)
4. Step execution loop with signal handling:
   - COMPLETE: returns context delta
   - FAIL: returns structured error (SIGNAL_FAIL)
   - AWAIT_USER: returns structured error (AWAIT_USER)
   - BRANCH: returns structured error (NESTED_BRANCH)
   - CONTINUE: resolves next_step via result.next_step or _default_next()
5. Returns delta for dict contexts, {"_full_context": ...} for non-dict
6. Max iterations guard (default 100)
7. Added helper methods:
   - _branch_error() for structured error payloads
   - _compute_context_delta() for delta computation
8. Added 10 new tests covering all signal handling and error cases
