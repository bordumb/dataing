# fn-58 Apply each migration exactly once (schema_migrations tracking)

## Overview
Every migration runner re-applied every file on every run and ignored errors.
Re-applying 007 and 013 empties `users` and `investigations` and drops 28 FKs.
Track applied files in `schema_migrations`, apply each pending file strictly and
atomically, and refuse databases migrated before tracking.

**Design (source of truth):** `docs/plans/2026-09-26-migration-tracking-design.md`.
Decision (user, 2026-09-26): refuse pre-tracking databases; `MIGRATIONS_BASELINE`
adopts one explicitly.

## Scope
- `infra/init-app-db.sh` becomes the one tracked, strict runner.
- Callers: compose `db-migrate`, `just demo-infra`, `migrate-prod.sh`, the
  `migrated_dsn` fixture.
- Integration tests for the runner; CLAUDE.md migration rule.

Out of scope: checksums, down migrations, squashing, repairing old databases.
