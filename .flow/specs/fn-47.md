# Scheduled Investigation Jobs

**Plan ref:** Task 2.3.1
**Phase:** 2 (Enterprise)
**Designation:** Enterprise

## Overview

Allow users to schedule investigations to run automatically on a cron schedule for regular health checks on critical tables. Uses Temporal's cron workflow capabilities.

## Scope

- `scheduled_investigations` table with cron expressions
- Temporal cron workflow for scheduled execution
- Schedule CRUD API routes
- Notification on completion (email, Slack, webhook)
- Pause/resume schedules
- CLI commands: `dataing schedule create`, `dataing schedule list`
- Timezone support

## Data Model

```sql
CREATE TABLE scheduled_investigations (
    id UUID PRIMARY KEY,
    tenant_id UUID NOT NULL,
    workspace_id UUID,
    asset_id UUID NOT NULL,
    goal TEXT NOT NULL,
    cron_expression TEXT NOT NULL,
    timezone TEXT DEFAULT 'UTC',
    is_active BOOLEAN DEFAULT TRUE,
    notify_always BOOLEAN DEFAULT FALSE,
    notification_channels JSONB,
    last_run_at TIMESTAMPTZ,
    next_run_at TIMESTAMPTZ,
    created_by UUID,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

## Gap Analysis Risks

- **Temporal cron workflow lifecycle**: Temporal cron workflows create a new workflow execution for each run with a unique ID. Need a correlation mechanism to track these back to the schedule.
- **DST timezone transitions**: A "daily at 2am EST" schedule hits a non-existent time or a duplicate time during DST. Verify Temporal handles this correctly; document behavior.
- **Schedule ownership**: What happens when the creator is deprovisioned (leaves company)? Schedule should transfer to admin, not stop silently.
- **Max concurrent overlap**: If a scheduled investigation takes 30 minutes and the schedule is every 15 minutes, define behavior: queue or skip.
- **LLM cost implications**: Daily schedule on 50 tables = 50 investigations/day = 1500/month. Must implement per-tenant cost limits or usage quotas before this ships.
- **Notification routing**: Current notifications target individual users. Scheduled investigations may need to notify a channel/group, not just the creator.
- **Existing InvestigationWorkflow**: Designed for one-shot execution. Needs a cron wrapper workflow, or the cron functionality needs to be a separate workflow that starts InvestigationWorkflow as a child.
