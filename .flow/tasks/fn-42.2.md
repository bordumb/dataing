# fn-42.2 Write run-first-investigation walkthrough with expected output

## Description

Write the core walkthrough section of the quickstart guide that takes the user from a running stack to their first completed investigation. Include the exact `curl` commands, expected JSON responses at each step, and a brief explanation of what Dataing is doing under the hood. This is the "aha moment" for new users.

**Depends on**: fn-42.1 (install and connect steps)

### Implementation

1. Add "Step 3: Run Your First Investigation" section to `docs/docs/quickstart.md`:
   - Trigger an investigation against the demo `null_spike` scenario:
     ```bash
     curl -X POST http://localhost:8000/api/v1/investigations \
       -H "Content-Type: application/json" \
       -H "X-API-Key: dd_demo_12345" \
       -d '{
         "alert": {
           "table": "orders",
           "column": "user_id",
           "metric": "null_rate",
           "anomaly_type": "spike",
           "detected_at": "2024-01-15T10:00:00Z",
           "description": "NULL rate increased from 1% to 15%"
         }
       }'
     ```
   - Show expected 202 response:
     ```json
     {
       "investigation_id": "inv_...",
       "status": "running"
     }
     ```
2. Add "Step 4: Watch the Investigation" section:
   - Poll the investigation status:
     ```bash
     curl http://localhost:8000/api/v1/investigations/{investigation_id} \
       -H "X-API-Key: dd_demo_12345"
     ```
   - Explain the phases: context gathering, hypothesis generation, parallel hypothesis evaluation, synthesis
   - Show intermediate status response (status: `investigating`)
   - Optionally mention Temporal UI at `http://localhost:8233` for workflow visualization
3. Add "Step 5: View Results" section:
   - Show the completed investigation response with:
     - Root cause analysis (mobile app v2.3.1 bug)
     - Supporting evidence (SQL queries that were run, their results)
     - Recommended actions
     - Confidence score
   - Format the JSON response with syntax highlighting and annotations explaining each field
4. Add a "What just happened?" explainer box (`!!! info`) with a brief diagram:
   - Context gathered from schema + statistics
   - LLM generated 3-5 hypotheses
   - Each hypothesis tested with SQL in parallel
   - Evidence synthesized into root cause
5. Include both `curl` and Python SDK examples using tabbed content.
