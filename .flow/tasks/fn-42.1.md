# fn-42.1 Write install CLI and connect demo datasource steps

## Description

Write the first two sections of the quickstart guide in `docs/docs/quickstart.md`: installing the Dataing CLI/package and connecting the demo datasource with pre-seeded anomalies. The existing quickstart page has outdated content referencing Arq/Redis workers and manual Redis setup. Replace it entirely with a streamlined 5-minute flow that uses Docker Compose (from fn-41) as the primary path and pip install as the secondary path.

### Implementation

1. Replace the content of `docs/docs/quickstart.md` with the new quickstart guide structure:
   - **Hero section**: "Zero to first investigation in 5 minutes" with prerequisites box
   - **Prerequisites**: Docker (with Docker Compose v2), or Python 3.11+ with pip/uv
   - **Path A -- Docker Compose (recommended)**: 3-command flow:
     ```bash
     git clone https://github.com/bordumb/dataing.git && cd dataing
     cp .env.example .env
     # Edit .env to add ANTHROPIC_API_KEY
     docker compose up -d
     ```
   - **Path B -- pip install**: For developers who want to integrate into existing tooling:
     ```bash
     pip install dataing
     ```
2. Write the "Connect Demo Datasource" section:
   - Docker path: demo datasource is automatically configured; API key `dd_demo_12345` is seeded
   - pip path: instructions to download demo fixtures and load via DuckDB:
     ```bash
     # Download demo fixtures
     curl -L https://github.com/bordumb/dataing/releases/latest/download/demo-fixtures.tar.gz | tar xz
     # Load into DuckDB
     duckdb demo.db < demo-fixtures/load_duckdb.sql
     ```
3. Include copy-pasteable `curl` commands to verify the connection:
   ```bash
   # Verify API is running
   curl http://localhost:8000/health
   # Expected: {"status": "healthy"}
   ```
4. Use MkDocs Material tabbed content (`=== "Docker Compose"` / `=== "pip install"`) for dual-path presentation.
5. Use admonitions (`!!! tip`, `!!! warning`) for important callouts.
