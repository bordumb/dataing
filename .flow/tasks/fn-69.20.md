# fn-69.20 [M2] Starter suite: profile, draft, dry-run

## Description
### Goal
"Draft checks" for datasets that don't have a suite yet (design §7.7, §17).

### Implementation
- **`POST /datasets/{id}/checks/draft`** profiles the dataset as the clicking user, under the limiter, and produces a `ProfileResult`:
  - numeric values;
  - **timestamps as epoch seconds**, using explicit conversion in a separate profile-compile path, so normal check validation isn't weakened.
- **Choosing a window:**
  - Pick a timestamp column by type, preferring names like `created_at`, `updated_at` and `event_time`.
  - Ambiguous or missing → profile the whole table behind a row-count guard. Above N rows, skip the expensive metrics, or use TABLESAMPLE where the dialect supports it.
  - `as_of` = now.
- **LLM:** gets the profile numbers and the JSON Schema only. Validate and dry-run the draft, and flag checks that would already fail.
- **UI:** a "Draft checks" button in the Checks tab's empty state shows the YAML, the flags and a copy button. On EE, a pull request comes through fn-69.28.
## Acceptance
- [ ] A test confirms the prompt contains only aggregates.
- [ ] Tests cover timestamp metrics, an empty dataset, a dataset without a time column, and the row-count guard.
- [ ] The draft for the demo `orders` dataset validates and passes on the baseline data. Checks that would fail are flagged, not dropped.
