# fn-33.1 Fix canonical hash computation and add verify_chain()

## Description
## Fix Canonical Hash Computation and Add verify_chain()

### What
Replace the non-deterministic `compute_content_hash()` in `core/evidence.py` with RFC 8785 canonical serialization, include chain metadata in the hash, fix the double-construction bug, and add a `verify_chain()` pure function.

### Why
The current `compute_content_hash()` at `core/evidence.py:71-81` uses `json.dumps(content, sort_keys=True, default=str)` which is non-deterministic across Python versions/platforms. The `default=str` handler produces different output for datetime, float, UUID, and Decimal types. Additionally, the hash only covers `content` — not `prev_hash`, `seq`, or `kind` — meaning evidence items can be reordered without detection. The `create_evidence_chain()` factory has a bug where a throwaway `EvidenceBase` computes the hash with a different timestamp than the final evidence object.

### Approach

1. **Add `rfc8785>=0.1.4` dependency** to `python-packages/dataing/pyproject.toml`

2. **Rewrite `compute_content_hash()`** in `core/evidence.py`:
   - Input: `seq`, `kind`, `prev_hash`, `content` dict (pre-normalized to JSON-safe types)
   - Use `rfc8785.dumps()` for canonical serialization
   - Add domain separation prefix: `b"evidence_v1:" + canonical_bytes`
   - Hash with `hashlib.sha256().hexdigest()`
   - Make it a module-level function (not a method on EvidenceBase) to avoid the double-construction bug

3. **Fix `create_evidence_chain()`**:
   - Compute hash using the new function
   - Construct evidence object only once (no throwaway instance)
   - Pass timestamp explicitly to avoid mismatch

4. **Add `verify_chain()` pure function**:
   - Input: `list[dict]` of evidence items ordered by seq
   - For each item: recompute `content_hash`, verify it matches stored hash
   - For each item after first: verify `prev_hash` matches previous item's `content_hash`
   - For first item: verify `prev_hash is None`
   - Use `hmac.compare_digest()` for hash comparison (timing-safe)
   - Return `(is_valid: bool, first_broken_seq: int | None, error: str | None)`

5. **Make `store_evidence()` INSERT-only**:
   - In `sdk_repository.py:411-417`, remove `ON CONFLICT DO UPDATE`
   - Use plain INSERT; raise on duplicate `(run_id, seq)` to prevent silent overwrites

6. **Unit tests** in `tests/unit/core/test_evidence.py`:
   - Test hash determinism (same input always produces same hash)
   - Test chain verification (valid chain passes)
   - Test broken content_hash detection
   - Test broken prev_hash detection
   - Test genesis block validation (first item must have prev_hash=None)
   - Test reordered items detection
   - Test empty chain verification
