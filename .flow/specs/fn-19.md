# fn-19: Persistence Layer

## Goal
Replace in-memory stores with PostgreSQL so bundles, runs, and events survive restarts and can be retrieved later.

## Problem
Currently `runs.py` uses module-level dicts (`_run_events`, `_run_metadata`) at lines 164-165. This means:
- Runs disappear on server restart
- Events can't be replayed after `REPLAY_WINDOW_SECONDS`
- No way to re-open past investigations

## Solution
Add PostgreSQL tables for persistence:
1. `bundles` table - Store bundle snapshots with hash for deduplication
2. `runs` table - Store run metadata, status, timestamps
3. `run_events` table - Store SSE events with seq ordering

Use existing `app_db` adapter pattern from `dataing/adapters/db/app_db.py`.

## Schema Design
```sql
CREATE TABLE bundles (
    id UUID PRIMARY KEY,
    tenant_id UUID NOT NULL,
    bundle_hash VARCHAR(64) NOT NULL,
    assets JSONB NOT NULL,
    window VARCHAR(50),
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE(tenant_id, bundle_hash)
);

CREATE TABLE runs (
    id UUID PRIMARY KEY,
    tenant_id UUID NOT NULL,
    bundle_id UUID REFERENCES bundles(id),
    goal TEXT NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'running',
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    completed_at TIMESTAMPTZ,
    INDEX idx_runs_tenant_status (tenant_id, status)
);

CREATE TABLE run_events (
    id BIGSERIAL PRIMARY KEY,
    run_id UUID NOT NULL REFERENCES runs(id),
    seq INTEGER NOT NULL,
    event_type VARCHAR(50) NOT NULL,
    data JSONB NOT NULL,
    timestamp TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE(run_id, seq)
);
```

## Success Criteria
- [ ] Bundles persist with content-addressable hash deduplication
- [ ] Runs survive server restart
- [ ] SSE replay works from database
- [ ] GET /bundles/{id} returns persisted bundle
- [ ] GET /runs/{id}/events?seq=N replays from database
