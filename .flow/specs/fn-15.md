# fn-15 Maestro Event-Sourced State Machine with Engine/Runner Split

## Overview

Transform Maestro from an imperative workflow executor into a deterministic event-sourced state machine. This architectural change separates pure state transitions (Engine) from effectful execution (Runner), enabling:

- **Debuggability**: "Why did this run do X?" becomes "read the event log"
- **Determinism**: Reproduce any bug by replaying events - runs are reproducible across machines
- **Rust migration path**: Engine + State + Events can be rewritten in Rust while keeping Python Runner/Steps
- **Testability**: Engine is pure, making unit tests trivial

## Scope

### In Scope
- New files in `maestro/src/maestro/`: `state.py`, `commands.py`, `events.py`, `log.py`, `merge.py`, `engine.py`, `runner.py`, `replay.py`
- Modify `result.py`: Add `await_token` field to `StepResult` (token only; Engine computes routing)
- Modify `workflow.py`: Facade over Engine+Runner with new `run_with_events()` API
- Remove stateful handlers: `BranchingSignalHandler` replaced by pure `merge.py`
- Update `__init__.py` exports
- New tests with invariant checks
- Update consumer in `dataing/src/dataing/core/investigation/flow.py`

### Out of Scope
- Persistent event log (database/file) - use in-memory for now
- Event versioning/migration - defer to future
- **Workflow-as-a-Step** (arbitrary nesting of workflow definitions) - branches are different
- Distributed execution

## Key Design Decisions (Locked Down)

### 1. Deterministic Branch Completion Order

**Decision: Canonicalize branch completion events (Option B)**

Runner buffers branch results and emits `BranchCompleted` events in **stable alphabetical order by branch name**. This ensures:
- Two runs of the same workflow produce identical event sequences
- "Reproduce any bug by rerunning" works across machines
- Replay is fully deterministic, not just "replay the exact log"

```python
# Runner collects results in any order, then emits canonically:
results = await asyncio.gather(*branch_tasks)
for branch_name in sorted(results.keys()):
    emit(BranchCompleted(branch_name=branch_name, ...))
```

### 2. AWAIT_USER: Steps Report Facts, Engine Decides Routing

**Decision: `resume_step` is computed by Engine, not provided by Steps**

Steps should report facts (I need user input), not decide routing (where to go next).

- `StepResult` contains only `await_token: str | None` - the pause point identifier
- `AwaitState` contains `resume_step: str` - computed by Engine using `_default_next(current_step)`
- This keeps Steps decoupled from workflow structure

```python
# Step returns:
StepResult(signal=Signal.AWAIT_USER, await_token="confirm_hypothesis_42")

# Engine computes:
await_state = AwaitState(
    token="confirm_hypothesis_42",
    resume_step=self._default_next(current_step)  # Engine decides
)
```

### 3. Engine.apply() Takes Events Only

**Rule: Engine never sees raw exceptions, Python errors, or StepResults directly**

Runner translates runtime facts into Events. Engine only processes Events.

```python
# Runner catches exception, creates event:
try:
    result = await step.execute(context, input_data)
    event = StepCompleted(step_name=step_name, context_update=result.context_update)
except Exception as e:
    event = StepFailed(step_name=step_name, error=str(e))

# Engine only sees the event:
state, cmd = engine.apply(state, event)
```

### 4. Context Updates in Events (Not Full Contexts)

**Decision: Events store context deltas, not full contexts**

Full contexts in events make logs heavy. Engine state stores full context; events store updates.

```python
@dataclass(frozen=True)
class StepCompleted(Event):
    step_name: str
    context_update: dict[str, Any]  # Delta, not full context

# Engine applies update:
new_context = {**state.context, **event.context_update}
```

### 5. Branches vs Sub-Workflows

**Clarification:**

- **Branches**: Child runs of the *same workflow definition*, executed under the same Runner, returning a context result. Each branch starts at a specified step and runs until completion/failure.
- **Workflow-as-a-Step** (out of scope): Arbitrary nesting where a Step wraps an entire different Workflow definition.

Branches are in scope. Arbitrary nesting is not.

### 6. Merge Step is Continuation Point

**Rule: `merge_step` is the continuation point after all branches complete**

After all branches complete and merge, Engine schedules `merge_step` for execution. This step typically aggregates branch results.

## Complete Event Type Catalog

All events inherit from `Event` base with `seq: int`.

| Event | Fields | Purpose |
|-------|--------|---------|
| `RunStarted` | `run_id`, `start_step` | Workflow execution begins |
| `StepStarted` | `step_name` | Step execution begins (UI, stuck detection) |
| `StepCompleted` | `step_name`, `context_update`, `signal` | Step finished successfully |
| `StepFailed` | `step_name`, `error` | Step raised exception |
| `BranchStarted` | `branch_name`, `start_step` | Branch execution begins |
| `BranchCompleted` | `branch_name`, `context_update` | Branch finished (emitted in canonical order) |
| `InputRequested` | `token` | AWAIT_USER triggered, waiting for input |
| `InputReceived` | `token`, `payload` | External input provided |
| `RunPaused` | `reason` | Run paused (derived from InputRequested) |
| `RunResumed` | `reason` | Run resumed (derived from InputReceived) |
| `RunCompleted` | `final_context` | Workflow finished successfully |
| `RunFailed` | `error` | Workflow finished with failure |

## Workflow.py API Design

Keep backward compatibility while exposing new event-streaming API:

```python
class Workflow(Generic[ContextT]):
    # Existing API (backward compat)
    async def run(self, context: ContextT, start_step: str) -> ContextT:
        """Run workflow, return final context."""
        ...

    # New API: event stream
    async def run_with_events(
        self, context: ContextT, start_step: str
    ) -> tuple[ContextT, list[Event]]:
        """Run workflow, return (final_context, events)."""
        ...

    # New API: async generator for streaming
    async def run_streaming(
        self, context: ContextT, start_step: str
    ) -> AsyncGenerator[Event, None]:
        """Yield events as they occur. Final event is RunCompleted/RunFailed."""
        ...

    # Deprecated
    @deprecated("Use run() or run_with_events() instead")
    async def tick(self, context, step_name, input_data=None):
        ...
```

## Risks and Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| Breaking `flow.py` consumer | High | Keep `tick()` as deprecated wrapper; add `run_with_events()` |
| Test suite rewrite | Medium | Update tests incrementally per task |
| Performance regression | Low | Context deltas keep events small; benchmark if needed |
| Non-deterministic replay | High | Canonical branch ordering; invariant tests |

## Acceptance Criteria

### Functional
- [ ] Engine.apply() is pure: takes Event only, no I/O, no side effects
- [ ] Replay produces identical state from same event sequence
- [ ] Branch completion events emitted in canonical (alphabetical) order
- [ ] AWAIT_USER: Steps provide token only; Engine computes resume_step
- [ ] Events contain context_update deltas, not full contexts

### Tests (with invariants)
- [ ] State machine transition validity (no illegal state transitions)
- [ ] Event sequence monotonicity (seq numbers always increase)
- [ ] Branch completion counts match expected
- [ ] Replay idempotence: `replay(replay(events)) == replay(events)`
- [ ] All existing maestro tests pass (or appropriately migrated)

### Quality
- [ ] `flow.py` consumer works with new architecture
- [ ] Ruff + mypy clean on all new/modified files
- [ ] Docstrings on all public APIs
