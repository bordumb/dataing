# fn-51.3 Implement Test Renderers (GX, dbt, Soda, SQL)

## Description
Render abstract `DataQualityTest` to concrete test code for each supported framework.

**Why:** Users won't change frameworks for us. We must output tests in their existing format.

**Renderer Outputs:**

**GX (Great Expectations):**
```json
{
  "expectation_type": "expect_column_values_to_not_be_null",
  "kwargs": {"column": "customer_id"},
  "meta": {"generated_by": "dataing", "investigation_id": "inv_abc123"}
}
```

**dbt:**
```yaml
models:
  - name: orders
    columns:
      - name: customer_id
        tests:
          - not_null:
              severity: error
```

**Soda:**
```yaml
checks for orders:
  - missing_count(customer_id) = 0:
      name: customer_id not null (from inv_abc123)
```

**SQL:**
```sql
-- Generated by Dataing from investigation inv_abc123
SELECT COUNT(*) as null_count FROM analytics.orders WHERE customer_id IS NULL;
-- EXPECTED: 0
```

**Key Design Notes:**
- Use Jinja2 templates for each renderer
- Include comments with provenance (investigation_id, date, description)
- GX renderer should output both JSON and Python code options

**Location:** `python-packages/dataing/src/dataing/renderers/`
