# Task fn-12.3: Queue Context Propagation

**Epic:** fn-12 Observability & SLOs
**Status:** blocked-by fn-12.2
**Estimate:** Medium

## Objective

Propagate full W3C trace context through Redis queue for proper span linking.

## Critical Fix from Review

The initial plan only passed `trace_id` string. This is **insufficient** for distributed tracing:
- Cannot reconstruct parent span without full context
- API and worker traces will be disconnected
- Need `traceparent` + `tracestate` for proper linking

## Deliverables

1. **Migration**: Add columns to `investigation_jobs` (CONCURRENTLY)
2. **Queue updates**: Full W3C context serialization
3. **Producer span**: Create span at enqueue time

### queue.py updates

```python
from datetime import datetime, timezone
from opentelemetry import trace
from opentelemetry.trace import SpanKind
from dataing.telemetry.config import get_tracer
from dataing.telemetry.context import serialize_trace_context

async def enqueue_investigation(
    redis_url: str,
    investigation_id: UUID,
    tenant_id: UUID,
    datasource_id: UUID | None = None,
    priority: int = 0,
    parent_job_id: UUID | None = None,
    branch_spec: dict[str, Any] | None = None,
    correlation_id: str | None = None,
) -> str:
    """Enqueue investigation with full trace context propagation."""

    tracer = get_tracer("dataing.queue")

    # Create producer span (links API trace to queue)
    with tracer.start_as_current_span(
        "investigation.enqueue",
        kind=SpanKind.PRODUCER,
        attributes={
            "investigation.id": str(investigation_id),
            "tenant.id": str(tenant_id),
            "messaging.system": "redis",
            "messaging.destination": INVESTIGATIONS_QUEUE,
        },
    ):
        # Serialize current trace context (includes traceparent, tracestate)
        trace_context = serialize_trace_context()
        enqueued_at = datetime.now(timezone.utc).isoformat()

        pool = await create_pool(RedisSettings.from_dsn(redis_url))
        try:
            job = await pool.enqueue_job(
                "run_investigation",
                str(investigation_id),
                str(tenant_id),
                str(datasource_id) if datasource_id else None,
                str(parent_job_id) if parent_job_id else None,
                branch_spec,
                # NEW: Full trace context payload
                {
                    "traceparent": trace_context.get("traceparent"),
                    "tracestate": trace_context.get("tracestate"),
                    "correlation_id": correlation_id,
                    "enqueued_at": enqueued_at,
                },
                _queue_name=INVESTIGATIONS_QUEUE,
            )

            logger.info(
                "investigation_enqueued",
                investigation_id=str(investigation_id),
                job_id=job.job_id,
                traceparent=trace_context.get("traceparent"),
                correlation_id=correlation_id,
            )

            return job.job_id
        finally:
            await pool.close()
```

## Key Changes from Initial Design

1. **Full W3C context** - `traceparent` + `tracestate`, not just `trace_id`
2. **Producer span** - Created at enqueue time for proper linking
3. **Simple migration** - Pre-launch, no need for CONCURRENTLY
4. **enqueued_at timestamp** - For accurate SLO measurement
5. **Correlation ID** - Separate from trace context for log correlation
