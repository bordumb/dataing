# fn-41.1 Create multi-stage Dockerfile for backend (API + workers)

## Description

Create a production multi-stage Dockerfile at `infra/Dockerfile.backend` for the backend service. This Dockerfile must produce a lean image capable of running both the FastAPI API server and the Temporal worker, selected via the container command. The release CI workflow already references this path but the file does not exist.

### Implementation

1. Create `infra/Dockerfile.backend` with a multi-stage build:
   - **Stage 1 (`builder`)**: Use `python:3.11-slim` as base, install `uv`, copy `python-packages/dataing/` and its `pyproject.toml`, run `uv pip install` to produce a virtualenv with all dependencies (including `temporalio`, `asyncpg`, `cryptography`, `anthropic`, etc.).
   - **Stage 2 (`runtime`)**: Use `python:3.11-slim`, copy the virtualenv from `builder`, copy source code and migrations, set `PATH` to use the virtualenv, expose port 8000.
2. Include a non-root user (`dataing`) for security.
3. Set appropriate labels (`org.opencontainers.image.*`) for image metadata.
4. Default `CMD` should start the API server (`uvicorn dataing.entrypoints.api.app:app --host 0.0.0.0 --port 8000`), but the worker is invokable via command override (`python -m dataing.entrypoints.temporal_worker`).
5. Add a `HEALTHCHECK` instruction that curls the FastAPI health endpoint.
6. Copy migrations into the image at `/app/migrations/` so the entrypoint or init container can run them.
7. Ensure the image builds for both `linux/amd64` and `linux/arm64` (no architecture-specific dependencies).

### Key Files
- **CREATE**: `infra/Dockerfile.backend`
- **REFERENCE**: `python-packages/dataing/pyproject.toml` (dependencies)
- **REFERENCE**: `python-packages/dataing/src/dataing/entrypoints/api/app.py` (API entrypoint)
- **REFERENCE**: `python-packages/dataing/src/dataing/entrypoints/temporal_worker.py` (worker entrypoint)
- **REFERENCE**: `python-packages/dataing/migrations/` (SQL migration files)

### Verification
```bash
# Build the image
docker build -f infra/Dockerfile.backend -t dataing-backend:dev .

# Verify image size is reasonable (target < 500MB)
docker images dataing-backend:dev --format '{{.Size}}'

# Verify API server starts
docker run --rm -e DATABASE_URL=postgresql://localhost/test \
  dataing-backend:dev uvicorn dataing.entrypoints.api.app:app --host 0.0.0.0 --port 8000 &
sleep 3 && curl -f http://localhost:8000/health && docker stop $(docker ps -q --filter ancestor=dataing-backend:dev)

# Verify worker entrypoint is accessible
docker run --rm dataing-backend:dev python -c "from dataing.entrypoints.temporal_worker import main; print('OK')"

# Verify multi-arch build (requires buildx)
docker buildx build --platform linux/amd64,linux/arm64 -f infra/Dockerfile.backend .
```
