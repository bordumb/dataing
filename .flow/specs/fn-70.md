# fn-70: Issue hub: shared agent chat, handoff and steering

Source spec: `docs/specs/0001_issue_chat.md` (read it first; this epic implements it). Mockup: `0001_issue_chat_mockup.html`.

## Overview
The issue page becomes a hub: one shared thread per issue where people and a read-only agent talk; the agent runs read-only SQL as the asking user; people hand the thread's context to the investigation manager (InvestigationWorkflow) and subagents (EvaluateHypothesisWorkflow) via an editable brief; people steer a running investigation; private scratch chats publish into the shared thread.

## Scope
Milestones M1–M4 from spec §10. CE only.

## Approach and decisions made during planning (deviations from the spec are marked)
- **Agent runtime (deviation from spec §7.6):** bond-agent 0.1.2 has no `model_settings` and replays tool calls after text instead of streaming them. The chat agent uses **pydantic-ai `Agent` directly** (pydantic-ai 1.44 is already a dependency) with `agent.iter()` / `event_stream_handler` for live text and tool events. Model: `AnthropicModel(CHAT_AGENT_MODEL, settings=AnthropicModelSettings(anthropic_cache_instructions=True, anthropic_cache_tool_definitions=True, anthropic_cache_messages=True, extra_body={"output_config": {"effort": CHAT_AGENT_EFFORT}}))`. Defaults `CHAT_AGENT_MODEL=claude-opus-5`, `CHAT_AGENT_EFFORT=low` (brief drafting `medium`). The effort `extra_body` is unverified against the live API: guard it behind config and fall back to no effort key on a 400.
- **Queries as the user:** add `UserPrincipal` (same fields as `QueryPrincipal`) and route agent queries through `QueryGateway` (`adapters/datasource/gateway.py`), which today has no callers and does NOT validate SQL. The agent query service validates with `safety/validator.py` (`validate_query(sql, dialect=adapter dialect)`, `add_limit_if_missing`) before the gateway, mirroring `temporal/activities/execute_query.py:89-125`. `CredentialsNotConfiguredError` → typed `credentials_missing` tool error. `QueryContext(source="agent")` for the audit log. Never fall back to the stored connection.
- **SSE cursor (deviation from spec §7.3):** `(updated_at, id)` loses late-committing rows. Messages get `rev BIGINT` from a global sequence, bumped on every insert and update. The stream polls `rev > cursor` every 250 ms and also re-reads rows touched in the last 5 s (`touched_at >= clock_timestamp() - 5s`), de-duplicating per connection by `(id, rev)`. Don't copy `stream_issue_events`' UUID cursor or its `payload`-reads-as-`{}` bug (no JSONB codec: `json.loads` string payloads; write with `to_json_string`).
- **Migration 037** (renumber at merge if fn-59 took 037/038). Every new table carries `tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE`. User FKs `ON DELETE SET NULL`. Backfill a shared thread per existing issue and copy `issue_comments` into it (`seq` via `ROW_NUMBER()`), then drop `issue_comments`. `issue_investigation_runs.brief` backfilled as `{"version":1,"symptom":<issue title>,"notes":<focus_prompt>}` before `NOT NULL`, then drop `focus_prompt`. No BEGIN/COMMIT.
- **EE caller:** `dataing-ee/.../core/automation/executor.py` inserts into `issue_comments` (already broken: no `author_type` column). Repoint to a shared-thread `system` comment via the new repository.
- **Shared thread creation:** lazily with `INSERT ... ON CONFLICT DO NOTHING` on the partial unique index, plus the migration backfill. Every issue-creation path goes through the same helper.
- **seq locking:** only inserts lock the thread row (`SELECT ... FOR UPDATE` then `MAX(seq)+1`); streaming updates touch only the message row.
- **Authorization:** owner, author, requester and `ask_agent` checks are enforced in handlers (registered `ANY_USER` in `POLICY`, with explicit tests). Scratch threads return 404 to non-owners on every route (messages, stream, publish, cancel, brief-drafts).
- **Temporal testing:** the `InProcessTemporal` fixture can't do signals or `wait_condition`. Add a `WorkflowEnvironment.start_time_skipping()` fixture. Record Replayer histories of the current InvestigationWorkflow **before** changing it (fn-70.12).
- **Outcome write-back:** nothing writes `investigations.outcome` today. `publish_investigation_outcome` writes it (which also stamps `completed_at` via the 036 trigger) plus the `issue_investigation_runs` summary fields, idempotently.
- **Open questions, defaults chosen (flag in the final report):** model `claude-opus-5` low effort; raw tables visible to all issue viewers (D4); PII redaction of tool results before the model ON; people can steer check-started runs; scratch chats owner-only; no Slack mirroring.
- **Edge-case defaults:** editing an answered `asks_agent` comment doesn't re-run the agent; queued turns are cancelled by removing them from the FIFO; a streaming turn is cancelled via heartbeat; a crashed turn's retry reuses its reply message; stale `streaming` rows are marked `error` on worker start; the per-person limit of 3 running turns is checked in the API (429); `rule_out` on a finished hypothesis is rejected; steers are inserted `pending` before signalling and marked `rejected` if the signal fails; late steers during synthesis are batched into one re-synthesis.
