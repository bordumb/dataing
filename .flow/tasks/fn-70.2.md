# fn-70.2 M1: thread repository and thread/message API with SSE

## Description
Spec: `docs/specs/0001_issue_chat.md`. Epic decisions: `.flow/specs/fn-70.md` (read both first).


- New `adapters/db/issue_threads.py` repository: `ensure_shared_thread(tenant_id, issue_id)` (INSERT ON CONFLICT DO NOTHING + select), `create_scratch_thread`, `list_threads(issue_id, user_id)`, `append_message(...)` (locks thread row, MAX(seq)+1), `update_message(...)`, `list_messages(after_seq, limit)`, `messages_since(rev, overlap)`, soft delete, cancel. JSON via `to_json_string` / `json.loads`.
- New routes module `entrypoints/api/routes/issue_threads.py` mounted in `routes/__init__.py`: every route in spec §7.1 for threads and messages except publish and brief-drafts (later tasks). Human comment in shared thread: any authenticated user; `ask_agent=true`: `auth.has_scope("write")` checked in handler (403); scratch threads: owner-only, 404 for others on every route. Posting a comment also records `comment_added` via `_record_issue_event` and bumps `issues.updated_at`.
- Issue events also append a `system`/`event` message to the shared thread (hook into `_record_issue_event`).
- SSE `GET .../threads/{thread_id}/stream?after=<rev>` using sse_starlette `EventSourceResponse` (as stream_issue_events): 250 ms poll, rev cursor + 5 s overlap re-read with per-connection (id, rev) dedupe, 30 s heartbeat, `request.is_disconnected()` checks, event id = rev, honours `Last-Event-ID`.
- Remove `GET/POST /issues/{issue_id}/comments` and their tests; repoint the EE automation executor's `issue_comments` insert to `append_message` as a system comment.
- Update `POLICY` in `tests/unit/entrypoints/api/routes/test_route_authorization.py`.
