# fn-69.21 [M3] EE wiring: EE worker, feature flags, fail-closed entitlements, CE hooks

## Description
### Goal
The foundation for the EE checks features, working in **both** the API and the worker (design §9, §10.5, §17).

### Implementation
- **Feature flags:** `Feature.CHECK_SCHEDULES` and `Feature.GITHUB_APP` on the enterprise plan, plus the frontend's `DEMO_ENTITLEMENTS`.
- **Entitlements:** `require_feature` fails closed when `request` or `auth` is missing (`middleware/entitlements.py:43-45`).
- **Hooks:**
  - A CE `ChecksHooks` protocol covering four events: suite activated, suite deactivated, automation credential changed, and open a pull request.
  - CE implements them as no-ops.
- **Shared dependency construction:**
  - `build_dependencies(edition)` is used by **both** API startup and worker startup.
  - EE injects its implementations in `create_ee_app` *and* in a new EE worker entrypoint, `dataing_ee/entrypoints/temporal_worker.py`, which wraps the CE worker (`temporal_worker.py:256`).
- **Hook call sites:**
  - CE `apply` (fn-69.9)
  - EE sync (fn-69.25)
  - automation credential changes (fn-69.14)
  - the schedule reconciler (fn-69.22)
- **Import boundary:** a test that `python-packages/dataing/src` never imports `dataing_ee`.
## Acceptance
- [ ] Gated routes return 403 `feature_not_available` without the plan, and fail closed when misconfigured.
- [ ] Integration tests show that both an API `apply` and a sync in the worker call the **real EE** schedule implementation, not the CE no-op.
- [ ] The import-boundary test passes.
