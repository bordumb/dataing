# fn-69.28 [M3] Pull requests from dataing: Codify, starter suites, bootstrap

## Description
### Goal
Every change dataing makes arrives as a PR, and retrying never duplicates one (design §6.7, §6.8, D9, §17).

### Implementation
- **`github_pr_operations`**, one row per operation: stable operation ID, source, kind, base SHA, branch, commit SHA, PR number and status.
- **`open_pull_request(operation)`:**
  - Uses the Git Data API (blobs → tree → commit → ref).
  - Branches from the tracked branch's head, onto `dataing/<kind>-<operation_id>`.
  - The commit carries the trailer `Dataing-Operation: <id>`.
  - Never touches the default branch, and never force-pushes.
- **On retry:**
  - Reconcile first: an existing branch and PR are verified through the trailer and then reused.
  - An unrelated branch that collides on the name gets a suffixed branch.
- **YAML edits:** ruamel round-trip with fn-69.1's canonical settings, plus a golden test that load → dump leaves files unchanged.
- **Wired through the fn-69.21 hook:**
  - Codify "Add as check".
  - Starter suites.
  - Bootstrap for a repo that only has a README: the folder layout, a `.vscode/settings.json` `yaml.schemas` mapping, a README and a starter suite.
  - Suites from `api` sources fall back to YAML.
## Acceptance
- [ ] respx tests, against both base URLs, cover response loss after the ref is created and after the PR is created, with no duplicates. A duplicate submission reuses the PR.
- [ ] An unrelated branch colliding on the name leaves that branch untouched.
- [ ] Comments and formatting survive in an edited suite, and the bootstrap PR opens on a README-only repo.
