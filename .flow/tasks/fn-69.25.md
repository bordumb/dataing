# fn-69.25 [M3] GitHub webhooks and push sync

## Description
### Goal
Reliable webhook intake, and sync on merge that stays correct under out-of-order delivery (design §6.4, §6.5, §17).

### Webhook intake
- **Endpoint:** `POST /api/v1/github/webhooks/{app_id}` (EE).
- **Verification:**
  - Compute the HMAC over the raw body; reject the webhook if no secret is configured.
  - Check `X-GitHub-Hook-Installation-Target-ID`.
  - On GHES, compare **`X-GitHub-Enterprise-Host`** (normalized) with the stored host, after the HMAC check.
- **Delivery ledger:** `github_deliveries`, keyed by GUID, with status received / processing / done / failed, attempt count, timestamps and error. Kept for 30 days.
  - A delivery that's already `done` starts nothing.
  - A `failed` delivery is processed again.
  - Workflow ID `gh-delivery-<guid>` with ALLOW_DUPLICATE_FAILED_ONLY. Handlers are idempotent.
- **Response:** 202.

### Sync
- **Events only signal a change.** The per-source sync workflow is serialized and **resolves the branch's current head via the API** each time, ignoring the SHA in the payload.
- **Steps:**
  1. Read the tree, handling `truncated`.
  2. Compute the **complete delta** for the source.
  3. Apply it in **one transaction**, evaluating uniqueness against the final state.
  4. **Renames** (same dataset, new path) keep the `suite_id`, history and open issue, and dataset swaps are handled.
  5. Invalid files keep their last-good version.
  6. Before committing, re-check the head. If it moved, loop.
  7. `last_synced_sha` advances only after a successful commit.
- **Imports:** tags resolve to SHAs, and editing a library re-versions the suites that import it.
- **Installations:** a deleted or suspended installation marks the source as disconnected.
- **Hooks:** called through fn-69.21's shared dependencies.
## Acceptance
- [ ] Recorded payloads: a valid signature gets 202, and a bad or missing secret gets 401. Redelivery while running, after success, after failure, and after Temporal history has expired all behave as the ledger specifies.
- [ ] Reverse delivery order, a stale redelivery, a race between the poll and a webhook, and the head changing mid-sync all end at the true head.
- [ ] Rename `orders.yml` → `orders.yaml` keeps the suite, history and open issue. A dataset swap between two files and a crash-retry lose nothing.
- [ ] Both base URLs are covered.
