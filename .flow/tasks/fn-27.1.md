# fn-27.1 Refactor EE webhook routes to use adapter classes

## Description
Refactor the EE webhook route (`dataing-ee/src/dataing_ee/entrypoints/api/routes/integrations.py`) to properly use the adapter classes.

## Current Problem

The route at line 733-830 has inline parsing logic (`_map_payload_to_issue()`) that duplicates what the adapter classes already do. The adapters (`monte_carlo.py`, `great_expectations.py`) exist but aren't used.

## What to Do

1. Modify `receive_provider_webhook()` to:
   - Get the appropriate adapter based on provider
   - Use `adapter.verify_signature()` instead of inline verification
   - Use `adapter.parse_payload()` to get `IssueData`
   - Use `adapter.get_fingerprint()` for deduplication

2. Keep fallback for providers without adapters (use existing inline logic)
