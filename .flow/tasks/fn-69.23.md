# fn-69.23 [M3] GitHub App: registration, installation claim and API client

## Description
### Goal
Connect github.com and GHES safely (design §6.1–§6.3, §6.10, §17).

### Implementation
- **Migration:** `github_apps`, `github_installations` (UNIQUE(github_app_id, installation_id)) and `github_pending_operations`. Secrets are encrypted with fn-69.2's helper.
- **States:**
  - Registration and installation use **separate** single-use `state` values.
  - Each expires, and is stored server-side, bound to the user's session, the tenant, the app and the host.
  - A callback without a matching pending operation is rejected. This applies to the SaaS app too.
- **Manifest registration** (self-hosted):
  - `request_oauth_on_install: true`.
  - Permissions: write on contents, pull_requests and checks; read on metadata.
  - Events: push, pull_request, installation, installation_repositories, check_run and check_suite.
  - Exchange the code within 1 hour, and refuse a null `webhook_secret`.
- **Claim authority** (§6.2). All three of these must hold:
  1. The installation appears in paginated `GET /user/installations`.
  2. For an **organization** installation, the user has an entry in paginated **`GET /user/memberships/orgs`** — this endpoint needs no extra app permission, unlike `/user/memberships/orgs/{org}`, which needs Members:read. The entry must match the installation account's **org ID**, with **`state: active`** and **`role: admin`**, so pending invitations are rejected. For a **personal** installation, `account.id` must equal the user's ID.
  3. The claim is made from an admin session in dataing.
- **Repository binding:** a repo can become a source only if the installation grants it and the user has admin or maintain permission on it.
- **Configuration modes:**
  - **SaaS:** shared-app environment variables.
  - **Self-hosted:** manifest mode, with no app environment variables, only `DATAING_PUBLIC_URL`.
  - Credentials are validated only for the selected mode.
- **Client (httpx):**
  - JWT signed RS256 (`iat` 60 seconds in the past, `exp` at most 10 minutes out, `iss` = client ID).
  - Installation tokens cached by (installation, repository_ids, permissions) and refreshed from `expires_at`.
  - `X-GitHub-Api-Version: 2022-11-28`, with base URL `api.github.com` or `https://<host>/api/v3`.
  - Missing rate-limit headers are fine.
## Acceptance
- [ ] respx tests run against both base URLs, using **only the permissions the manifest declares**.
- [ ] An org admin can claim; a pending admin invitation, a read-only outside collaborator, someone who isn't an admin, and an unadministered repo are all rejected. Two tenants claiming concurrently: one wins.
- [ ] Callback substitution, replay, an expired state and tenant switching are rejected; the SaaS installation flow works.
- [ ] CE and a fresh self-hosted EE start without shared-app credentials.
