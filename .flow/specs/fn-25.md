# fn-25: Month 2-4: Investigation UX + Feedback Loop

## Goal
Ship a tighter investigation UX with feedback capture, human review routing, issue workspace
surfacing, and a reliable investigation queue so feedback signals are usable for iteration.

## Scope
- Feedback UI wired into investigation detail for synthesis and evidence.
- Policy-triggered context review flow with notification routing.
- Investigation summary promoted on issue workspace.
- Recommendation capture and issue resolution signals for analytics.
- Queue worker retry/idempotency/stability improvements.

## Non-Goals
- SSO/SAML and enterprise readiness items (Month 4-6).
- Runbook generation or automated fixing.
- New integrations.

## Approach
- Use existing investigation detail layout and feedback components; persist via feedback API.
- Extend policy-driven review gating and notifications to route to context review.
- Add summary card/CTA in issue workspace linked to latest investigation.
- Capture recommendation feedback and resolution events with clear API actions.
- Harden queue worker retry/backoff + error handling with better visibility.

## Quick commands
- `just test-frontend`
- `uv run pytest python-packages/dataing/tests/unit/core/test_state.py -v`

## Acceptance
- [ ] Feedback capture works for synthesis and evidence on investigation detail.
- [ ] Context review flow is gated by policy and reachable via notifications.
- [ ] Issue workspace surfaces latest investigation summary and link to detail.
- [ ] Recommendations and issue resolution signals are persisted for analytics.
- [ ] Queue worker handles retries and failures reliably with clearer logging.
