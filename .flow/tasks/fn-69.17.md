# fn-69.17 [M2] Check-triggered investigations run as AutomationPrincipal

## Description
### Goal
Investigations that checks start run only as `AutomationPrincipal`, on every warehouse access path. They get a complete alert, and write an execution receipt before any side effect (design §7.3, §17).

### Dependencies
Rebase on the in-flight fixes that touch `entrypoints/temporal_worker.py`: the tenant-scoped `get_adapter`, and passing query errors through.

### Execution receipt
The investigation workflow's **first activity** writes `investigation_intents.execution_receipt_at` and `workflow_run_id` (fn-69.15), before gathering context or running any query.

### Principal propagation
- **Carry the principal end to end:** the starter → the Temporal client → the parent and child workflows → `gather_context` (`temporal/activities/gather_context.py:93`) → schema lookup (`adapters/context/schema_lookup.py:46`) → the query activities.
- **Schema discovery** goes through a gateway session, and never the legacy adapter cache.
- **Credentials deleted** after intake fail cleanly and move the issue to `review`.

### A complete AnomalyAlert mapping
- **`metric_spec`:** built from the check.
- **Numeric fields:** `expected_value`, `actual_value` and `deviation_pct` become Optional, with a `measurement` status: `available`, `unavailable_empty_window` or `not_numeric`. The prompts and consumers are updated to handle None.
- **Ranges:** `expected_value` is the violated bound, with the full condition in `metadata`.
- **Zero expected value:** `deviation_pct` is None.
- **Empty-window freshness:** `actual_value` is None.
- **Baseline checks:** the baseline value and its N go into `metadata`.
## Acceptance
- [ ] The receipt is written before any gateway call; a test asserts the order.
- [ ] A failing demo check starts an investigation whose schema lookups and queries are all audited as `automation` / `investigation:<id>`. A table visible only to the base account stays invisible.
- [ ] Credentials deleted after intake → the issue moves to review.
- [ ] Mapping tests cover thresholds, ranges, change against a baseline, zero expected values and empty-window freshness.
