# fn-23.2 Server Extension Credential Storage

## Description

Implement credential storage with 3 explicit modes and wizard detection.

### Goal
Allow users to store API keys securely with clear messaging about which mode is active.

### Three Credential Modes

| Mode | How it works | When used | Persistence |
|------|--------------|-----------|-------------|
| **OS Keychain** | `keyring` library | Keyring available + user consents | Permanent |
| **Environment Variable** | `DATAING_API_KEY` | Env var set, OR keyring unavailable + user has env var | Until env changes |
| **Session-Only** | In-memory only | User declines persistence, OR no keyring + no env var | Until JupyterLab restart |

### Mode Detection Logic

```python
def detect_credential_mode() -> tuple[CredentialMode, str]:
    """Detect best available credential mode.

    Returns:
        (mode, explanation_message)
    """
    # Check env var first (always works)
    if os.environ.get("DATAING_API_KEY"):
        return (CredentialMode.ENV_VAR,
                "Using API key from DATAING_API_KEY environment variable")

    # Check keyring availability
    try:
        import keyring
        keyring.get_keyring()  # Raises if no backend
        return (CredentialMode.KEYCHAIN,
                "API key will be stored securely in your OS keychain")
    except Exception:
        pass

    # Fallback to session-only
    return (CredentialMode.SESSION_ONLY,
            "API key will be stored in memory only (not persisted)")
```

### Implementation

1. **New handlers**:
   ```python
   POST /dataing/credentials  # {api_key: "...", persist: bool}
   GET /dataing/credentials   # {mode: "keychain"|"env_var"|"session", stored: bool}
   DELETE /dataing/credentials  # Clear stored credential
   ```

2. **Credential precedence** (highest first):
   - Explicit API key in request header (`X-Dataing-Api-Key`)
   - Session-only memory store (if set this session)
   - OS keyring
   - Environment variable
   - Error if none found

3. **Add dependency**: `keyring` to `pyproject.toml`

### Security Considerations
- Never return actual key value in GET response
- Log credential operations without logging the key
- XSRF protection enabled for credential endpoints

**Session-Only Security Model** (be explicit):
- Stored in **server extension process memory only** (not kernel, not frontend, not disk)
- Cleared on:
  - Server extension restart (JupyterLab server restart)
  - Explicit `DELETE /dataing/credentials`
  - **NOT** cleared on kernel restart (credential is server-side, not kernel-side)
- After initial connect, frontend only receives `{stored: true}`, never the actual key
- Never logged, even in debug mode
- Never echoed in error messages
