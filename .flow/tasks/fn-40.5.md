# fn-40.5 Add publish step to release.yml CI workflow

## Description

Wire the PyPI publish workflow (fn-40.2) into the existing `release.yml` CI pipeline so that tagged releases automatically publish all client packages to PyPI. This is the final integration task that connects semantic-release version bumping, package building, and OIDC-based PyPI publishing into a single automated pipeline.

**Depends on:** fn-40.2, fn-40.3, fn-40.4

### Implementation

1. Update `.github/workflows/release.yml` to add a `publish` job after the existing `release` job:

   ```yaml
   publish:
     runs-on: ubuntu-latest
     needs: release
     if: needs.release.outputs.new_release_published == 'true'
     environment: pypi
     permissions:
       id-token: write
       contents: read

     strategy:
       matrix:
         package:
           - dir: python-packages/dataing-cli
             name: dataing-cli
           - dir: python-packages/dataing-sdk
             name: dataing-sdk
           - dir: python-packages/dataing-notebook
             name: dataing-notebook
           - dir: python-packages/dataing-meta
             name: dataing

     steps:
       - uses: actions/checkout@v4
         with:
           ref: ${{ needs.release.outputs.new_release_git_tag }}

       - name: Set up Python
         uses: actions/setup-python@v5
         with:
           python-version: "3.11"

       - name: Install build tools
         run: pip install build

       - name: Build package
         working-directory: ${{ matrix.package.dir }}
         run: python -m build

       - name: Publish to PyPI
         uses: pypa/gh-action-pypi-publish@release/v1
         with:
           packages-dir: ${{ matrix.package.dir }}/dist/
   ```

2. Ensure the `release` job outputs the new version info. Update the semantic-release step:
   ```yaml
   - name: Semantic Release
     id: semantic
     env:
       GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
     run: npx semantic-release
   ```
   Add outputs to the job:
   ```yaml
   outputs:
     new_release_published: ${{ steps.semantic.outputs.new_release_published }}
     new_release_version: ${{ steps.semantic.outputs.new_release_version }}
     new_release_git_tag: ${{ steps.semantic.outputs.new_release_git_tag }}
   ```

3. Add a version-sync step between `release` and `publish`:
   ```yaml
   - name: Sync versions across packages
     if: steps.semantic.outputs.new_release_published == 'true'
     run: python scripts/sync_versions.py ${{ steps.semantic.outputs.new_release_version }}
   ```

4. Add a post-publish verification step:
   ```yaml
   verify:
     runs-on: ubuntu-latest
     needs: publish
     steps:
       - name: Wait for PyPI propagation
         run: sleep 60

       - name: Verify packages on PyPI
         run: |
           pip install dataing-cli==${{ needs.release.outputs.new_release_version }}
           pip install dataing-sdk==${{ needs.release.outputs.new_release_version }}
           pip install dataing-notebook==${{ needs.release.outputs.new_release_version }}
           pip install "dataing[all]==${{ needs.release.outputs.new_release_version }}"
   ```

5. Update the existing `docker` job to depend on `publish` (so Docker images and PyPI publish happen in parallel after release, or sequentially if preferred):
   ```yaml
   docker:
     needs: release
     # Unchanged -- docker and publish run in parallel after release
   ```
