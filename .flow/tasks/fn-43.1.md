# fn-43.1 Create CONTRIBUTING.md with dev setup and PR process

## Description

Create a comprehensive CONTRIBUTING.md that guides new contributors through the development setup, coding standards, and pull request process. This is the primary onboarding document for open-source contributors and must lower the barrier to first contributions while enforcing quality standards like DCO sign-off and conventional commits.

### Implementation

1. Create `CONTRIBUTING.md` at the repository root with the following sections:
   - **Welcome** -- brief project summary and encouragement to contribute.
   - **Getting Started** -- prerequisites (Python 3.11+, Node 20+, uv, just), clone instructions, `just setup`, and `just dev` to verify the stack runs.
   - **Development Workflow** -- branching model (`main` is protected; work on feature branches), `just lint`, `just format`, `just typecheck`, `just test` before pushing.
   - **Code Style** -- link to Ruff config, line length 100, docstrings on all public methods and `__init__`, `isinstance(x, A | B)` form.
   - **Commit Messages** -- conventional commits format (`feat:`, `fix:`, `chore:`, `docs:`, `test:`, `refactor:`), scope optional but encouraged (e.g. `feat(temporal): ...`).
   - **DCO Sign-Off** -- every commit must include `Signed-off-by` via `git commit -s`; explain what the DCO is and link to https://developercertificate.org.
   - **Pull Request Process** -- open a draft PR early, fill in PR template, ensure CI is green, request review, squash-merge policy.
   - **Issue Triage** -- how to pick up a `good first issue`, how to ask for clarification.
   - **License** -- note that CE is Apache-licensed; EE code under `python-packages/dataing-ee/` has a separate license and external contributors should focus on CE.
   - **Community** -- link to Discord (placeholder URL until fn-44 completes), link to discussions.

2. Verify the document renders correctly on GitHub by checking markdown formatting.
