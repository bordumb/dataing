# fn-47.4 Add schedule CRUD API routes with pause/resume

## Description

Expose REST API endpoints for managing scheduled investigations: create, list, get, update, delete, pause, and resume. These endpoints allow the frontend and CLI to manage schedules. All operations are tenant-scoped via the existing auth middleware.

Depends on: fn-47.2 (repository must exist).

### Implementation

1. Create `python-packages/dataing/src/dataing/entrypoints/api/routes/schedules.py`:

```python
router = APIRouter(prefix="/schedules", tags=["schedules"])

# Pydantic request/response models:
class CreateScheduleRequest(BaseModel):
    asset_id: UUID
    goal: str
    cron_expression: str
    timezone: str = "UTC"
    notify_always: bool = False
    notification_channels: list[dict[str, Any]] = []
    workspace_id: UUID | None = None

class ScheduleResponse(BaseModel):
    id: UUID
    asset_id: UUID
    goal: str
    cron_expression: str
    timezone: str
    is_active: bool
    notify_always: bool
    notification_channels: list[dict[str, Any]]
    last_run_at: datetime | None
    next_run_at: datetime | None
    last_run_status: str | None
    created_at: datetime

class UpdateScheduleRequest(BaseModel):
    goal: str | None = None
    cron_expression: str | None = None
    timezone: str | None = None
    notify_always: bool | None = None
    notification_channels: list[dict[str, Any]] | None = None
```

2. Implement seven endpoints:
   - `POST /schedules` -- create schedule, compute `next_run_at`, start Temporal cron workflow
   - `GET /schedules` -- list schedules for tenant (query param `?active_only=true`)
   - `GET /schedules/{id}` -- get single schedule by ID
   - `PATCH /schedules/{id}` -- update mutable fields; if cron changes, restart the Temporal workflow
   - `DELETE /schedules/{id}` -- delete schedule and terminate Temporal cron workflow
   - `POST /schedules/{id}/pause` -- set `is_active=False`, terminate Temporal cron workflow
   - `POST /schedules/{id}/resume` -- set `is_active=True`, restart Temporal cron workflow

3. Validate `cron_expression` on create/update using `croniter.is_valid()`. Return 422 for invalid expressions.

4. Register the router in `python-packages/dataing/src/dataing/entrypoints/api/routes/__init__.py`.
