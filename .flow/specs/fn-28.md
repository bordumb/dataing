# Dataing CLI: Python Typer + Rich wrapper for SDK

## Overview

Build a command-line interface (`dataing-cli`) that wraps the existing `dataing-sdk` to provide terminal-based access to Dataing's investigation capabilities. The CLI uses Python with Typer for command structure and Rich for terminal formatting.

**Key decisions:**
- Python (not Rust) - reuses existing SDK, no API client reimplementation
- Typer + Rich - type-safe CLI with beautiful terminal output
- XDG paths for config, keyring for credentials
- Sync-first (SDK has sync methods)

## Scope

### In Scope
- Package scaffold: `python-packages/dataing-cli/`
- Config management: `~/.config/dataing/config.toml` + keyring
- Commands: `init`, `status`, `run start/watch/list`, `ds list/test/attach/schema`
- Rich output: tables, panels, live streaming display
- Shell completions: bash, zsh, fish
- Error handling with user-friendly messages
- Non-interactive mode for CI/CD (`--api-key`, `--url` flags)
- `--json` output flag for machine-readable output

### Out of Scope (deferred)
- GUI/TUI mode
- Plugin system
- Multi-profile management
- Investigation cancellation (API exists but not priority for v1)

### Dependencies (must exist first)
- `dataing-sdk` package (exists)
- SDK methods: `list_datasources()`, `test_datasource()`, `get_schema()` (need to add)
- API endpoint: `GET /api/v1/runs` for run listing (need to add or defer)

## Approach

### Package Structure
```
python-packages/dataing-cli/
├── pyproject.toml
├── src/
│   └── dataing_cli/
│       ├── __init__.py
│       ├── main.py              # Entry point, top-level commands
│       ├── commands/
│       │   ├── __init__.py
│       │   ├── run.py           # run start, watch, list
│       │   ├── ds.py            # ds list, test, attach, schema
│       │   └── config.py        # init, status (if separated)
│       ├── config.py            # Config + credential management
│       ├── output.py            # Rich formatting helpers
│       └── completions.py       # Dynamic shell completions
└── tests/
    ├── __init__.py
    ├── test_config.py
    ├── test_commands_run.py
    └── test_commands_ds.py
```

### Credential Storage Priority
1. `--api-key` flag (highest, for CI/CD)
2. `DATAING_API_KEY` env var
3. Keyring (`dataing-cli` service)
4. Config file (fallback, warns about security)

### Config File Format
```toml
# ~/.config/dataing/config.toml
api_url = "https://api.dataing.io"
default_datasource_id = "ds-abc123"
default_datasource_name = "prod-snowflake"
output_format = "table"  # or "json"
```

### Error Handling Strategy
Map SDK exceptions to user-friendly CLI output:
- `AuthError` → "Authentication failed. Check your API key." + exit 1
- `NotFoundError` → "Resource not found: {details}" + exit 1
- `RateLimitError` → "Rate limited. Retry after {retry_after}s" + exit 1
- `ValidationError` → "Invalid input: {field}: {message}" + exit 2
- `AmbiguousAssetError` → Show candidates table, prompt user
- Network errors → "Cannot connect to {url}. Check network." + exit 1

### Streaming Display Pattern
```python
with Live(Panel("Starting..."), refresh_per_second=4, transient=True) as live:
    for event in client.stream_run(run_id):
        if event.type == "progress":
            live.update(Panel(event.message, title="Progress"))
        elif event.type == "evidence":
            live.stop()  # Persist evidence panels
            console.print(format_evidence(event))
            live.start()
        elif event.type in ("completed", "failed"):
            live.stop()
            print_result(event)
```

## Risks and Mitigations

| Risk | Mitigation |
|------|------------|
| Keyring unavailable (CI, containers) | Fall back to env var, warn if using config file |
| `GET /runs` API doesn't exist | Defer `run list` or call `GET /runs/{id}` from local history |
| Rich output breaks in non-TTY | Detect TTY, use plain output or `--no-color` flag |
| Streaming SSE drops connection | Use `last_seq` parameter for resumption |

## Acceptance Criteria

- [ ] `dataing --help` shows all commands with descriptions
- [ ] `dataing init` stores credentials in keyring (or config with warning)
- [ ] `dataing status` shows connection status and config
- [ ] `dataing run start <table> --goal "..."` starts investigation, streams output
- [ ] `dataing run watch <id>` attaches to existing run
- [ ] `dataing ds list` shows datasources in table format
- [ ] `dataing ds attach <id>` sets default datasource
- [ ] `--json` flag works on all commands
- [ ] Exit codes: 0 success, 1 error, 2 usage error
- [ ] Shell completions install correctly
