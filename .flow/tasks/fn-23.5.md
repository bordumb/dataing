# fn-23.5 Settings Persistence via ISettingRegistry

## Description
## Task: Settings Persistence via ISettingRegistry

Persist non-secret settings through JupyterLab's settings system.

### Goal
Settings like backend URL, auto-connect preference, and check interval should survive JupyterLab restarts.

### Implementation

1. **Update settings schema** (`schema/plugin.json`):
   ```json
   {
     "backendUrl": { "type": "string", "default": "http://localhost:8000" },
     "autoConnect": { "type": "boolean", "default": true },
     "checkInterval": { "type": "integer", "default": 2000, "minimum": 1000 },
     "recentUrls": { "type": "array", "items": { "type": "string" }, "default": [] }
   }
   ```

2. **Load settings on activation**:
   - In `activate()`, load settings via `ISettingRegistry.load(PLUGIN_ID)`
   - Apply to widget state
   - Watch for changes via `settings.changed.connect()`

3. **Save settings on change**:
   - When user changes URL, call `settings.set('backendUrl', value)`
   - Update `recentUrls` array on successful connections

4. **DO NOT store API keys here** - that's fn-23.2's job

### Files to Modify
- `frontend/jupyterlab-dataing/schema/plugin.json` - Add settings properties
- `frontend/jupyterlab-dataing/src/index.ts` - Load/watch settings
- `frontend/jupyterlab-dataing/src/widget.ts` - Apply settings to widget

### Testing
- Manual: Change settings, restart JupyterLab, verify settings restored
- Settings appear in JupyterLab Settings Editor
