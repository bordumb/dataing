# fn-40.1 Sync package versions and add CHANGELOG.md per package

## Description

Align all five Python package versions to a consistent `0.1.0` starting point and add a `CHANGELOG.md` to each package directory. Currently the main `dataing` package is at `0.0.1` while the client packages are at `0.1.0`. Consistent versioning is required before PyPI publishing, and changelogs are a PyPI best practice for discoverability and trust.

Additionally, set up a version-sync mechanism so that `semantic-release` can bump versions across all packages atomically. The packages currently use hatchling as the build backend, so version management should be compatible with hatch's version source.

### Implementation

1. Update version strings to `0.1.0` in all `pyproject.toml` files:
   - `python-packages/dataing/pyproject.toml` -- change `version = "0.0.1"` to `version = "0.1.0"`
   - `python-packages/dataing-ee/pyproject.toml` -- verify/set to `0.1.0`
   - `python-packages/dataing-cli/pyproject.toml` -- already `0.1.0`, verify
   - `python-packages/dataing-sdk/pyproject.toml` -- already `0.1.0`, verify
   - `python-packages/dataing-notebook/pyproject.toml` -- already `0.1.0`, verify
   - Root `pyproject.toml` -- change `version = "0.0.1"` to `0.1.0`

3. Create `CHANGELOG.md` in each package directory with initial content:
   ```markdown

   All notable changes to this project will be documented in this file.
   ```

4. Configure semantic-release to use the version-sync script. Update `.releaserc` or `release.config.js`:
   ```json

       "@semantic-release/changelog",
       ["@semantic-release/exec", {
         "prepareCmd": "python scripts/sync_versions.py ${nextRelease.version}"
       }],
       "@semantic-release/git",
       "@semantic-release/github"
     ]
   }
   ```
