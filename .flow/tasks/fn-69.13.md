# fn-69.13 [M1] Acceptance: demo fixtures caught by checks

## Description
### Goal
Prove the engine against the 6 demo anomalies (design §11), and make `just demo` show real check results on a clean start and on an existing, populated demo database, **without losing any data**.

### Dependencies
The tracked migration runner (fn-69.34) must land first. Today `just demo` recreates `db-migrate`, which replays migrations that drop `users` and `investigations`.

### Acceptance test
- **File:** `tests/integration/checks/test_demo_fixture_suites.py`.
- **Setup:** DuckDB directory mode, with `as_of` = 2026-01-14. Run on `baseline/` N times first to build history.
- **Assert execution success separately from the outcome.**

| Fixture | Check |
|---|---|
| `null_spike` | `null_rate` on `user_id` |
| `volume_drop` | `row_count` with `change_pct` |
| `duplicates` | `duplicate_count` on `[order_id, product_id]` |
| `orphaned_records` | `orphan_count` from `user_id` to `users.user_id` |
| `late_arriving` | custom SQL counting late rows |
| `schema_drift` | custom SQL counting `TRY_CAST` failures |

### `just demo` wiring
- **Fixtures** are mounted into the `api` and `worker` containers (`demo/docker-compose.demo.yml:19` mounts them only into `pg_duckdb`), with `DATADR_FIXTURE_PATH` and `DATADR_DEMO_MODE` set.
- **An idempotent `demo bootstrap-checks` step** runs after migrations, whether or not the tenant already exists (`entrypoints/api/deps.py:309`). It:
  1. upserts the native DuckDB datasource by `key`;
  2. syncs its catalog;
  3. upserts a user credential and an automation credential;
  4. applies `demo/checks/*.yml`;
  5. starts and persists the initial runs.
- **Demo suites don't depend on the clock:** whole-table metrics, or custom SQL relative to the data.
## Acceptance
- [ ] On the baseline data, every check passes; on each anomaly fixture, the matching check fails and the others pass. Every check executes without error.
- [ ] Clean start: `just demo` reaches the Checks tab with persisted results.
- [ ] Running **the full `just demo` command** twice against a populated database keeps existing users, investigations, credentials and check results.
