# fn-23.10 SSE Reconnection with Resume

## Description

Implement robust SSE reconnection with a defined backend contract for resuming from last event.

### Goal
When SSE connection drops, automatically reconnect and resume from where we left off without duplicating or missing events.

### Backend Contract (REQUIRED)

This is not just a UI task - the backend must support resume semantics:

#### 1. Events MUST have `seq` field
Every SSE event includes a monotonically increasing sequence number per run:
```
event: investigation_step
id: 42
data: {"seq": 42, "type": "hypothesis_generated", ...}
```

#### 2. SSE endpoint accepts `?from_seq=N`
```
GET /api/v1/investigations/{run_id}/stream?from_seq=42
```
- Returns events starting from seq > 42
- If seq is valid and events available → stream from there
- If seq is valid but events expired → send `replay_unavailable` event, then continue with current
- If seq is invalid → send error event

#### 3. Server extension caches `last_seq`
```python
# Per (kernel_id, run_id)
_run_last_seq: dict[tuple[str, str], int] = {}
```

#### 4. Retention Policy (define expectations)

- Backend keeps last **1000 events** OR **last 30 minutes** per run (whichever is larger)
- After retention window, events are eligible for cleanup
- Clients should **not** assume infinite replay

#### 5. `replay_unavailable` event type
```
event: replay_unavailable
data: {"message": "Events before seq 50 are no longer available", "available_from": 50}
```

**UI behavior when replay unavailable**:
1. Show info banner: "Some history unavailable" (NOT error state)
2. Continue streaming from `available_from`
3. Offer "Open full run in web UI" link (if web UI exists)
4. Do NOT block the user - this is expected for long-running investigations

### Implementation

#### Backend Changes

1. **SSE event format** (if not already):
   ```python
   async def stream_events(run_id: str, from_seq: int | None = None):
       seq = from_seq or 0
       for event in get_events_since(run_id, seq):
           yield f"id: {event.seq}\nevent: {event.type}\ndata: {json.dumps(event.data)}\n\n"
   ```

2. **Server extension SSE proxy**:
   ```python
   class SSEProxyHandler(APIHandler):
       async def get(self, path: str):
           from_seq = self.get_query_argument("from_seq", None)
           # Forward to backend with from_seq
   ```

3. **Cache last_seq in state**:
   ```python
   run.last_seq = max(run.last_seq, event.seq)
   ```

#### Frontend Changes

1. **Track last received seq**:
   ```typescript
   let lastSeq = 0;
   eventSource.onmessage = (e) => {
       const data = JSON.parse(e.data);
       if (data.seq) lastSeq = data.seq;
   };
   ```

2. **Reconnection with resume**:
   ```typescript
   eventSource.onerror = () => {
       if (eventSource.readyState === EventSource.CLOSED) {
           // Reconnect with last seq
           const newSource = new EventSource(`${url}?from_seq=${lastSeq}`);
       }
   };
   ```

3. **Handle `replay_unavailable`**:
   ```typescript
   if (event.type === 'replay_unavailable') {
       showBanner("Some history unavailable");
   }
   ```

4. **UI states**:
   - Connected + streaming: normal timeline
   - Reconnecting: "Reconnecting..." overlay
   - Max retries exceeded: "Connection lost" + Manual Retry button
   - Replay unavailable: Info banner + continue streaming
