# fn-41.3 Create production docker-compose.yml with all services

## Description

Create the main `docker-compose.yml` at the repository root that starts the full Dataing stack for self-hosted deployment. This replaces the stale `demo/docker-compose.demo.yml` (which uses Arq/Redis workers, not Temporal). The production compose must include Temporal server, which is now the only supported investigation engine.

**Depends on**: fn-41.1 (backend Dockerfile), fn-41.2 (frontend Dockerfile)

### Implementation

1. Create `docker-compose.yml` at the repository root with these services:
   - **postgres** (`pgvector/pgvector:pg16`): Shared PostgreSQL for both the application database and Temporal persistence. Port 5432.
   - **temporal** (`temporalio/auto-setup:latest`): Temporal server with auto-setup that creates its own schema in the shared PostgreSQL. Depends on postgres. Port 7233 (gRPC) and 8233 (HTTP/UI).
   - **temporal-ui** (`temporalio/ui:latest`): Temporal Web UI for workflow visibility. Port 8233.
   - **redis** (`redis:7-alpine`): Cache and rate limiting. Port 6379.
   - **api** (built from `infra/Dockerfile.backend`): FastAPI server. Port 8000. Depends on postgres, temporal, redis.
   - **worker** (built from `infra/Dockerfile.backend`, command override to `python -m dataing.entrypoints.temporal_worker`): Temporal worker. Depends on postgres, temporal, redis.
   - **frontend** (built from `infra/Dockerfile.frontend`): Nginx serving React app. Port 3000. Depends on api.
2. Configure Temporal auto-setup to use the shared PostgreSQL:
   ```yaml
   environment:
     DB: postgresql
     POSTGRES_SEEDS: postgres
     POSTGRES_USER: temporal
     POSTGRES_PWD: temporal
     DYNAMIC_CONFIG_FILE_PATH: config/dynamicconfig/development-sql.yaml
   ```
3. Create a second PostgreSQL database for Temporal by adding an init script:
   - **CREATE**: `infra/init-temporal-db.sh` -- shell script mounted into postgres `/docker-entrypoint-initdb.d/` that creates the `temporal` user and `temporal`/`temporal_visibility` databases.
4. Wire environment variables for api and worker services:
   - `DATABASE_URL`, `APP_DATABASE_URL` pointing to `postgres:5432/dataing`
   - `TEMPORAL_HOST=temporal:7233`
   - `TEMPORAL_NAMESPACE=default`
   - `TEMPORAL_TASK_QUEUE=investigations`
   - `DATADR_ENCRYPTION_KEY` and `ANTHROPIC_API_KEY` read from host env (with `${VAR:-}` syntax)
5. Set `depends_on` with `condition: service_healthy` where health checks are defined (postgres, redis, temporal).
6. Use profiles to optionally include observability (otel-collector, jaeger) via `--profile observability`.

### Verification
```bash
# Validate compose file syntax
docker compose config

# Start all services
docker compose up -d

# Verify all services are running
docker compose ps

# Check API is responding
curl -f http://localhost:8000/health

# Check frontend is serving
curl -f http://localhost:3000/

# Check Temporal is accepting connections
docker compose exec worker python -c "
import asyncio
from temporalio.client import Client
async def check():
    c = await Client.connect('temporal:7233')
    print('Temporal OK')
asyncio.run(check())
"

# Tear down
docker compose down -v
```
