# fn-32.3 Pattern matching and resolution algorithm

## Description

Implement the core resolution algorithm that finds the best repo mapping for a given dataset identifier. Pure Python module with no database dependencies — the caller fetches candidate mappings and passes them in.

### Implementation

Create `python-packages/dataing/src/dataing/core/repo_mapping.py`:

1. **`normalize_dataset_id(dataset_id: str) -> list[str]`**
   - Returns list of normalized forms to match against
   - Input `"analytics.orders"` → `["analytics.orders"]`
   - Input `"mydb.analytics.orders"` → `["mydb.analytics.orders", "analytics.orders"]`
   - Lowercase, strip whitespace

2. **`match_pattern(pattern: str, pattern_type: str, dataset_id: str) -> bool`**
   - `exact`: direct string comparison after normalization
   - `glob`: `fnmatch.fnmatch` after normalization
   - Match against all normalized forms of dataset_id

3. **`resolve_file_path(template: str, dataset_id: str) -> str`**
   - Replace `{table}`, `{schema}`, `{database}` tokens
   - Parse dataset_id: `"analytics.orders"` → schema=analytics, table=orders
   - If template has no tokens, return as-is

4. **`resolve_repo_mapping(mappings: list[dict], dataset_id: str) -> dict | None`**
   - Filter mappings by `match_pattern`
   - Sort by `(priority ASC, confidence DESC, created_at DESC)`
   - Apply `resolve_file_path` to winning mapping's file_path
   - Return first match or None

5. **`resolve_all_repo_mappings(mappings: list[dict], dataset_id: str) -> list[dict]`**
   - Same filtering and sorting, returns all matches

### Design Notes
- Pure functions for testability
- `fnmatch` handles `*` (any chars) and `?` (single char) — sufficient for `analytics.*`, `*.orders`
- The DB layer handles exact match optimization; this module handles glob evaluation
