# Task fn-13.4: Observability Subchart

**Epic:** fn-13 Helm Charts for Self-Hosted Deployment
**Status:** blocked-by fn-13.2
**Estimate:** Medium

## Objective

Create optional observability components as a subchart, integrating with fn-12's OTEL implementation. Support two backends: Jaeger (simple) and Grafana+Tempo (production).

## Backend Options

| Backend | Use Case | Components | Complexity |
|---------|----------|------------|------------|
| `jaeger` | Dev, small deployments | Jaeger all-in-one | Single container |
| `grafana-tempo` | Production | Grafana + Tempo + Loki + Prometheus | Full observability stack |

## Deliverables

1. **Observability subchart** (charts/dataing/charts/observability/):
   - Backend selector (`jaeger` or `grafana-tempo`)
   - OTEL Collector deployment (shared by both backends)
   - Conditional templates based on backend choice

2. **OTEL Collector template**:
   - Receives OTLP from API/Worker
   - Exports traces to Jaeger OR Tempo based on backend
   - Exports metrics to Prometheus (when grafana-tempo backend)
   - Configurable via values.yaml

3. **Jaeger backend templates** (when `backend: jaeger`):
   - all-in-one image for simplicity
   - Service for UI access
   - Optional Ingress for external access
   - Dark mode enabled by default

4. **Grafana+Tempo backend templates** (when `backend: grafana-tempo`):
   - Grafana deployment with pre-configured datasources
   - Tempo deployment for trace storage
   - Loki deployment for log aggregation (optional)
   - Prometheus for metrics (optional, can use external)
   - Pre-built dashboards for Dataing (investigation latency, error rates, etc.)

5. **values.yaml structure**:
   ```yaml
   observability:
     enabled: false
     # Backend: "jaeger" (simple, dev) or "grafana-tempo" (production)
     backend: jaeger

     otelCollector:
       image:
         repository: otel/opentelemetry-collector-contrib
         tag: "0.96.0"
       resources:
         requests: { cpu: 100m, memory: 128Mi }

     # Jaeger backend (when backend: jaeger)
     jaeger:
       image:
         repository: jaegertracing/all-in-one
         tag: "1.76.0"
       persistence:
         enabled: false
         size: 10Gi
       ingress:
         enabled: false

     # Grafana stack (when backend: grafana-tempo)
     grafana:
       image:
         repository: grafana/grafana
         tag: "10.3.1"
       adminPassword: ""  # Generated if empty
       persistence:
         enabled: true
         size: 5Gi
       ingress:
         enabled: false

     tempo:
       image:
         repository: grafana/tempo
         tag: "2.3.1"
       persistence:
         enabled: true
         size: 50Gi

     loki:
       enabled: false  # Optional log aggregation
       image:
         repository: grafana/loki
         tag: "2.9.3"

     prometheus:
       enabled: false  # Set true or provide external endpoint
       external:
         url: ""  # Use external Prometheus if set
   ```

6. **Integration with core deployments**:
   - When observability.enabled, set OTEL env vars on API/Worker
   - Conditional OTEL_EXPORTER_OTLP_ENDPOINT pointing to collector
   - Automatic service discovery for trace correlation

7. **Pre-built Grafana dashboards** (ConfigMaps):
   - Investigation Performance: latency percentiles, throughput
   - Error Tracking: error rates by step, failure reasons
   - Resource Usage: LLM token consumption, query execution time
   - Queue Health: job backlog, processing time

## Acceptance Criteria

- [ ] Backend selector works (`jaeger` vs `grafana-tempo`)
- [ ] Jaeger backend: single container, traces visible in UI
- [ ] Grafana backend: unified view of traces, metrics, logs
- [ ] OTEL Collector routes to correct backend
- [ ] Observability can be disabled without errors
- [ ] Resources are configurable via values.yaml
- [ ] Pre-built dashboards load automatically in Grafana
- [ ] Documentation covers when to use each backend
