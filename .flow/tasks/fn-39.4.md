# fn-39.4 Build snapshot import with replay marking and schema validation

## Description

Implement the core import logic that reads a snapshot `.tar.gz` archive, validates its schema version, reconstitutes the investigation as a "replay" record, and stores all evidence. This is the inverse of the archive builder (fn-39.2). The importer must handle schema version migration for forward compatibility and clearly mark imported investigations so they are never confused with live runs.

**Depends on:** fn-39.1

### Implementation

1. Create `python-packages/dataing/src/dataing/core/snapshot_importer.py`:

   ```python
   class SnapshotImporter:
       """Import a snapshot archive and create a replayed investigation."""

       def __init__(self, max_size_bytes: int = 100 * 1024 * 1024) -> None: ...

       def validate_archive(self, archive_path: Path) -> SnapshotMetadata:
           """Extract and validate metadata.json from archive.

           Raises:
               InvalidSnapshotError: If archive is malformed or schema unsupported.
               SnapshotSizeExceededError: If archive exceeds max_size_bytes.
           """

       def extract_evidence(
           self, archive_path: Path,
       ) -> list[dict[str, Any]]:
           """Extract all evidence items from the archive."""

       def extract_prompts(
           self, archive_path: Path,
       ) -> dict[str, str]:
           """Extract prompt templates from the archive."""

       def import_investigation(
           self,
           archive_path: Path,
           target_tenant_id: str,
       ) -> ImportResult:
           """Full import: validate, extract, create replay investigation."""
   ```

2. Schema version validation:
   - Parse `schema_version` from `metadata.json`.
   - Support version `"1.0"` initially.
   - For unknown versions, raise `UnsupportedSchemaVersionError` with a message indicating the minimum required Dataing version.
   - Add a `SUPPORTED_SCHEMA_VERSIONS` set for easy extension.

3. Replay marking:
   - Set `status = "replay"` on the imported investigation.
   - Preserve `created_at` from the original investigation (stored in metadata).
   - Add `imported_at` timestamp.
   - Store `original_investigation_id` from metadata.
   - Store `source_instance` URL if present.

4. Security checks for import:
   - Validate tar archive for path traversal attacks (reject entries with `..` or absolute paths).
   - Strip `tenant_id` from imported metadata (prevent cross-tenant data leakage in CE).
   - Verify file inventory in `metadata.json` matches actual archive contents.


6. Define error types:
