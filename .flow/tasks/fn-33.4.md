## Description
## Add CLI Verify Command and Export Enhancement

### What
Add `dataing verify <investigation_id>` CLI command and enhance the existing export to include per-item evidence chain metadata.

### Why
The CLI verify command provides a quick way for operators and auditors to check investigation integrity from the command line. Enhanced export enables external/offline verification.

### Approach

1. **Add SDK method**:
   - In `dataing-sdk/src/dataing_sdk/client.py`: add `verify_investigation(investigation_id: str)` method
   - Calls `GET /api/v1/investigations/{id}/verify` (from fn-33.3)
   - Returns typed response

2. **Add CLI verify command**:
   - In `dataing-cli/src/dataing_cli/commands/run.py` (or new `verify.py`): add `verify` subcommand
   - Usage: `dataing verify <investigation_id>`
   - Output format:
     - Success: green checkmark, evidence count, root hash
     - Failure: red X, broken item seq, error details
     - Not available: yellow warning, "chain not available for this investigation"
   - Exit codes: 0=valid, 1=broken, 2=not available
   - Use `@cli_error_handler` decorator
   - Follow patterns from existing CLI commands

3. **Enhance export with chain metadata**:
   - In `dataing-cli/src/dataing_cli/export.py`:
   - Add per-item `content_hash`, `prev_hash`, `seq` to markdown and JSON export
   - Add header metadata: `hash_algorithm: "sha256"`, `canonicalization: "rfc8785"`, `chain_version: "evidence_v1"`
   - Include `root_hash` in investigation metadata section
   - Replace existing `compute_chain_hash()` (which hashes entire list at once) with per-item chain data

4. **Update SDK types**:
   - Add `ChainVerificationResult` type to `dataing-sdk/src/dataing_sdk/types.py`
