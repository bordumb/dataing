# fn-69.4 [M1] SQL compiler for built-in metrics and custom SQL

## Description
### Goal
`compile_check(resolved_check, dataset, dialect, as_of, catalog)` produces one query, correct for the datasource's dialect, that returns one number (design §5.1 step 2, §16 "Compiler details", §17).

### Implementation
- **File:** `dataing/checks/compiler.py`. Map each `SourceType` (`adapters/datasource/types.py:16-43`) to a sqlglot dialect.
- **Build with sqlglot expressions, not strings.**
  - Tables use `exp.table_(…, quoted=True)` from the catalog parts on `datasets`. Never split `native_path`.
  - Identifier case comes from the catalog, which matters for Snowflake.
- **Built-in metric semantics** (exact definitions, added to design §3.6):
  - Counts COALESCE to 0.
  - `null_count`/`null_rate`: rate = nulls / rows, NULL when there are 0 rows.
  - `distinct_count`: distinct key tuples among rows with no NULL key.
  - `duplicate_count`: `count(*) - count(distinct key tuple)` over rows with no NULL key column. So three identical rows count as **2**.
  - `accepted_values_violations`: non-NULL values not in the list. NULL is not a violation.
  - `orphan_count`: `NOT EXISTS`. A NULL foreign key isn't an orphan, and the window applies only to the checked dataset.
  - Multi-column keys use a grouped subquery, because BigQuery rejects `COUNT(DISTINCT a, b)`.
  - Ratios use `CAST(... AS DOUBLE)` and `NULLIF`. `freshness_minutes` uses `exp.DateDiff(unit=MINUTE)`.
- **`window` and `where`:**
  - Bounds are literals computed from `as_of`.
  - `where` is parsed in the datasource's dialect.
- **Custom SQL** (and the SQL of resolved library metrics):
  - Replace `{{ dataset }}` with a sentinel.
  - Parse **all** statements with `sqlglot.parse(dialect=…)`, and require exactly one non-empty statement. `parse_one` silently drops the second statement of `SELECT …; DELETE …`.
  - Then `transform` sentinel `Table` nodes into the table, or into a filtered subquery that keeps any alias.
  - Never transpile custom SQL, and don't use `exp.replace_tables`.
- **`compiled_sql_hash`** hashes the canonical query semantics: dialect, dataset identity, the resolved AST, the window column and duration, and the filters. Only the generated `as_of` anchor literals are normalized; authored constants are kept.

### Tests
- **Snapshots** for postgres, snowflake, bigquery, duckdb and trino.
- **Execution:** run every metric on DuckDB and Postgres (throwaway container), with **exact expected values** on small fixtures covering:
  - repeated groups;
  - NULL keys and NULL values;
  - empty input;
  - rows exactly at the window boundaries.
## Acceptance
- [ ] Snapshot tests cover every built-in metric on all 5 dialects.
- [ ] Exact-value tests pass on both DuckDB and Postgres for duplicates (3 identical rows → 2), NULL keys, accepted values with NULLs, orphans with NULL foreign keys, empty input and window boundaries.
- [ ] Two-statement custom SQL is rejected, not truncated. A compiler → validator test proves it.
- [ ] A `{{ dataset }} o` alias is preserved, and custom SQL gets the window through the subquery.
- [ ] Column names always end up as quoted identifiers (an injection-attempt test). The Snowflake snapshot shows catalog-cased `"ANALYTICS"."ORDERS"`.
- [ ] The hash is unchanged when only `as_of` or a threshold changes, and changes when the window duration, filters, dataset or resolved library SQL change.
