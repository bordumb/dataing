# fn-69.29 [M4] Edition switch in deployments and Temporal images

## Description
### Goal
Run CE or EE from the same images and builds (design §10.1, §10.3, §17).

### Implementation
- **Edition switch:** `DATAING_EDITION=ce|ee` picks the API app and the worker entrypoint in:
  - `infra/Dockerfile.backend:81`
  - `Procfile:1`
  - `docker-compose.yml`, for the api and worker services
  - Railway
- **Railway:** `railway.json` uses Nixpacks with `uv sync --frozen --no-dev` on the root project, which doesn't include `dataing-ee`. Add a reproducible dependency setup that installs the matching CE and EE packages, and smoke-test both entrypoints in that build.
- **Temporal:** replace the deprecated `temporalio/auto-setup:latest` with pinned `temporalio/server` and `temporalio/admin-tools`, starting in this order:
  1. Postgres
  2. set up or update both Temporal schemas (default and visibility)
  3. wait for the server to be ready
  4. register `TEMPORAL_NAMESPACE`, idempotently
  5. start the workers

  Also pin `temporalio/ui`.
- **Docs:** `DATAING_EDITION`, `DATAING_PUBLIC_URL`, the required encryption key, `REDIS_URL`, and the SaaS-only GitHub App variables (optional; validated only in SaaS mode, fn-69.23), in `.env.example` and `infra/check-env.sh`.
## Acceptance
- [ ] Temporal comes up correctly from a fresh volume, after a restart with existing volumes, and with a non-default namespace; each is verified by completing an actual workflow.
- [ ] `docker compose up` with `DATAING_EDITION=ee` serves the EE routes and runs the EE worker; with `ce`, it serves CE only.
- [ ] The Railway build installs EE, and both entrypoints pass a smoke test.
- [ ] No `:latest` Temporal images remain.
