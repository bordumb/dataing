# fn-37.3 Add code_change hypothesis category and commit evidence linking

## Description

Extend the hypothesis system to support a new `code_change` category so the LLM can generate hypotheses that specifically attribute anomalies to code deploys. Add commit reference fields to hypothesis and evidence models so findings can link back to specific commits. Update the system prompt to include `code_change` as a valid category with guidance on when to use it.

### Implementation

1. Add `CODE_CHANGE` to `HypothesisCategory` enum in `python-packages/dataing/src/dataing/core/domain_types.py`:
   ```python
   class HypothesisCategory(str, Enum):
       UPSTREAM_DEPENDENCY = "upstream_dependency"
       TRANSFORMATION_BUG = "transformation_bug"
       DATA_QUALITY = "data_quality"
       INFRASTRUCTURE = "infrastructure"
       EXPECTED_VARIANCE = "expected_variance"
       CODE_CHANGE = "code_change"
   ```

2. Update the SYSTEM_PROMPT in `python-packages/dataing/src/dataing/agents/prompts/hypothesis.py` to include `code_change` in the HYPOTHESIS CATEGORIES section:
   ```
   - code_change: Recent code deploy altered query logic, schema, or data flow
   ```

3. Add optional `commit_refs` field to `Evidence` model in `domain_types.py`:
   ```python
   class Evidence(BaseModel):
       ...
       commit_refs: list[str] | None = None  # Commit hashes linked to this evidence
   ```

4. Update the `HypothesisResponse` model in `python-packages/dataing/src/dataing/agents/models.py` to accept the new category. Verify the Pydantic validation allows `code_change` as a valid category value.

5. Update tests in `python-packages/dataing/tests/unit/agents/test_models.py` to cover the new category, ensuring `code_change` hypotheses validate correctly.

6. Add tests verifying that `Evidence` with `commit_refs` serializes/deserializes correctly through the Temporal adapter.
