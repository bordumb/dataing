# fn-10.7 Handle BRANCH signal with child jobs

## Description

Handle maestro BRANCH signal by creating child jobs for parallel hypothesis testing.

### Problem

When maestro emits `Signal.BRANCH`, multiple parallel execution paths are created. Each branch needs its own job for durable execution.

### Solution

1. Parent job receives BRANCH signal with `BranchSpec` list
2. Parent creates child jobs (one per branch)
3. Parent sets status to `awaiting_merge`
4. Child jobs execute independently
5. Last child to complete triggers MERGE
6. Parent resumes from merge point

### Files to Modify

**dataing/src/dataing/entrypoints/worker.py**:

Add branch handling:
```python
if result.signal == Signal.BRANCH:
    # Create child jobs
    for spec in result.branch_specs:
        await enqueue_investigation(
            investigation_id=investigation_id,
            tenant_id=tenant_id,
            parent_job_id=job_id,
            branch_spec=spec.model_dump(),
        )

    # Mark parent as waiting
    await db.execute("""
        UPDATE investigation_jobs SET status = 'awaiting_merge'
        WHERE id = $1
    """, job_id)

    return {"status": "branched", "children": len(result.branch_specs)}
```

Add merge detection:
```python
async def check_merge_ready(db, parent_job_id: str) -> bool:
    """Check if all child branches completed."""
    result = await db.fetchrow("""
        SELECT COUNT(*) FILTER (WHERE status != 'complete') as pending
        FROM investigation_jobs
        WHERE parent_job_id = $1
    """, parent_job_id)
    return result["pending"] == 0
```
