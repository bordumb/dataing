# fn-45.3 Implement Assertion Consumer Service (ACS) endpoint

## Description

Create the SAML ACS endpoint that receives the IdP's POST response after user authentication. This
endpoint validates the SAML response (signature, conditions, audience), extracts user identity, and
issues JWT tokens -- the SAML equivalent of the existing OIDC `/auth/sso/callback`. The ACS is the
most security-critical piece of the SAML flow: it must reject tampered, expired, or replayed
assertions.

Depends on: fn-45.2 (login redirect must exist to generate the state consumed here).

### Implementation

1. Add a new POST route in `python-packages/dataing-ee/src/dataing_ee/entrypoints/api/routes/sso.py`:
   ```python
   @router.post("/saml/acs")
   async def saml_acs(
       request: Request,
       state_repo: StateRepoDep,
       sso_repo: SSORepoDep,
   ) -> SSOTokenResponse:
   ```

2. Parse the form-encoded POST body:
   ```python
   form = await request.form()
   saml_response_b64 = form.get("SAMLResponse")
   relay_state = form.get("RelayState")  # This is our state_id
   ```

3. Validate and consume the SSO state (relay_state) using `state_repo.validate_and_consume()`,
   identical to the OIDC callback pattern (lines 243-261 of sso.py).

4. Retrieve the SAML SSO config for the org from `sso_repo.get_sso_config(sso_state.org_id)`.
   Verify `provider_type == SSOProviderType.SAML` and config is complete.

5. Build `SAMLProvider` with the org's config and call:
   ```python
   user_info = await provider.validate_response(
       saml_response_b64=saml_response_b64,
       expected_request_id=sso_state.state_id,
   )
   ```

6. Handle validation errors:
   - `SAMLSignatureError` -> 400 "SAML signature verification failed"
   - `SAMLConditionError` -> 400 "SAML assertion conditions not met"
   - `SAMLResponseError` -> 400 "SAML response validation failed"

7. Extract identity: `name_id` (IdP user ID), `email` from `user_info`.

8. Look up or create the user following the same JIT provisioning pattern as the OIDC callback
   (lines 352-412 of sso.py):
   - Check `sso_repo.get_sso_identity(sso_config.id, name_id)`.
   - If exists, load user. If not, check by email and link (if email_verified) or JIT provision.
   - Create SSO identity link.

9. Issue JWT tokens using `create_access_token` / `create_refresh_token`.

10. Return redirect to frontend with tokens (or return `SSOTokenResponse` for API consumers).

11. Add tests in `python-packages/dataing-ee/tests/unit/routes/test_saml_acs.py`:
    - Mock valid SAML response -> returns tokens.
    - Tampered signature -> 400.
    - Expired assertion -> 400.
    - Invalid/consumed relay_state -> 400.
    - SP-only: reject requests without relay_state (no IdP-initiated).
