# fn-69.1 [M1] Check spec models, JSON Schema and strict YAML loader

## Description
### Goal
Build the Pydantic `CheckSpec` models for `dataing/v1` (`CheckSuite` and `MetricLibrary`), the JSON Schema generated from them, and a strict YAML loader that reports errors with 1-based file:line positions. Design §3 and §16 ("Strict spec").

### Implementation
- **New package** `python-packages/dataing/src/dataing/checks/`: `__init__.py`, `spec.py`, `loader.py`, `schema.py`, `resolve.py`.
- **Models:**
  - Use `ConfigDict(extra="forbid", frozen=True)`. `apiVersion: Literal["dataing/v1"]`, with `kind` as the discriminator.
- **A check is one of three variants**, chosen by a *callable* `Discriminator` with `Tag`s whose names can't collide with YAML keys, so a typo produces one error, not five:
  1. **Built-in metric:** `metric` is one of the names in §3.6.
  2. **Library metric reference:** `metric` has the form `<namespace>.<name>`, e.g. `acme.revenue_per_order`.
  3. **Custom SQL:** `sql`, which requires `key`.
- **Conditions** (§3.5): comparisons, `between`/`outside`, and a signed `change_pct` with `baseline: previous | avg_<N>_runs`. Every check needs `fail_when` or `warn_when`.
- **Keys:**
  - Default: `<metric>_<column or columns>`. A library reference uses its dotted name with `.` replaced by `_`.
  - Keys are unique within a suite.
- **Resolution** (`resolve.py`) turns a parsed suite plus fetched libraries into a `ResolvedSuite`:
  - Library references are replaced with the library's SQL.
  - Import refs are pinned to SHAs.
  - Unknown namespaces or metric names are errors at the reference's line.

  This `ResolvedSuite` is the contract that the compiler (fn-69.4), the runner (fn-69.8), apply (fn-69.9), sync (fn-69.25) and previews (fn-69.27) consume. The loader validates syntax only; resolution needs the fetched libraries.
- **Schema:**
  - `schema.py` has a `json_schema()` wrapper, following `core/snapshot_schema.py:202-208`.
  - Add `$schema` with a `GenerateJsonSchema` subclass.
  - Commit the output to `checks/schema/dataing-v1.schema.json`.
- **Loader:**
  - Use ruamel.yaml `YAML()` in round-trip mode, and read positions from `.lc`. Those are 0-based, so add 1.
  - Reject anchors and aliases, cap files at 256 KiB, and report duplicate keys as errors.
  - Map a Pydantic `loc` to the nearest node that exists (this handles missing keys).
  - Return `LoadResult(spec | None, errors: list[SpecError(path, line, column, message)])`. Never raise on user input.
- **Canonical dump settings** (`width=4096`, `preserve_quotes`, `indent(mapping=2, sequence=4, offset=2)`) are exported for write-back (fn-69.28).
- **Dependencies:** add `ruamel.yaml>=0.19.1,<0.20`, pin `sqlglot` to one minor version (currently locked on 28.x), and re-lock with `uv lock`.
## Acceptance
- [ ] The complete design §3.2 example loads and resolves, including the `acme.revenue_per_order` library reference, and survives load → dump unchanged in canonical style.
- [ ] An unknown key (`fail_wehn`) gives exactly one error at the correct 1-based line.
- [ ] A missing condition, a duplicate YAML key, an anchor or alias, and an oversized file each give one clear error and no exception.
- [ ] An unknown library namespace or metric is rejected at resolution, with the line of the reference.
- [ ] Key derivation and uniqueness are enforced, and a `sql` check without `key` is rejected.
- [ ] The committed JSON Schema matches `json_schema()`; a test fails if it's stale.
- [ ] ruff and mypy are clean.
