# fn-45.5 Add SAML metadata endpoint and admin configuration routes

## Description

Expose an SP metadata endpoint that IdP administrators can use to configure their side of the
trust relationship, and add admin API routes for creating/updating SAML SSO configuration. The
metadata endpoint publishes the SP entity ID, ACS URL, and optionally an SP signing certificate in
standard SAML 2.0 metadata XML format. The admin routes let tenant admins configure their IdP
details (metadata URL, entity ID, certificate) and attribute/group mappings.

Depends on: fn-45.1 (SAMLProvider must exist for metadata generation).

### Implementation

1. Add a public (no auth) GET endpoint in
   `python-packages/dataing-ee/src/dataing_ee/entrypoints/api/routes/sso.py`:
   ```python
   @router.get("/saml/metadata", response_class=Response)
   async def saml_metadata() -> Response:
       """Return SP metadata XML for IdP configuration."""
       sp_entity_id = _get_sp_entity_id()
       acs_url = _get_acs_url()
       metadata_xml = build_sp_metadata_xml(
           entity_id=sp_entity_id,
           acs_url=acs_url,
           name_id_format="urn:oasis:names:tc:SAML:1.1:nameid-format:emailAddress",
       )
       return Response(content=metadata_xml, media_type="application/xml")
   ```

2. Add `build_sp_metadata_xml()` helper to `saml_provider.py`:
   - Generate `<EntityDescriptor>` with `<SPSSODescriptor>` containing:
     - `<AssertionConsumerService>` with Binding=`urn:oasis:names:tc:SAML:2.0:bindings:HTTP-POST`
       and Location=acs_url.
     - `<NameIDFormat>` element.
   - Use `lxml.etree` for XML construction.

3. Add admin-only routes for SAML configuration in a new section of the SSO routes (or in
   `python-packages/dataing-ee/src/dataing_ee/entrypoints/api/routes/settings.py` if SSO admin
   routes belong there):
   ```python
   @router.post("/saml/config")
   async def create_saml_config(body: CreateSAMLConfigRequest, ...) -> SAMLConfigResponse:
       """Create or update SAML SSO configuration for the tenant."""

   @router.put("/saml/config")
   async def update_saml_config(body: UpdateSAMLConfigRequest, ...) -> SAMLConfigResponse:
       """Update SAML SSO configuration."""

   @router.get("/saml/config")
   async def get_saml_config(...) -> SAMLConfigResponse:
       """Get current SAML SSO configuration."""

   @router.post("/saml/config/test")
   async def test_saml_config(body: TestSAMLConfigRequest, ...) -> TestSAMLConfigResponse:
       """Test SAML configuration by fetching IdP metadata."""
   ```

4. Define Pydantic request/response models:
   - `CreateSAMLConfigRequest`: `idp_metadata_url`, `idp_entity_id`, `certificate`,
     `attribute_mapping` (optional), `group_role_mapping` (optional), `display_name`.
   - `SAMLConfigResponse`: all config fields plus certificate expiry date.
   - `TestSAMLConfigResponse`: `success`, `idp_entity_id`, `sso_url`, `error` (if any).

5. The test endpoint should fetch the IdP metadata URL and validate it parses correctly,
   returning the discovered IdP entity ID and SSO URL.

6. Add tests in `python-packages/dataing-ee/tests/unit/routes/test_saml_metadata.py`:
   - Test metadata XML is valid and contains correct ACS URL and entity ID.
   - Test admin CRUD routes with auth.
   - Test config test endpoint.
