# fn-14.11 SLA tracking and breach notifications

## Description

Add SLA tracking and breach notification system.

### SLA Compute Model (Critical)
- SLA timers are **derived fields** (not constantly written)
- `sla_policy_id` nullable on issues; uses tenant default if null
- Background job evaluates breaches and writes `issue_events` + enqueues notifications

### SLA Policy Table (CE)
```sql
CREATE TABLE sla_policies (
    id UUID PRIMARY KEY,
    tenant_id UUID NOT NULL REFERENCES tenants(id),
    name TEXT NOT NULL,
    is_default BOOLEAN DEFAULT false,
    -- Time limits in minutes
    time_to_acknowledge INT,  -- ack = OPEN → TRIAGED
    time_to_progress INT,     -- progress = TRIAGED → IN_PROGRESS
    time_to_resolve INT,      -- resolve = any → RESOLVED
    -- Per severity overrides (JSONB)
    severity_overrides JSONB,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### Background Job
- Poll issues approaching SLA breach (50%, 75%, 90% thresholds)
- Create issue_events on breach
- Enqueue notifications via outbox pattern

### Notifications
- Notify: assignee, watchers, escalation chain (EE)
- Respect dataset permissions (no leaking content)
- SLA clock pauses when issue is BLOCKED
