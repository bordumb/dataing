# fn-23.1 Asset Instances Search API Endpoint

## Description

Create a cross-datasource **asset instances** search endpoint with a well-defined contract for the typeahead picker.

### Goal
Enable searching for asset instances (concrete table/view in a specific datasource) across all tenant datasources. Each result is fully qualified - no ambiguity.

### Why "Asset Instances" (not "Assets")

This endpoint returns **asset instances** (asset + specific datasource), not abstract assets:
- Each result maps to exactly one datasource (no ambiguity at selection time)
- 409 only happens if user types asset name manually without using picker
- Picker UX is cleaner: user sees "orders (Production)" vs "orders (Staging)" as separate options

### API Contract

```
GET /api/v1/asset-instances/search
  ?q=<query>           # Required, min 1 char
  &limit=<int>         # Default 10, max 100
  &cursor=<string>     # Opaque pagination cursor (base64-encoded offset)
  &datasource_id=<id>  # Optional filter

Response:
{
  "results": [
    {
      "asset_urn": "urn:dataing:postgres:ds_prod:public.orders",  # Includes datasource!
      "display_name": "orders",
      "type": "table",              # table | view | dataset
      "schema": "public",
      "datasource_id": "ds_prod",
      "datasource_name": "Production Analytics",
      "platform": "postgres",
      "match_reason": "name_prefix" # name_exact | name_prefix | name_contains | schema_match
    }
  ],
  "next_cursor": "eyJvZmZzZXQiOjEwfQ==" | null,
  "total_hint": 42  # Approximate total for UI (optional, can be expensive)
}
```

**URN Format**: `urn:dataing:{platform}:{datasource_id}:{schema}.{table}`
- Fully qualified, includes datasource
- Attaching this URN is deterministic (no 409 possible)

### Implementation

1. **New endpoint**: `GET /api/v1/assets/search` in `routes/assets.py` (new file)

2. **Query logic** (in order of relevance):
   - Exact name match → `match_reason: "name_exact"`
   - Name prefix match → `match_reason: "name_prefix"`
   - Name contains match → `match_reason: "name_contains"`
   - Schema match → `match_reason: "schema_match"`

3. **Pagination**:
   - Cursor-based (NOT offset in query string)
   - Cursor encodes: `{"offset": N, "sort_key": "..."}`
   - Server-side pagination is **non-negotiable** for 10k+ catalogs

4. **Performance**:
   - Database index on table name (ensure exists)
   - Query timeout limit (5s)
   - Consider caching popular searches in Redis (optional, Phase 2)
