# fn-32.9 Unit tests for resolution, pattern matching, and CRUD

## Description

Comprehensive unit tests for the repo mapping system. Focus on the resolution algorithm (the core logic) and API endpoint behavior.

### Implementation

**1. Core resolution tests** — `python-packages/dataing/tests/unit/core/test_repo_mapping.py`:

- `test_normalize_dataset_id_schema_table` — "analytics.orders" → ["analytics.orders"]
- `test_normalize_dataset_id_db_schema_table` — "mydb.analytics.orders" → ["mydb.analytics.orders", "analytics.orders"]
- `test_match_exact_pattern` — exact match works
- `test_match_exact_pattern_case_insensitive` — "Analytics.Orders" matches "analytics.orders"
- `test_match_glob_wildcard` — "analytics.*" matches "analytics.orders"
- `test_match_glob_prefix_wildcard` — "*.orders" matches "analytics.orders"
- `test_match_glob_no_match` — "analytics.*" doesn't match "staging.orders"
- `test_resolve_file_path_tokens` — "{schema}/{table}.sql" → "analytics/orders.sql"
- `test_resolve_file_path_no_tokens` — "dags/orders.py" → "dags/orders.py"
- `test_resolve_repo_mapping_priority_order` — lower priority wins
- `test_resolve_repo_mapping_confidence_tiebreak` — higher confidence wins at same priority
- `test_resolve_repo_mapping_exact_beats_glob` — explicit (priority=0) beats pattern (priority=10)
- `test_resolve_repo_mapping_no_match` — returns None
- `test_resolve_all_returns_sorted_list` — all matches returned in order

**2. API endpoint tests** — `python-packages/dataing/tests/unit/routes/test_repo_mappings.py`:

- `test_create_repo_mapping` — POST returns 200 with mapping
- `test_create_repo_mapping_invalid_pattern_type` — POST with bad pattern_type returns 422
- `test_list_repo_mappings_empty` — GET returns empty list
- `test_list_repo_mappings_with_filter` — GET with source filter
- `test_update_repo_mapping` — PUT updates fields
- `test_delete_repo_mapping` — DELETE returns 200
- `test_delete_repo_mapping_not_found` — DELETE returns 404
- `test_resolve_dataset_repo_found` — GET /datasets/{id}/repo returns mapping
- `test_resolve_dataset_repo_not_found` — returns primary=null, not 404
- `test_bulk_import` — POST /bulk creates multiple
- `test_suggestions_list` — GET /suggestions returns unconfirmed only
- `test_confirm_suggestion` — POST /confirm sets confirmed=true
- `test_dismiss_suggestion` — POST /dismiss deletes

**3. dbt manifest import tests** — in same file or separate:

- `test_parse_dbt_manifest_models_only` — only model nodes imported
- `test_parse_dbt_manifest_schema_name` — correct dataset_pattern
- `test_parse_dbt_manifest_file_path` — original_file_path preserved
