# fn-32.7 Dataset resolve endpoint

## Description

Add the resolution endpoint that returns the best repo mapping for a given dataset. This is the primary endpoint consumed by the investigation agent.

### Implementation

Add to `routes/repo_mappings.py` (or a separate datasets route file):

```python
class ResolvedRepoResponse(BaseModel):
    repo_owner: str
    repo_name: str
    file_path: str | None
    branch: str | None
    confidence: float
    source: str
    job_name: str | None

class DatasetRepoResponse(BaseModel):
    dataset_id: str
    primary: ResolvedRepoResponse | None
    all_matches: list[ResolvedRepoResponse] | None = None  # only if include_all=true
```

**Endpoint:** `GET /datasets/{dataset_id}/repo`

Query params:
- `include_all: bool = False` — if true, return all matching mappings

**Logic:**
1. Call `db.resolve_repo_for_dataset(tenant_id, dataset_id)` to get exact matches from DB
2. If no exact matches, load all glob patterns for tenant and evaluate with `core.repo_mapping.resolve_all_repo_mappings()`
3. Apply `resolve_file_path()` to substitute `{table}`, `{schema}` tokens
4. Return primary (first match) + optionally all matches
5. If no matches found, return `{"dataset_id": "...", "primary": null}`

**Graceful degradation:** This endpoint returns 200 with `primary: null` when no mapping exists — never 404. The agent checks `primary` and skips CODE_CHANGE hypothesis if null.
