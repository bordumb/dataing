# Alert Ingestion Hub

## Overview

Make dataing the universal receiver for data quality alerts from external monitoring tools. Transform incoming alerts into `AnomalyAlert` objects and auto-start investigations.

**Goal**: Become the "ears" of the octopus — capture alerts from Monte Carlo, Great Expectations, Soda, dbt, and custom sources.

## Current State

### What Already Exists

1. **Monte Carlo Adapter (EE)**: `dataing-ee/src/dataing_ee/adapters/integrations/monte_carlo.py`
   - Signature verification, payload parsing, fingerprinting
   - Outputs `IssueData` (NOT wired to auto-investigation)

2. **Great Expectations Adapter (EE)**: `dataing-ee/src/dataing_ee/adapters/integrations/great_expectations.py`
   - Signature verification, validation result parsing
   - Outputs `IssueData` (NOT wired to auto-investigation)

3. **CE Generic Webhook**: `dataing/entrypoints/api/routes/integrations.py:121-278`
   - Policy evaluation and auto-investigation via Temporal
   - Single shared secret, no per-provider configuration

4. **EE Webhook Routes**: `dataing-ee/src/dataing_ee/entrypoints/api/routes/integrations.py`
   - `POST /{provider}/webhook` endpoint
   - Creates Issues but does NOT trigger auto-investigation
   - Inline parsing logic (doesn't use adapter classes)

### Key Gap

EE provider webhooks stop at Issue creation. They don't evaluate policy or start investigations like CE generic webhook does.

## Approach

### Architecture Decision: Unified Flow

All provider webhooks should follow the same flow:

```
POST /webhooks/{provider}
  → verify_signature(adapter)
  → parse_payload(adapter) → IssueData
  → convert_to_anomaly_alert(issue_data) → AnomalyAlert
  → create_issue(issue_data)
  → evaluate_policy(anomaly_alert)
  → if AUTO: start_investigation(anomaly_alert)
```
