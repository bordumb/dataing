# fn-15.1 Create state.py with RunState, BranchState, AwaitState

## Description

Create `maestro/src/maestro/state.py` with frozen dataclasses representing workflow run state.

**Classes to implement:**

1. **RunStatus** - Literal type: `"running" | "paused" | "completed" | "failed"`

2. **BranchState** - Tracks pending branch execution:
   - `merge_step: str` - step to execute after merge
   - `expected: frozenset[str]` - branch names expected to complete
   - `completed: dict[str, dict[str, Any]]` - branch_name -> context_update (use `field(default_factory=dict)`)

3. **AwaitState** - Tracks AWAIT_USER pause state:
   - `token: str` - deterministic resume key (from Step)
   - `resume_step: str` - step to resume after input (**computed by Engine**, not provided by Step)

4. **RunState[ContextT]** - Main workflow state (Generic):
   - `run_id: str`
   - `status: RunStatus`
   - `context: ContextT` - full context (events store deltas)
   - `current_step: str | None` - None if terminal/paused
   - `pending_branches: BranchState | None`
   - `pending_await: AwaitState | None`
   - `seq: int` - monotonically increasing event counter

**Design notes:**
- **Context**: `RunState.context` holds the full current context. Events store `context_update` deltas.
- **AwaitState.resume_step**: Engine computes this using `_default_next(current_step)`. Steps only provide the `await_token`.
- **BranchState.completed**: Stores context_update deltas from each branch, not full contexts.

**Reference:** Existing pattern at `dataing/src/dataing/core/state.py:42-59`

**File location:** `maestro/src/maestro/state.py`
