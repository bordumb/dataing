# fn-69.33 [M2] Exports rebuilt from CheckSpec with explicit semantics

## Description
### Goal
The dbt, Great Expectations, Soda and SQL exports come from `CheckSpec`, with the **same semantics as the evaluator** (design §7.6, §17).

### Implementation
- **The export's failure predicate means "this check's outcome is fail"**:
  - **`WHERE <fail_when condition>`**, with the same polarity as `fail_when`.
  - It includes the evaluator's NULL rules: an empty-window `freshness_minutes` (NULL) is a failure, so the predicate adds `OR value IS NULL`; other NULL metrics are warnings, which these exports can't express, so they get a diagnostic.
- **SQL:** the scalar metric query, plus that failure predicate over it.
- **dbt singular test:** returns a row exactly when the outcome is fail.
- **Great Expectations and Soda:** map built-in metrics and static conditions to their equivalents.
- **Unsupported, with a diagnostic for each check:** baseline conditions (`change_pct`), warn thresholds where the format has no equivalent, custom SQL in formats that can't express it, and NULL semantics that can't be expressed.
- **Delete** `DataQualityTest` and the old renderer paths.
## Acceptance
- [ ] **Parity tests:** for passing, failing, boundary and NULL values, the exported SQL and dbt-test SQL (run on DuckDB) agree exactly with `evaluate()`. For example, `fail_when: {gt: 0.01}` with value 0.20 → a failure row; with 0 → no row; with exactly 0.01 → no row; an empty-window freshness → a failure row.
- [ ] Great Expectations and Soda snapshots match the mapping table, and unsupported checks return diagnostics.
- [ ] No `DataQualityTest` references remain.
