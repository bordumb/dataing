# fn-42.4 Package demo fixtures subset for quickstart

## Description

Package a minimal subset of the demo fixtures for use in the quickstart guide. The full `demo/fixtures/` directory contains 7 scenarios with all tables. For the quickstart, we only need the `baseline` and `null_spike` scenarios (baseline for comparison, null_spike as the investigation target). This package will be published as a GitHub release artifact so pip-install users can download it without cloning the full repository.

### Implementation

1. Create a packaging script `demo/package-quickstart-fixtures.sh`:
   ```bash
   #!/bin/bash
   set -e
   OUTDIR="demo-fixtures"
   rm -rf "$OUTDIR" "$OUTDIR.tar.gz"
   mkdir -p "$OUTDIR"

   # Copy selected scenarios
   cp -r demo/fixtures/baseline "$OUTDIR/"
   cp -r demo/fixtures/null_spike "$OUTDIR/"
   cp -r demo/fixtures/volume_drop "$OUTDIR/"

   # Copy DuckDB loader
   cp demo/load_duckdb.sql "$OUTDIR/"

   # Create a quickstart-specific manifest
   cat > "$OUTDIR/README.md" << 'EOF'
   # Dataing Quickstart Fixtures
   Pre-seeded e-commerce data with anomalies for the Dataing quickstart guide.

   ## Scenarios
   - baseline: Clean data, no anomalies
   - null_spike: Mobile app bug causes NULL user_id spike
   - volume_drop: Weekend traffic drop in orders

   ## Usage
   duckdb demo.db < load_duckdb.sql
   EOF

   tar czf demo-fixtures.tar.gz "$OUTDIR"
   echo "Created demo-fixtures.tar.gz ($(du -h demo-fixtures.tar.gz | cut -f1))"
   ```

2. Include 3 scenarios in the quickstart bundle:
   - `baseline` -- clean data for comparison
   - `null_spike` -- primary quickstart scenario (NULL rate spike, clear root cause)
   - `volume_drop` -- secondary "try next" scenario

3. Modify `demo/load_duckdb.sql` to work relative to the extracted directory (it already uses relative paths like `fixtures/...` which need to be updated or the script needs a wrapper).

4. Create a quickstart-specific loader `demo/quickstart-load.sql`:
   ```sql
   -- Quickstart loader: loads null_spike scenario by default
   SET VARIABLE fixture = 'null_spike';
   CREATE OR REPLACE TABLE users AS SELECT * FROM read_parquet(getvariable('fixture') || '/users.parquet');
   -- ... (all tables)
   ```

5. Add a GitHub Actions step in the release workflow to build and attach `demo-fixtures.tar.gz` as a release artifact.

6. Verify the tarball size is reasonable (target < 5MB for quick download).
