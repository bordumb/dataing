# fn-40.2 Configure PyPI trusted publishing in GitHub Actions

## Description

Set up OIDC-based trusted publishing for all publishable packages so that the CI/CD pipeline can push to PyPI without long-lived API tokens. GitHub Actions supports PyPI trusted publishing natively via OIDC identity tokens. This is the security-first approach recommended by PyPI.

Only the three client packages (`dataing-cli`, `dataing-sdk`, `dataing-notebook`) are published to PyPI. The backend `dataing` package is distributed via Docker, not PyPI. The `dataing-ee` package is private and not published.

**Depends on:** fn-40.1

### Implementation

1. Register trusted publishers on PyPI (manual, one-time setup):
   - Go to https://pypi.org/manage/account/publishing/
   - For each package (`dataing-cli`, `dataing-sdk`, `dataing-notebook`), add a trusted publisher:
     - **Owner**: `<github-org>`
     - **Repository**: `dataing`
     - **Workflow**: `release.yml`
     - **Environment**: `pypi` (will create in step 2)
   - Document the setup in a `docs/adr/adr-pypi-publishing.md` or inline comments.

2. Create a `pypi` GitHub environment with deployment protection:
   - In GitHub repo Settings > Environments, create `pypi` environment.
   - Optionally add required reviewers for production releases.

3. Create a reusable publish workflow `.github/workflows/publish-pypi.yml`:
   ```yaml
   name: Publish to PyPI

   on:
     workflow_call:
       inputs:
         package-dir:
           required: true
           type: string
         package-name:
           required: true
           type: string

   jobs:
     publish:
       runs-on: ubuntu-latest
       environment: pypi
       permissions:
         id-token: write  # Required for OIDC trusted publishing
       steps:
         - uses: actions/checkout@v4

         - name: Set up Python
           uses: actions/setup-python@v5
           with:
             python-version: "3.11"

         - name: Install build tools
           run: pip install build

         - name: Build package
           working-directory: ${{ inputs.package-dir }}
           run: python -m build

         - name: Publish to PyPI
           uses: pypa/gh-action-pypi-publish@release/v1
           with:
             packages-dir: ${{ inputs.package-dir }}/dist/
   ```

4. Add a test publish workflow `.github/workflows/test-publish.yml` that publishes to TestPyPI on PRs:
   ```yaml
   name: Test Publish

   on:
     pull_request:
       paths:
         - "python-packages/dataing-cli/**"
         - "python-packages/dataing-sdk/**"
         - "python-packages/dataing-notebook/**"

   jobs:
     build-check:
       runs-on: ubuntu-latest
       strategy:
         matrix:
           package:
             - { dir: "python-packages/dataing-cli", name: "dataing-cli" }
             - { dir: "python-packages/dataing-sdk", name: "dataing-sdk" }
             - { dir: "python-packages/dataing-notebook", name: "dataing-notebook" }
       steps:
         - uses: actions/checkout@v4
         - uses: actions/setup-python@v5
           with:
             python-version: "3.11"
         - run: pip install build twine
         - run: python -m build
           working-directory: ${{ matrix.package.dir }}
         - run: twine check ${{ matrix.package.dir }}/dist/*
   ```

### Key Files
- **CREATE**: `.github/workflows/publish-pypi.yml` (reusable publish workflow)
- **CREATE**: `.github/workflows/test-publish.yml` (PR build check)
