## Implementation Details

### Why FastAPIInstrumentor over Custom Middleware

The initial plan used `BaseHTTPMiddleware` which is fragile:
- Breaks streaming responses
- Can lose async context
- Misses edge cases the OTEL team has handled

`FastAPIInstrumentor` is battle-tested and handles all HTTP semantics correctly.

### correlation.py (thin middleware)

```python
"""Thin middleware for correlation ID only - tracing handled by OTEL."""
import uuid
from starlette.middleware.base import BaseHTTPMiddleware
from starlette.requests import Request
from starlette.responses import Response
from opentelemetry import trace, baggage
from opentelemetry.context import attach, detach

class CorrelationMiddleware(BaseHTTPMiddleware):
    """
    Lightweight middleware for correlation ID management.
    Tracing is handled by FastAPIInstrumentor - this only manages correlation IDs.
    """

    async def dispatch(self, request: Request, call_next) -> Response:
        # Extract or generate correlation ID
        correlation_id = (
            request.headers.get("X-Correlation-ID") or
            request.headers.get("X-Request-ID") or
            str(uuid.uuid4())
        )

        # Store in request state for downstream use
        request.state.correlation_id = correlation_id

        # Add to current span as attribute
        span = trace.get_current_span()
        if span:
            span.set_attribute("correlation_id", correlation_id)

        response = await call_next(request)

        # Echo back in response
        response.headers["X-Correlation-ID"] = correlation_id

        return response
```

### Integration in app.py

```python
from opentelemetry.instrumentation.fastapi import FastAPIInstrumentor
from dataing.telemetry.config import init_telemetry
from dataing.telemetry.correlation import CorrelationMiddleware

def create_app() -> FastAPI:
    # Initialize OTEL SDK (idempotent)
    init_telemetry()

    app = FastAPI(...)

    # Auto-instrument FastAPI (handles all HTTP tracing)
    FastAPIInstrumentor.instrument_app(app)

    # Add thin correlation ID middleware
    app.add_middleware(CorrelationMiddleware)

    # ... other middleware (auth, rate limit, etc.)
    return app
```

import structlog
from dataing.telemetry.structlog_processor import add_trace_context

def configure_logging():
    """Configure structlog with trace context injection."""
    structlog.configure(
        processors=[
            structlog.stdlib.add_log_level,
            add_trace_context,  # Inject trace_id, span_id
            structlog.processors.TimeStamper(fmt="iso"),
            structlog.processors.JSONRenderer(),
        ],
        wrapper_class=structlog.stdlib.BoundLogger,
        context_class=dict,
        logger_factory=structlog.stdlib.LoggerFactory(),
        cache_logger_on_first_use=True,
    )

## Key Changes from Initial Design

1. **Use FastAPIInstrumentor** - Not custom `BaseHTTPMiddleware` for tracing
2. **Thin correlation middleware** - Only handles correlation ID, not tracing
3. **Wire structlog** - Actually connect the processor (was missing before)
4. **Standard headers** - Accept both `X-Correlation-ID` and `X-Request-ID`
