# Agent Memory Integration (bond-agent)

**Epic:** fn-55
**Phase:** Core Platform
**Designation:** CE

## Overview

Wire up bond-agent's memory toolset to dataing investigation agents. The infrastructure exists (memory_toolset, PgVectorMemoryStore, migration 012_agent_memories.sql) but AgentClient is not using it. Enable agents to learn from corrections, remember filter patterns, and persist learnings across investigations per tenant.

Like OpenAI's internal data agent, this gives investigations a "memory layer" that improves over time.

## Scope

- Expose asyncpg pool from AppDatabase for PgVectorMemoryStore
- Update AgentClient to accept optional memory store and wire to BondAgent
- Thread tenant_id through Temporal activities to memory operations
- Create PgVectorMemoryStore in Temporal worker and API lifespan
- Graceful degradation when memory unavailable
- Row-Level Security (RLS) for defense-in-depth tenant isolation
- Audit logging for compliance (banking, healthcare, etc.)

### Out of Scope

- Memory pruning/TTL (future epic)
- Memory admin UI
- Export/import of memories with investigation snapshots
- Per-tenant memory enable/disable settings

## Approach

1. **Expose pool** - Add `pool` property to `AppDatabase` (trivial)
2. **Update AgentClient** - Accept optional `memory_store: AgentMemoryProtocol`, pass to BondAgent with `memory_toolset`
3. **Thread tenant_id** - Add to activity inputs, convert str->UUID at boundary
4. **Inject at entrypoints** - Create `PgVectorMemoryStore(pool=app_db.pool)` in worker and API lifespan
5. **Update adapter** - `TemporalAgentAdapter` passes tenant_id to agent methods

## Risks

| Risk | Mitigation |
|------|------------|
| Embedding API unavailable | Graceful degradation - log warning, continue without memory |
| pgvector not installed | Check extension exists, fail fast with clear error |
| Memory store slows investigations | Memory ops are fire-and-forget, don't block critical path |

## Acceptance

- [ ] AgentClient accepts optional memory_store parameter
- [ ] BondAgent instances have memory_toolset when store provided
- [ ] tenant_id flows from workflow through activities to memory operations
- [ ] PgVectorMemoryStore created in Temporal worker
- [ ] PgVectorMemoryStore created in API lifespan
- [ ] Memory operations are tenant-isolated (WHERE tenant_id = $1)
- [ ] Agents can call create_memory and search_memories tools
- [ ] Graceful degradation when memory_store is None
- [ ] RLS policy enforces tenant isolation at database level
- [ ] Audit log captures all memory operations with tenant context
