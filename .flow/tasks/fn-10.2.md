# fn-10.2 Create investigation_jobs migration

## Description

Create a new migration for the `investigation_jobs` table that tracks job execution state, checkpoints, and worker ownership.

### Migration File

Create `dataing/migrations/0XX_investigation_jobs.sql` (next available number):

```sql
CREATE TABLE investigation_jobs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    investigation_id UUID NOT NULL REFERENCES investigations(id) ON DELETE CASCADE,
    tenant_id UUID NOT NULL,
    status TEXT NOT NULL DEFAULT 'pending',
    priority INT NOT NULL DEFAULT 0,

    -- Checkpoint state
    current_step TEXT,
    checkpoint JSONB,

    -- Execution tracking
    worker_id TEXT,
    attempts INT DEFAULT 0,
    max_attempts INT DEFAULT 3,

    -- Timing
    created_at TIMESTAMPTZ DEFAULT now(),
    started_at TIMESTAMPTZ,
    completed_at TIMESTAMPTZ,

    -- Failure handling
    error TEXT,
    last_error_at TIMESTAMPTZ
);

CREATE INDEX idx_jobs_pending ON investigation_jobs (priority DESC, created_at)
    WHERE status = 'pending';
CREATE INDEX idx_jobs_tenant ON investigation_jobs (tenant_id);
CREATE INDEX idx_jobs_investigation ON investigation_jobs (investigation_id);
```

### Reference

### Notes

- Use `ON DELETE CASCADE` to clean up jobs when investigation deleted
- Index on `(priority DESC, created_at)` for efficient polling
- `checkpoint` column stores serialized `InvestigationContext`
