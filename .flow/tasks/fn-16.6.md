# fn-16.6 Add Signals for cancellation and AWAIT_USER

## Description

Add Temporal Signals for cancellation and AWAIT_USER interaction.

### Cancellation Signal

```python
@workflow.signal
def cancel_investigation(self) -> None:
    self._cancelled = True
```

Check `self._cancelled` before each activity call. If true, return early with cancelled status.

### AWAIT_USER Signal

```python
@workflow.signal
def user_input(self, payload: dict) -> None:
    self._user_input = payload

# In workflow:
await workflow.wait_condition(lambda: self._user_input is not None)
```

### Client Usage

```python
handle = client.get_workflow_handle(workflow_id)
await handle.signal(InvestigationWorkflow.cancel_investigation)
await handle.signal(InvestigationWorkflow.user_input, {"feedback": "..."})
```

# Task fn-16.6: Add Signals for cancellation and AWAIT_USER

## Signals Added

1. **cancel_investigation** - Gracefully cancels the investigation
   - Sets `_cancelled` flag checked before each activity
   - Cancels all child workflows
   - Returns with "cancelled" status

2. **user_input** - Accepts user feedback when AWAIT_USER triggered
   - Stores payload in `_user_input`
   - `wait_condition` wakes up when input received

## InvestigationWorkflow Changes

- Added `__init__` with state: `_cancelled`, `_user_input`, `_awaiting_user`, `_child_handles`
- Added `_check_cancelled()` method called before each activity
- Added `_cancel_children()` to cancel running child workflows
- Added `_await_user_input()` with configurable timeout
- Added CancelledError handling for each activity

- `get_result()` - Get completed result
