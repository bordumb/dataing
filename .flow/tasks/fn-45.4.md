# fn-45.4 Add JIT user provisioning from SAML attributes

## Description

Extend the ACS endpoint's user creation logic to perform rich JIT (Just-In-Time) provisioning using
SAML attribute statements. Beyond basic email and name, SAML assertions can carry group memberships
that should be mapped to Dataing roles (OWNER, ADMIN, MEMBER). This task adds configurable
attribute mapping and group-to-role mapping for SAML users, including handling of existing-user
linking with security checks.

Depends on: fn-45.3 (ACS endpoint must exist).

### Implementation

1. Extend `SAMLUserInfo` in `saml_provider.py` to include raw attributes:
   ```python
   @dataclass
   class SAMLUserInfo:
       name_id: str
       email: str
       name: str | None = None
       given_name: str | None = None
       family_name: str | None = None
       groups: list[str] | None = None
       raw_attributes: dict[str, list[str]] | None = None
   ```

2. Add SAML attribute mapping config to `SSOConfig` type in
   `python-packages/dataing-ee/src/dataing_ee/core/sso/types.py`:
   ```python
   # Add to SSOConfig dataclass:
   saml_attribute_mapping: dict[str, str] | None  # e.g. {"email": "urn:oid:0.9.2342...", ...}
   saml_group_role_mapping: dict[str, str] | None  # e.g. {"Engineering": "member", "Admin": "admin"}
   ```

3. Add columns to `sso_configs` table via migration
   `python-packages/dataing/migrations/032_saml_attribute_mapping.sql`:
   ```sql
   ALTER TABLE sso_configs
     ADD COLUMN saml_attribute_mapping JSONB DEFAULT '{}',
     ADD COLUMN saml_group_role_mapping JSONB DEFAULT '{}';
   ```

4. Update `SSORepository._row_to_sso_config()` and `create_sso_config()` in
   `python-packages/dataing-ee/src/dataing_ee/adapters/sso/repository.py` to handle the new columns.

5. Create `python-packages/dataing-ee/src/dataing_ee/core/sso/provisioning.py`:
   ```python
   class SAMLUserProvisioner:
       """JIT provisions or updates users from SAML assertions."""

       async def provision_or_update(
           self,
           saml_user: SAMLUserInfo,
           sso_config: SSOConfig,
           auth_repo: PostgresAuthRepository,
           sso_repo: SSORepository,
       ) -> User:
   ```
   - Apply attribute mapping: look up email/name/groups from configured attribute OIDs, falling back
     to standard SAML attributes.
   - Map IdP group names to roles using `saml_group_role_mapping`. If user is in multiple groups,
     use highest privilege (OWNER > ADMIN > MEMBER).
   - If user exists by email but has no SSO identity:
     - Security check: only link if the SAML assertion carries a verified email attribute.
     - Log a warning for audit purposes.
   - If user exists with SSO identity: update name/groups if changed.
   - If user is new: create user, assign to org with mapped role.

6. Update the ACS endpoint (fn-45.3) to use `SAMLUserProvisioner` instead of inline provisioning
   logic.

7. Add tests in `python-packages/dataing-ee/tests/unit/core/sso/test_provisioning.py`:
   - Test group-to-role mapping (multiple groups, highest wins).
   - Test attribute mapping with custom OIDs.
   - Test existing user linking with security check.
   - Test new user JIT provisioning.
   - Test user update on re-login (name/role change).
