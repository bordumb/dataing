# Investigation Snapshot Export and Import

**Plan ref:** Task 0.4.2
**Phase:** 0 (Foundation)
**Designation:** OSS (export + same-tenant import), Enterprise (cross-tenant, bulk)

## Overview

`dataing run snapshot <investigation_id>` exports everything needed to replay an investigation as a compressed tar.gz archive. `dataing run import <snapshot.tar.gz>` loads it into any Dataing instance for replay.

## Scope

- tar.gz archive builder with structured directory layout
- Parquet storage for query results (space efficient)
- CLI commands: `dataing run snapshot`, `dataing run import`
- API endpoints: `GET /investigations/{id}/snapshot`, `POST /investigations/import`
- Schema versioning for forward compatibility
- Imported investigations marked as "replay" with original timestamp

## Archive Structure

```
snapshot-<id>/
  metadata.json
  evidence/
    001-hypothesis.json
    002-query.json
    003-results.parquet
    ...
  lineage.json
  code_changes.json
  prompts/
    hypothesis.txt
    query.txt
    synthesis.txt
```

## Acceptance

- Snapshot is a single compressed .tar.gz archive
- Contains all evidence, queries, results, lineage, agent prompts
- Results stored as Parquet
- Snapshot can be loaded into any Dataing instance
- Imported investigation marked as "replay"
- Schema version included for forward compatibility
- Maximum snapshot size configurable (default 100MB)

## Gap Analysis Risks

- **Parquet dependency**: `pyarrow` or `fastparquet` adds ~200MB to install size. For CLI users who just want markdown export, this bloats install significantly. Consider making Parquet an optional dependency.
- **Snapshot of incomplete investigation**: Can you snapshot an in-progress investigation? Need clear handling or rejection.
- **Snapshot size truncation**: When exceeding 100MB limit, what gets truncated? Results? Diffs? Define priority ordering.
- **Import across schema versions**: "Version field, migration on import" needs a defined snapshot schema version format and migration strategy.
- **Cross-tenant import (EE)**: Must sanitize imported snapshots to not carry over permissions, API keys, or tenant-specific data. PII in investigation data is a concern.
- **Agent prompts in snapshot**: Storing exact prompts enables reproducibility but exposes system prompts. For SaaS customers, evaluate acceptability.
